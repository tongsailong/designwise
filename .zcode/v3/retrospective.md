## 3. 旧 Copilot 闸门的真实贡献

| 闸门 | 实际做了什么 | 抓到了什么 | 没抓到什么 |
|---|---|---|---|
| 第一轮 G3 方向 | 1 次 CONSULT（`gpt-6.1-sol`），逐方向合格性 + 采用/拒绝 | 当前/下一站语义冲突、累计数矛盾、假箭头、B/C 的注意力竞争与骨架不可泛化 | 无预审、无原型评审、无原生评审 |
| 第二轮 G2 提示词预审 | 1 次 CONSULT，10 条修正全部采纳 | 数据样本未闭合、锁定态被压平、大字体风险、概念板≠像素规格 | 没有像素，不能判对比度/回流 |
| 第二轮 G3 方向 | 1 次 CONSULT，A/B 合格、C 不合格、融合 | 地图地理失真、步骤语义重复、封面压字 | 原生可行性显式留给后续阶段 |
| 第二轮 G4 原型评审 | 7 轮截图评审，标注「G4 无剩余必须改项」 | 权限态显示 0、跨日文案、假「继续走」、广告入口命名 | 地图层级、ProgressBar 0%、mine@1.6、city sheet@1.45、状态栏、深色、崩溃 |
| 第一轮 G4 | **未运行** | — | 全部原生缺陷 |

**结论**：旧 Copilot 是有效的「设计语义审读者」，但**没有代码与渲染几何能力**，且第一轮整段缺审。它不是工程验收门，也无法替代原生自检。v6 又把 `call_gpt.py` 退役，V2 的 G2/G3/G4 CONSULT 链路已不可用——V3 必须把设计判断归还 ZCode，并把 Copilot 定位为治理。

## 4. V2 能力缺口 → V3 措施

| 缺口 | V2 表现 | V3 措施 | 对应条件 |
|---|---|---|---|
| 页面清单 ≠ 状态地图 | 页面地图有「适用状态」列，但无「状态在哪被建模/验证」闭合 | 状态地图 `P*/S*/X*`，逐项记 数据/规则出处（file:line）、状态集合、覆盖去向；`check-deliverables.py` 校验闭合 | C4 C5 |
| 数据/规则出处缺失 | brief 抄文档规则 | 每个展示值/规则必须引用真实 UI 代码路径；文档规则与 UI 路径冲突时列为待决，不静默采用 | C4 |
| 三方向强制 | 新任务固定 3 个 | 按实质分歧自适应 1..N；无分歧给 1 个最优方向；有互补可融合；全不合格全拒 | C5 C9 |
| 伪差异无实测 | 只靠 prompt 要求结构差异 | 新增 `direction_divergence.py`：色板距离 + 版式骨架相关性，判「换皮/换骨/实质不同」 | C5 |
| 提示词失败无修正树 | 只有「改 prompt 重出」 | 失败归因四类（未执行结构 / 共用块矛盾 / 要求不适合 / 参考不足）→ 对应改法 | C5 |
| 原型覆盖不闭合 | 页面地图有 22 页，原型 5 类 | 原型必须给出 P*/S* 覆盖矩阵：已渲染 / 明确原生-only（写理由 + 原生验证义务） | C5 C8 |
| 缩放矩阵不完整 | 1.0/1.3（项目要求时 1.5） | 默认 1.0/1.3/1.6/2.0；多列、label+value、固定高度结构必须在最大档渲染 | C8 |
| 弹层可滚动性未建模 | 固定高度弹层 | 弹层必须声明滚动容器与关闭可达；最大字号单独渲染 | C7 C8 |
| 交接只写 token/结构 | 无组件等价与禁用替代 | 交接新增组件等价映射、禁用替代、绘制层级/命中优先级、滚动契约、业务规则出处 | C7 |
| 原生自检无清单 | 构建成功即进真机 | 阶段 5 增加 pre-device 自检：组件替换 diff、自绘层级、旧资源残留、动态列表 smoke、主题 token | C7 |
| 深色模式「若适用」 | 可跳过且无结论 | 验证矩阵每项必须 PASS/FAIL/NOT TESTED/N/A，不得把未测写成通过 | C8 |
| 测试能力边界未声明 | 用 2742 绿测试暗示质量 | 明确「单测/契约测试不能证明渲染几何」，几何/层级/裁切/图标色必须渲染或真机证据 | C8 |
| Gate 结构冗余 | G0/G1 同一产物；G5 常为空转 | 合并 0+1；素材并入完善阶段；交接独立成阶段 | C9 |
