## 4. 独立场景（不是历史缺陷，是本次真实执行）

### S1 伪差异（同骨架换色）能否被实测挡住

- **做法**：生成两张**合成验证图**（同一版式、不同配色；仅用于测指标行为，不是设计产物），运行 `scripts/direction_divergence.py`。
- **实测输出** `[实测]`：

```
reskinA.png ↔ reskinB.png: palette=0.571 skeleton=0.996 → same-skeleton
严格模式：判出同骨架/换皮，未通过。   （--strict 退出码 1）
reskinA.png ↔ distinctC.png: palette=0.3945 skeleton=0.0149 → distinct （退出码 0）
```

- **结论**：换色但骨架不变的方向会被判 `same-skeleton`，`--strict` 使 G1 失败；结构不同的对照判 `distinct`。**边界**：合成图只证明指标行为，不证明真实概念图质量；脚本不判断方向对不对。

### S2 页面地图里的状态静默消失

- **做法**：临时任务目录写入 `design-brief.md`（含 P1/P2/S1）与只含 P1/P2 的 `coverage.json`，运行 `check-deliverables.py --stage 0 --skip-artifacts`。
- **实测输出** `[实测]`：

```
❌ [coverage-id-missing] .../coverage.json
   地图里的 id 在 coverage 中消失：S1
（退出码 1）
```

删掉 `coverage.json` 后再跑：`⚠️ [coverage-missing] … 整机/多页面任务必需（局部迭代可忽略）`，退出码 0。

- **结论**：历史那种「brief 写 22 页、原型只有 5 类页面」的缺口，现在会以**错误**（id 消失）或**警告**（整机任务缺 coverage）出现，而不是靠人读报告。语义合理性仍由设计判断。

### S3 已知边界：检查器不强制「每页都渲染最大档」

- `coverage.json` 只要求 `scales_rendered` 是已知档位；**不要求每个多列页面包含 1.6/2.0**。所以 D3 类问题的机器拦截力弱于 D5/D8。
- V3 的处理是**规则 + 评审**（阶段 2-6 + G2 + 阶段 3 App 三项），而非假装检查器能判。回放结论里 D3 标「有条件」就是这条边界。

### S4 已知边界：真机证据不可机器证明

- 阶段 6 的四态矩阵、三方对照、装包入口都是**流程与取证规则**；`check-deliverables.py` 只能校验报告存在与阶段产物，不能证明「这张截图来自这台设备」。
- 因此 V3 明确：设备不在线只能 `PARTIAL`/`BLOCKED`，未测项写 `NOT TESTED`（SKILL §2.2 阶段 6、§9）。这条靠执行纪律与可选只读复核，不靠脚本。

### S5 已知边界：交接「七件套」完整性不是机器门

- `check-deliverables.py` 在阶段 4 只要求 `handoff/README.md` 存在；七件套与四类契约的完整性由 G4 评审核对。V3 没有把「文件存在」冒充成「契约等价」。

## 5. 对 V3 的反向要求（回放暴露的剩余问题）

1. **D3 的机器拦截不足**：可在未来给 `coverage.json` 增加「多列/固定高度页面必须含 1.6」的可选强校验，但需要先定义「哪些页面算高风险」，否则会误伤。本次不做，避免为通过检查而加硬规则。
2. **D6 的交互细节**：`states-interactions.md` 需要更具体的「操作 → 触发方式 → 结果 → 数值变化」四元组模板；当前是规则要求，不是模板强制。
3. **D1/D2 仍依赖阶段 5 的真实原生截图**：交接契约让缺陷「可被指出」，但不能替代渲染证据；`pre-device` 自检清单已包含，但没有自动截图比对。
4. 以上都是**后续可改进项**，不影响本次 8/8 提前拦截的结论；不把它们写成 V3 已完成的能力。
