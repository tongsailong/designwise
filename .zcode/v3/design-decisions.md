# DesignWise V3 设计决策

## 1. 核心判断

V2 的问题不是"流程不够多"，而是**设计判断外包给了 Copilot、产物覆盖靠叙述自证**。
V3 的改法：判断收回 ZCode，覆盖改成机器可核对的单一事实源，Copilot 退回治理。

三条硬结论（来自 `retrospective.md`）：

1. 概念阶段不是主要失败点。6 张真实概念图、方向差异真实、融合决策正确；失败集中在状态覆盖、HTML→原生等价、业务出处、验证矩阵。
2. 旧的 Copilot DESIGN 闸门在 v6 已不可执行（`call_gpt.py` 退役），且它没有代码与几何能力——第一轮整段缺审。
3. 上游最有价值的不是"五维评审"（写入版是六维，且 DesignWise 已吸收），而是**方向卡的思考结构**、**防换皮的实测方法**、**打磨环**、**上下文阶梯**。

## 2. 流程：8 阶段 → 7 阶段

| V3 | 目标 | 对应 V2 | Gate |
|---|---|---|---|
| 0 产品理解与设计目标 | 页面-状态地图 + 真实出处 + 目标映射 + 平台可行性 + 范围冻结 | 0 + 1 合并 | G0 |
| 1 概念方向 | 自适应 1..N 方向 → 真实生成 → 差异实测 → 设计决策（采用/融合/拒绝） | 2 + 3 合并，去 Copilot | G1 |
| 2 HTML 原型与覆盖 | 可交互原型 + P*/S*/X* 覆盖闭合 + 缩放矩阵 + 机械校验 | 4 前半 | G2 |
| 3 设计评审与完善 | 六维 + App 附加判据 + 严重度 + 打磨环 + 素材按需 | 4 后半 + 5 | G3 |
| 4 原生交接 | 交付包 + 等价映射 + 绘制/滚动/缩放/出处契约 | 6 前半（独立成阶段） | G4 |
| 5 原生实现 | 按交接实现 + pre-device 自检 + 首批三方对照 | 6 后半 | G5 |
| 6 真机验收 | 四态矩阵 + 定向修复 + 双验收 | 7 | G6 |

合并不减质量：G0 要过的清单比 V2 的 G0+G1 之和更具体（多了出处与状态闭合）。
交接独立不是加审批：它有自己的产物 `handoff/` 和独立失败模式（D1/D2 都死在这里）。

## 3. 角色重划分

| 角色 | V3 职责 | 不做 |
|---|---|---|
| 用户 / ChatGPT 侧 | 业务目标、重大取舍、最终产品与设计验收 | — |
| ZCode 原生 Agent | 唯一的**设计实施与技术决策**主体：产品理解、提示词、生成、原型、评审、交接、实现、测试、修复 | 不代替用户做业务取舍 |
| ZCode 原生只读 Reviewer | 复杂/高风险设计的独立复核：按判据查真实产物，给缺陷与结论 | 不改文件、不发布、不替代主 Agent 决策 |
| Copilot v6 | 任务合同、完成条件、状态、证据登记、审计、PARTIAL 推进、风险收口 | **不做设计裁决**、不调远程模型、不是普通开发的前置门 |
| DesignWise | 方法、判据、质量门、产物契约 | 不实施、不替用户决策 |

禁用：`call_gpt.py`、`bridge_evidence.py --image` 的设计裁决用途、SOL 通道、任何"等模型批准"的门。

## 4. 方向：固定三方向 → 自适应

| 情形 | 方向数 | 依据 |
|---|---|---|
| 结构由现有设计系统/用户指定，且无实质分歧 | 1 个最优 | 强制三方向只会产出换皮 |
| 存在真实结构分歧（两种信息组织都成立） | 2–3 个 | 分歧是真的就值得比较 |
| 两个以上方向有互补优点 | 先 N 个，后融合 | 融合必须说明保留/舍弃/统一逻辑 |
| 全部方向违反硬约束或产品原则 | 全部拒绝 | 不得选"最不差" |

方向卡（零成本，先写卡再决定出几张图）六栏：逻辑与来源 / 借用的是什么 / 主角信息与素材 / 结构骨架 / 差异点 / **form 来自产品的哪里**。

防换皮不靠口号：`direction_divergence.py` 实测色板距离与版式骨架相关性，输出事实，`--strict` 时作为门。

## 5. 覆盖：叙述 → 单一事实源

新增 `coverage.json`（整机/多页面重设计必需）：每个 `P*`/`S*`/`X*` 一条记录，含
`prototype`（rendered / deferred-native / not-applicable）、`scales`、`native`、`device`（每档四态）。
`check-deliverables.py` 校验：id 唯一、状态合法、deferred 必须写 reason 且 `native_verify=true`、
真机态只能是 `pass`/`fail`/`not-tested`/`not-applicable`、`not-tested` 不得缺少说明。

这直接修 D3/D5/D9：原型渲染了哪些、跳过了哪些、真机验了哪些，都在一个文件里，报告不能各说各话。

## 6. 评审：六维保留 + App 附加 + 打磨环

- 六维判据**不改写**（概念一票否决 + 5 执行维），只在 App UI 场景补三项附加检查：状态完整性、交互真实性、原生可实现性/适配风险。
- 严重度三级：致命（阻断交付）/ 重要（本轮必改）/ 打磨（可排期）。"致命"不是审美评价，是可判定的：状态缺失、假控件、不可读、不可实现、破数据口径。
- 打磨环：每轮只看 3 处、结构先于工艺、重渲染受影响屏；停止判据是"认真看完找不出值得改的三处"，通常 3–5 轮；≥5 轮还在大改 → 问题在结构/方向，停止打磨回头改方案。
- 改善用**重渲染证据**证明，不编造分数趋势。

## 7. 交接：补四类契约

V2 交接有 tokens/结构/状态/素材/适配/基线，缺的是原生等价性：

1. **组件等价映射 + 禁用替代**：自绘/分段/自定义控件点名"不得替换为系统默认控件"（D2）。
2. **绘制层级与命中优先级**：Canvas/z-order/declutter/hit-test（D1）。
3. **滚动与可达**：每个弹层声明滚动容器与关闭可达；固定高度结构标红（D4）。
4. **业务规则出处**：每个展示值/规则引用真实 UI 代码路径，文档规则与代码冲突列为待决（D8）。

再加主题 token 语义化（不用 white/black 反色）、旧资源清理清单、允许偏差 vs 缺陷清单。

## 8. 验证：四态矩阵 + 能力边界

- 默认缩放档 1.0 / 1.3 / 1.6 / 2.0；多列、label+value、固定高度结构必须在最大档渲染。
- 环境矩阵：缩放、屏幕尺寸、深色、首装首启、权限允许/拒绝/永久拒绝、空/非空、特殊业务态、弹层与长内容、Widget/外部入口（适用时）。
- 每项 PASS / FAIL / NOT TESTED / N/A；未测不得写成通过。
- 明确测试能力边界：单测/契约测试不能证明渲染几何、绘制层级、裁切、图标颜色；这些必须有渲染或真机证据（D10）。

## 9. 路由：按产物成熟度进入

| 已有 | 从哪进 | 仍须 |
|---|---|---|
| 有效 brief + 状态地图 + 出处 | 阶段 1 | 方向记录 |
| 有效方向记录（`direction-approved.md` 状态=实施基线） | 阶段 2 | 覆盖矩阵、评审 |
| 当前版本原型 | 阶段 3（只改受影响屏） | 复评受影响项 |
| 可靠素材清单 | 阶段 3 内跳过生成 | 消费者与指纹 |
| 有效 `handoff/` | 阶段 5 | 实现自检 |
| 只改后端/业务逻辑 | 不触发视觉流程 | 不改视觉断言 |

不允许跳过的只有：**本次真正产出的交付物必须有对应证据**。不再有"新任务必须三方向"的绝对规则。

## 10. 与 v6 协作基线的对齐

- 删除 SKILL.md 中所有 `call_gpt.py --mode CONSULT` 设计裁决描述。
- `direction-approved.md` 改名为语义：**ZCode 设计决策记录**，保留"用户可否决"。
- 可选的只读复核记录写在同一文件（reviewer、结论、findings），不建第二套台账。
- Copilot 治理只在长任务/跨会话/高风险时启用，说明其命令与证据登记方式，但不作为设计门。

## 11. 不做的事

- 不引入上游运行时代码、依赖、Hook、学习脚本。
- 不新增 Provider、模型、付费通道。
- 不为"目录完整"复制 45 个 references；只新增 3 个有真实内容的（`direction-strategy.md`、`state-map.md`、`polish-loop.md`），其余改写到已有文件。
- 不把评审变成打分仪式：没有真实截图与判据的不算评审。
