# 原生平台设计 · 平台语法、密度与反网页套路

> **读这份文档的时机**：阶段 0 做原生可行性、阶段 1 写方向与提示词、阶段 2 做原型、阶段 3 评审、阶段 4 交接、阶段 5 实现。
> **一句话立场**：**原生感不是把网页做小，而是按平台语法组织导航、密度、触控反馈、空间层级与系统行为。**
> 本文只展开 `SKILL.md`；阶段与证据门以 `SKILL.md` 为准。默认以 Android（Material 3）为主，iOS 给对应差异；项目有明确规范时项目优先。

---

## 1. 什么叫“原生感”

原生感由六件事共同成立，缺一项就会露出网页味：

| 维度 | 原生 App | 网页 App 倾向 |
|---|---|---|
| **导航** | 顶部 app bar + 底部导航/返回栈；系统返回与手势一致 | 侧边栏、面包屑、页面内大标题 hero、浏览器式返回 |
| **密度** | 列表/分组/分隔线承担结构；一屏信息量服务任务 | 每条内容套大卡片、卡片之间大留白、一屏只有一件事 |
| **触控反馈** | 按压态、涟漪/高亮、长按、触感；反馈在手指下发生 | 只有 hover；点击后整页跳转；按钮没有按下态 |
| **空间层级** | 背景—表面—内容—浮层四层，用 tonal surface/elevation 表达 | 所有内容都是白底圆角卡，靠阴影堆层级 |
| **系统集成** | 状态栏/导航栏/安全区/键盘/深色/字体缩放按系统 | 手写状态栏、固定像素、忽略 insets 与字体缩放 |
| **动效** | 转场有方向、反馈即时、可中断、尊重减少动态 | 全屏淡入淡出、装饰性循环动画、1s 以上过渡 |

**判定口径**：把颜色、阴影、图片全部去掉，只留灰块与文字，导航与信息层级仍然成立 → 结构是原生的；靠卡片与装饰撑起来 → 仍是网页。

## 2. 平台基线（实现与评审都用这张表）

### 2.1 尺寸与布局

| 项 | Android | iOS | 备注 |
|---|---|---|---|
| 触控目标 | ≥48×48dp | ≥44×44pt | 视觉图标可更小，热区不能小 |
| 屏幕边距 | 16dp（紧凑 12dp） | 16pt（紧凑 12pt） | 用 4dp 网格；8dp 为主节奏 |
| 顶部 app bar | 56dp（小）/112dp（大） | 44pt / 大标题 96pt | 与状态栏 insets 相加，不写死 |
| 底部导航 | 80dp + 手势条 insets | 49pt + home indicator | 3–5 个目的地；不塞更多 |
| 列表项 | 单行 56dp / 双行 72dp / 三行 88dp | 44pt 起 | 列表优先，不把每项做成卡 |
| 圆角 | shape scale：4/8/12/16/28 | 连续圆角，按组件层级 | 按组件尺寸选，不全局 24 |
| 字体缩放 | `sp`，跟随 fontScale（1.0–2.0） | Dynamic Type | 最大档必须重排，不缩字号硬塞 |

### 2.2 字体角色（按平台语义，不照抄网页 px）

| 角色 | Android（sp） | iOS（pt） | 用法 |
|---|---|---|---|
| Display | 45/57 | 34/41 | 一屏最多一处，品牌或核心数字 |
| Headline | 24–32 | 22–28 | 页面标题、区块标题 |
| Title | 16–22 | 17–22 | 列表组标题、卡片标题 |
| Body | 14–16 | 15–17 | 正文；中文行高 1.5–1.7 |
| Label | 12–14 | 12–13 | 标签、辅助说明；不得低于 12sp/12pt，正文仍 ≥14 |
| Numerals | tabular / 等宽数字 | 等宽数字 | 计时、金额、步数避免跳动 |

**中文**：系统字体优先（Noto Sans CJK / 苹方）；display 可用衬线，但必须确认目标设备有可用字体或随包提供，不能假设网络字体。

### 2.3 颜色与表面

- 用**语义角色**：`surface` / `surface_container` / `surface_container_high` / `on_surface` / `on_surface_variant` / `primary` / `on_primary` / `outline` / `error`。禁止把 `white`/`black` 当语义色。
- 暗色不是反相：降低饱和、提高表面层级差、正文用 `on_surface` 而非纯白；纯黑大底与纯白正文都容易刺眼。
- 表面层级优先用 **tonal surface**（同色相不同明度）表达，不靠一层层阴影。阴影只给真正浮起的元素（FAB、sheet、dialog、菜单）。

### 2.4 系统行为

| 行为 | 要求 |
|---|---|
| 边到边 | 内容可延伸到系统栏下，但用 insets 保证可读与可点；app bar 与底栏不得被状态栏/手势条遮挡 |
| 返回 | Android 系统返回/手势与页面返回一致；预测性返回不破坏状态；弹层先关弹层再退页 |
| 键盘 | 输入框聚焦时内容可滚动到可见区；主按钮不被键盘遮挡；IME insets 不写死 |
| 深色 | 跟随系统；素材有暗色变体或程序化调色；不简单反相 |
| 字体缩放 | 1.0/1.3/1.6/2.0 逐档检查；多列、同行 label+value、固定高度必须给替代形态 |
| 权限 | 首次请求前有解释；拒绝/永久拒绝都有恢复路径；不诱导、不反复弹 |
| 触感 | 确认/选择/失败用不同 haptic；不每次点击都震 |

## 3. 反网页套路清单（评审直接查）

| 网页套路 | 为什么不像原生 | 原生替代 |
|---|---|---|
| 每条内容一张大号白色圆角卡 | 卡片失去信息分组意义，层级靠阴影 | 分组列表 + 分隔线 + 区块标题；只有需要独立操作/浮起的对象才用卡 |
| 所有按钮都是胶囊 | 层级消失，主次不分 | 主操作用 filled/FAB，次操作用 tonal/text；胶囊只给 chip/筛选 |
| 全局 16–24px 圆角 | 组件尺寸与形状脱节 | shape scale 按组件尺寸选用；小控件小圆角 |
| 网页 Dashboard 网格/首屏 hero | 移动端首屏是任务入口，不是营销页 | 顶部 app bar + 一个核心任务 + 必要辅助信息 |
| 大面积无意义留白 | 首屏信息效率低，滚动成本高 | 4/8dp 节奏；留白服务分组，不服务“高级感” |
| 12–14px 正文 + 超大字距 | 移动阅读距离下偏小 | 正文 14–16sp；中文行高 1.5–1.7；字距只在大字用 |
| hover 才出现的操作 | 触屏没有 hover | 操作常驻或通过长按/滑动/更多菜单暴露；按压态必须有 |
| 手写状态栏/刘海/设备框 | 位置与 insets 必错 | `assets/ios_frame.jsx` / `assets/android_frame.jsx` |
| 用 toast/alert 承担所有反馈 | 打断且无上下文 | Snackbar（可撤销）/ 底部弹层 / 行内 banner / 字段错误 |
| 页面切换全屏淡入 | 丢失空间关系 | 方向性转场（push/pop）、容器变换、共享元素 |
| 固定 px 高度卡片装动态内容 | 大字体必崩 | 最小高度 + 内容驱动；最大档给替代形态 |
| 桌面式滚动条/整页滚动 | 移动端是嵌套滚动与边缘效果 | 列表独立滚动、吸顶头、下拉刷新、滚动边界 |

## 4. 组件行为（HTML 原型与原生交接共用）

| 组件 | 原生行为要点 | 原型必须能演出来 |
|---|---|---|
| Top app bar | 小/大标题、滚动收起、返回/菜单、动作不超过 2–3 个 | 滚动时收起/展开，返回可点 |
| Bottom navigation | 3–5 项、选中指示、保留各 tab 栈、再次点击回顶 | tab 可切、状态保留、选中态明确 |
| FAB | 主操作、可扩展/收起、避开底栏与 insets | 可点、有按压态、不遮挡内容 |
| List | 单行/双行/三行、leading/trailing、分隔线、分组头、swipe action | 滚动、滑动操作、长按菜单 |
| Card | 只在内容需要独立边界时用；可点击卡有状态层 | 点击有反馈，卡内操作不误触整卡 |
| Chip | 筛选/输入标记；选中态清晰 | 可切换、选中态与计数正确 |
| Bottom sheet | 拖拽/吸附、背景遮罩、返回先关、内容独立滚动 | 可开可关、下滑关闭、最大字号可达关闭 |
| Dialog | 仅用于必须打断的确认；按钮顺序符合平台 | 可开可关、焦点/滚动正确 |
| Snackbar | 底部浮出、可带一个动作、自动消失、可撤销 | 触发后出现、动作可点、不遮挡主操作 |
| Progress | 线性/环形、确定/不确定、超过 1s 才出现 | loading 真实可见、不会永远转圈 |
| Pull to refresh | 下拉阈值、刷新指示、失败保留旧内容 | 可触发、有结果、失败可重试 |
| Search | 进入即聚焦、取消返回、最近/建议、空结果 | 输入、提交、清空、空结果可达 |

**禁止伪控件**：只画外观、点不动的按钮、假开关、假进度、假箭头都不合格（`SKILL.md` §2.2 阶段 2）。

## 5. 密度与视觉重心

- **首屏只服务一个核心任务**：主操作在拇指区；次级入口不与之争抢。
- **一屏一个视觉主角**：数字、地图、封面或列表；不要同时让三个区块都“很重”。
- **分组优于分隔线堆叠**：先靠间距与区块标题分组，再用分隔线；不要每条都描边。
- **嵌套不超过两层**：卡里套卡、面板里再套面板会让层级失焦。
- **信息密度按任务阶段**：首屏克制，详情/专业页可以密；空态/新手态减少选择。
- **滚动节奏**：连续长列表用统一行高与分组头；穿插大图会打断扫描。

## 6. 平台差异：Android vs iOS

| 项 | Android | iOS |
|---|---|---|
| 导航 | 顶部 app bar + 系统返回/手势；底部导航 | 导航栏 + 返回箭头；tab bar；边缘右滑返回 |
| 主操作 | FAB / extended FAB | 导航栏按钮 / 底部主按钮 |
| 表面 | tonal surface + elevation | 材质/毛玻璃（谨慎）、分组列表 |
| 控件形态 | filled/tonal/outlined/text 按钮；Material 组件 | 系统控件形态；自定义需保持平台手感 |
| 动效 | M3 emphasized/standard easing；容器变换 | spring 为主；页面推入/弹出 |
| 触感 | haptic feedback 常量 | UIImpactFeedbackGenerator 等 |
| 字体 | Roboto/系统 sans + Noto CJK | SF Pro / 苹方 |

**不得机械套用默认 Material**：默认组件只保证可用，不保证有辨识度。品牌表达放在色彩、字体、图形、材质与一处签名细节上，不靠改坏平台行为。

## 7. HTML 原型如何演“原生”

1. 设备框只用 `assets/android_frame.jsx` / `assets/ios_frame.jsx`；禁止手写状态栏/刘海/手势条。
2. 用 CSS 变量模拟语义色与 tonal surface；按 4/8dp 节奏写间距；原型基准宽度按目标机型（如 360dp）。
3. 按压态用 `:active` + state layer（12% 主色覆盖）；需要涟漪时用伪元素扩散，不引第三方库。
4. 弹层用底部 sheet 形态：遮罩 + 拖拽把手 + 内容独立滚动；返回先关弹层。
5. 转场用方向性位移 + 淡入（见 `motion-design.md`），不用全屏 cross-fade 代替。
6. `prefers-reduced-motion` 必须给静态替代；循环动画必须有暂停/降级。
7. **CSS px 不是 dp**：原型只证明意图与相对关系，48dp/字体缩放/insets 必须在原生与真机核对。

## 8. 交接：HTML → 原生等价

| HTML 实现 | Android | iOS |
|---|---|---|
| 自绘分段进度 | Canvas/Compose Canvas + 文本层 | CAShapeLayer/SwiftUI Path |
| 底部 sheet | `BottomSheetScaffold` / `BottomSheetDialogFragment` | `UISheetPresentationController` |
| 列表 + 吸顶头 | `LazyColumn` + stickyHeader | `UICollectionView` pinned header / `List` section |
| 状态层/涟漪 | `Modifier.clickable` + indication | `UIButton.Configuration` / 自定义高亮 |
| 共享元素转场 | `sharedTransitionLayout` / MotionLayout | `matchedGeometryEffect` / 自定义转场 |
| 毛玻璃 | RenderEffect（API 31+）或半透明 tonal 替代 | `UIVisualEffectView` |
| Snackbar | `SnackbarHost` | 自定义 toast/banner（iOS 无系统 snackbar） |

**禁止的廉价替代**要写进 `handoff/states-interactions.md`，例如：自绘分段 gauge → 系统单值 `ProgressBar`；底部 sheet → 全屏 dialog；共享元素转场 → 全屏淡入。

## 9. 评审清单（每条都能指向截图）

1. 去掉颜色与图片后，导航与信息层级是否仍成立？
2. 首屏是否只有一个核心任务与一个视觉主角？
3. 是否存在“每条内容一张大卡 + 大留白”的卡片堆？
4. 主/次/三级操作是否用不同形态区分，而不是全是胶囊？
5. 按压/选中/禁用/加载态是否真实存在且可演？
6. 系统栏、手势条、键盘、安全区是否处理（原型与交接都要说明）？
7. 1.0/1.3/1.6/2.0 下关键结构是否有替代形态？
8. 深色模式下表面层级与对比度是否仍成立？
9. 弹层/返回/取消路径是否符合平台习惯？
10. 是否存在只在 hover 下才出现的操作？

**不合格信号**：说不出导航模型；所有区块同等权重；一屏三个主按钮；状态栏是手写的；大字体下靠裁切；“高级感”只来自渐变与阴影。
