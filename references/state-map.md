# 页面-状态地图与覆盖闭合

> **读这份文档的时机**：阶段 0 建理解、阶段 2 判原型覆盖、阶段 4 交接、阶段 6 验收。
> **一句话立场**：页面清单不是理解，**每个页面在哪些状态下被建模、被渲染、被验证**才是理解。
> 权威流程在 `SKILL.md`；本文只给方法与格式。

---

## 0. 为什么需要它

两次真实改版的失败都出在这里，而不是出在提示词：

- brief 写了「锁定三态」，原型却假设"下一站永远可走"，真实 `JourneyNextStop` 会返回锁定站 → 原生阶段才发现，改动面扩散到四个 action。
- brief 写了「大字体」，原型只渲染 mine@1.45，没渲染 1.6 → 真机三列摘要错位。
- brief 声明 22 页全覆盖，原型只有 5 类页面 → 报告与实现各说各话。
- brief 抄了文档里的 streak 规则（昨日 ≥3000），UI 实际走 `computeStreakDays(goal)` → 文案与代码冲突。

**结论**：理解必须有出处，覆盖必须有去向，去向必须能被机器核对。

## 1. 什么时候建

| 任务 | 深度 |
|---|---|
| 整机 / 多页面系统级重设计 | 全量地图：所有 `P*`、`S*`、`X*` |
| 新增一个页面或一条核心流程 | 该页 + 出入页 + 相关全局状态 |
| 只改单页视觉 | 该页 + 它的空/错/大字体状态 |
| 只换 token / 圆角 / 字体 | 不建地图（但视觉回归照跑） |
| 只改业务逻辑、不动 UI | 不触发本流程 |

深度按**风险**，不按模板。地图写薄了会漏状态；写厚了没人看。标准是：实现端不用回来问"这个状态长什么样"。

## 2. id 方案

| 前缀 | 含义 | 例 |
|---|---|---|
| `P*` | 页面（可导航到的独立界面） | `P3 今日`、`P8 环球路线` |
| `S*` | 弹层 / 底部弹层 / 对话框 / 抽屉 | `S4 目标选择`、`S9 城市详情` |
| `X*` | 全局或跨页状态（不属于单一页面） | `X1 权限被拒`、`X4 离线`、`X6 激励视频不可用` |

规则：

- id **稳定**：一旦分配，后续 brief / coverage / 原型 / 交接 / 验收都用同一个 id，不改号。
- 一个界面只属于一个 id；同一页面的多状态写在状态集合里，不另开 id。
- Widget / 通知 / 快捷方式等外部入口，能进入 App 就记一条 `P*` 或 `X*`，不另建体系。
- 旧版有、本次要下线的页面也要列，标「下线」，避免实现端以为漏做。

## 3. 每项必填字段

| 字段 | 要写什么 | 不合格的样子 |
|---|---|---|
| `id` / `title` | 稳定编号与用户看得懂的名字 | "页面1" |
| **用户目标** | 用户在这一屏要完成什么 | "展示信息" |
| **入口 / 出口** | 从哪来、到哪去、返回去哪 | 只写"底部 tab" |
| **主要功能** | 能做什么、关键操作是什么 | 罗列控件 |
| **关键信息与优先级** | 第一眼必须看到什么、其次是什么 | 平铺全部字段 |
| **数据 / 规则出处** | 每个展示值与业务规则的**真实来源**：`file:line`、数据表、接口 | "见 AGENTS.md" |
| **状态集合** | 该页真实可能出现的状态（见 §4） | 只写"正常" |
| **平台约束** | 权限、系统栏、键盘、深色、缩放风险 | 空白 |
| **当前问题** | 这一屏现在哪里不好（可被用户感知） | "不够美观" |
| **保留依据** | 哪些成熟体验要留，为什么 | "保持原样" |
| **重构范围** | 确认要改的部分 | 空白 |
| **覆盖去向** | 原型 `rendered` / `deferred-native` / `not-applicable` | 不写 |

### 3.1 出处规则（硬）

1. 界面上展示的**每个数值**与**每条业务规则**，都要能指到真实 UI 代码路径或数据源。
2. 只能找到文档/注释里的规则时，必须同时记录「文档规则」与「UI 实际路径」，并标明是否一致。
3. **不一致时列为待决**：写清两处出处、影响哪屏、需要谁拍板。**不得静默选一个**，也不得把文档规则当成 UI 事实。
4. 查不到就标 `ASSUMPTION` 并说明影响；不要让假设悄悄变成界面文案。
5. 不从截图反推业务规则：截图只能证明"长什么样"，不能证明"为什么这样算"。

## 4. 状态枚举库（按需取，不强制全填）

**页面级**：默认 / 加载 / 空数据 / 数据不足 / 取数失败 / 部分失败 / 首次使用 / 进行中 / 已暂停 / 已完成 / 锁定 / 未解锁 / 解锁中 / 额度用尽 / 完成终态（全部完成后）。

**权限与系统**：未授权 / 授权中 / 拒绝（可再问）/ **永久拒绝**（需去设置）/ 后台权限缺失 / 通知权限缺失 / 电池优化限制 / 定位或健康数据不可用。

**网络与外部**：离线 / 弱网 / 超时 / 外部依赖不可用（广告、视频、支付、地图）。

**平台适配**：最大字号 `2.0` / 深色模式 / 小屏 / 大屏 / 横屏（若支持）/ 键盘弹出 / 系统栏与手势条 / 动态列表与中文长文案。

**商业化与合规**：广告位展示 / 广告加载失败 / 激励视频不可用 / 免费额度边界 / 隐私同意 / 协议版本失效 / 儿童或特殊用户限制（若项目有）。

**不要为了凑齐而编造状态**：项目里不存在的能力不列；列了就要有真实呈现或明确 `not-applicable` 理由。

---

## 5. 跨页关系

除了单页字段，地图还要能回答：

- **导航结构**：tab / stack / drawer / 手势，层级深度，返回行为。
- **关键任务路径**：跨页主流程（如「今日 → 目标选择 → 保存 → 返回」），每步的成功/失败/取消出口。
- **共享状态**：哪些状态跨页影响（权限、额度、锁定、选中城市），改一处要同步哪些屏。
- **唯一入口约束**：某功能在多个页面都有入口时，写清哪一个是主入口，其余是快捷方式，避免实现出两套行为。

## 6. 覆盖闭合（G2 的核心）

原型不是"画了几台手机"，而是**地图里每一项都有去向**。

| 去向 | 含义 | 必须附 |
|---|---|---|
| `rendered` | 原型里真实渲染且可交互 | 屏名/查询参数 |
| `deferred-native` | 本次不渲染，留到原生实现 | 理由 + `native_verify: true` |
| `not-applicable` | 项目里不存在或本次明确不做 | 理由 |

**允许 deferred 的典型理由**：状态依赖无法在 HTML 中造出的真实数据（如需已解锁成就）、平台专有 UI（Widget）、依赖真实硬件（传感器）、触发条件不可控（广告回调）。

**不允许用 deferred 掩盖**：能做而没做、忘了做、懒得做。differential 判据是"HTML 里造得出吗"——造得出就必须渲染。

**页面地图有而原型没有的项不得静默消失**：阶段 2 结束时逐项核对，缺失即 G2 不通过。

## 7. `coverage.json`

机器可核对的单一事实源。整机/多页面重设计必需；局部迭代可选。

```json
{
  "schema": "designwise-coverage/v1",
  "scales": ["1.0", "1.3", "1.6", "2.0"],
  "items": [
    {
      "id": "P3", "kind": "page", "title": "今日",
      "prototype": "rendered", "screens": ["p1-today", "p6-today-1.45"],
      "scales_rendered": ["1.0", "1.6"],
      "native": "done",
      "device": {"1.0": "pass", "1.3": "not-tested", "1.6": "pass", "2.0": "not-tested"},
      "notes": "1.3/2.0 未测：设备档位只有 1.0/1.45/1.6"
    },
    {
      "id": "S9", "kind": "overlay", "title": "城市详情",
      "prototype": "rendered", "screens": ["p2-city-done"],
      "scales_rendered": ["1.0", "1.6"],
      "native": "todo", "device": {},
      "notes": "需在 1.6 下确认关闭按钮可达"
    },
    {
      "id": "X6", "kind": "state", "title": "激励视频不可用",
      "prototype": "deferred-native", "screens": [],
      "defer_reason": "HTML 无法模拟广告 SDK 回调；原生用假配额驱动",
      "native_verify": true,
      "native": "todo", "device": {}
    }
  ]
}
```

枚举：

| 字段 | 允许值 |
|---|---|
| `kind` | `page` / `overlay` / `state` |
| `prototype` | `rendered` / `deferred-native` / `not-applicable` |
| `native` | `todo` / `done` / `not-applicable` |
| `device.<scale>` | `pass` / `fail` / `not-tested` / `not-applicable` |

约束：

- `deferred-native` 必须有 `defer_reason` 且 `native_verify: true`。
- `not-tested` / `fail` 必须有 `notes` 说明缺什么条件或怎么修。
- `scales_rendered` 是实际渲染过的档位，不是打算渲染的档位。
- **地图与 coverage 的 id 集合必须一致**；不得新增未登记的 id，也不得让已登记 id 消失。
- 文件由 `scripts/check-deliverables.py` 校验结构、枚举与 id 集合；**结构合法不等于覆盖合理**，语义仍由设计判断。

## 8. 常见失败（都真实发生过）

| 失败 | 症状 | 防法 |
|---|---|---|
| 只写正常态 | 实现端自己发明空/错态 | 状态枚举库逐项过；空/错必须渲染 |
| 状态写在 brief 却不进原型 | 锁定态、额度用尽、永久拒绝 | 覆盖矩阵强制每项有去向 |
| 只验证一个缩放档 | 1.6 才错位 | `scales_rendered` 记录实际档位；高风险结构必须在最大档 |
| 规则抄文档 | streak 与代码冲突 | 出处规则 + 冲突列待决 |
| 页数声明大于原型 | 报告说 22 页，原型 5 类 | coverage 与地图 id 集合一致 + 报告数字可数 |
| 弹层只画 1.0 | 最大字号裁切、关闭不可达 | 弹层必须在最大档渲染并声明滚动容器 |

## 9. 交付前自检

1. 地图里每个 id 都有 `coverage.json` 记录吗？
2. 每条 `deferred-native` 的理由是否成立（HTML 真的造不出）？
3. 每个展示值与业务规则的出处，能点开看到吗？
4. 存在「文档规则 ≠ UI 路径」的项吗？是否已列为待决？
5. 多列 / 同行 label+value / 固定高度结构，是否在最大缩放档渲染过？
6. 弹层的关闭路径在最大档可达吗？
7. 报告里的页数、截图数、测试数，能在文件里数出来吗？
