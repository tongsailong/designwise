# 生图方法论与执行手册 · GPT-image（App UI 版）

> **读这份文档的时机**：要写生图 prompt、要判断模型能不能做、要批量出图/抠图/转换、或出图失败要查原因时。
> **本文吸收自** huashu-gpt-image 的提示词方法论、能力边界、批量与失败处理经验，并**按 App UI 场景重写**；生成入口统一为 DesignWise 的 `scripts/zcode_image.py`，不依赖其他 skill。
> **不重复的规则**：三方向概念图的流程位置、结构骨架与不可迁移声明、Copilot 送选，见 `references/app-visual-workflow.md` 阶段 2/3；素材登记与复用见 `references/image-assets.md`。

## 1. 先判断：这张图该不该生成

| 场景 | 做法 |
|---|---|
| 内容必需的图（人物、地点、实物、产品、场景） | **真实资产优先**；没有才生成，并标注生成来源 |
| 抽象概念 / 情绪 / 叙事背景 / 原创插画 | 生成是最优载体 |
| 数值 / 趋势 / 对比 / 结构 | 用真实数据可视化，不用装饰性 3D 球代替 |
| 材质 / 光泽 / 纹理 / 氛围 | 优先 CSS/SVG/Canvas 程序化，可调、可响应、零版权风险 |
| 图标 / 简单几何 / 控件 | **矢量化或代码实现**，不生成位图 |
| 装饰性配图 | 默认不生成；去掉后信息无损的图就是装饰 |

**真图诚实性测试**：去掉这张图，信息是否有损？有损 → 内容必需；无损 → 装饰，可以不加。

## 2. Prompt 硬约束（违反任何一条都是 AI slop）

### 2.1 默认中文写，图内描述性文字也默认中文

- 模型中英文理解对等；中文更精炼。
- ❌ 禁止默认英文段落式 prompt；❌ 禁止 `Subject:` / `Style:` / `Constraints:` 伪结构。
- 图内文字：描述性标签/标题/解释用中文；品牌名/产品名原样；技术术语/论文名可英文；数字规格原样。
- **必须显式写「图内描述性文字用中文」**，否则模型会按训练数据偏见跳到全英文。

### 2.2 长度看信息密度，不设硬上限

判断标准：删掉一半字，模型会不会损失信息？会损失就合格；不损失说明堆了无效形容词。

- 简单单图 30 字内理想。
- 构图型（人物位置/占比/手势/遮挡/大字位置）可到 200 字，因为每句都是空间决策。
- 无论多长，形容词堆砌禁止。

### 2.3 用真实参考名替代形容词

| ❌ 形容词 | ✅ 真实锚点 |
|---|---|
| minimalist editorial illustration | Anthropic 风格 / Field Notes 风格 |
| mid-century modern feel | Saul Bass 风格 |
| bold flat shapes | 朱赢椿装帧线条 |
| editorial with film grain | A24 海报质感 |

**1 个真名 > 5 个形容词。** 但出版物品牌名（The Economist / WSJ / NYT Magazine 等）会被画成 nameplate，且自动全英文——要么不用，要么显式加「严禁外文品牌名水印，严禁左上角 nameplate」。

### 2.4 写完必跑 5 项自检

- [ ] 1. 是中文还是英文段落？英文段落默认重写（除非主体是英文品牌名/设计师名，或用户明确要求英文）
- [ ] 2. 长度与场景匹配？简单单图 30 字内；构图型可长，但每句必须是空间关系或具体内容
- [ ] 3. 三槽位（主体/风格/媒介）有几个真名锚点？默认 ≥2；无真名时用「结构化描述 + 风格词」并说明
- [ ] 4. 有伪 section？有必须删
- [ ] 5. 删掉 50% 的字，模型还能理解吗？能就砍

**任何一条不过 → 不交付 prompt → 修复后重跑全部 5 项。**

## 3. 第一性原理

### 3.1 概念压缩比

Prompt 的有效信息 ≠ 字数。决定质量的是**单字承载的设计决策密度**。

> 「Dieter Rams 风格的大疆 Pocket 3 说明书」16 个字 → 完整 A4 说明书含真实参数。

写之前问：主体/风格/媒介三个槽位，能不能各填一个模型熟知的高频名字？能 → 短 prompt；有空槽 → 该槽位用结构化描述补足。

### 3.2 三种工作模式

| 模式 | 你心里有 | Prompt 形态 | 适合 |
|---|---|---|---|
| **执行** | 清晰目标 | 三层全给 | 已定方向、正式素材、品牌物料 |
| **混合** | 有方向不定细节 | 上下文 + 不要什么 | 日常大部分情况 |
| **探索** | 没答案想看惊喜 | 只给上下文 + 防 slop | 找新方向 |

**节奏**：不确定方向 → 先探索 5–10 张看方向 → 定方向 → 切执行模式深化批量。**不要一上来就执行模式**。

### 3.3 三层指令架构

1. **上下文层**：who（观众）/ why（解决什么问题）/ for what（看完做什么）
2. **约束层**：必须 / 禁止 / 冲突时优先级
3. **表面层**：媒介 / 风格 / 参考 / 技术参数

业余 prompt 只写第 3 层；专业 prompt 三层都给。

### 3.4 三维质量模型

```
输出质量 = 载体匹配度 × 精神理解深度 × 创造贡献空间
```

- **载体匹配度**：风格的原生载体与目标载体是否同类（Dieter Rams 是工业产品 → 用在表格不匹配，用在包装完美）。
- **精神理解深度**：模型对该风格是表层标签还是深层精神（Bauhaus 深 / Wes Anderson 浅）。
- **创造贡献空间**：载体允不允许品牌命名/slogan/隐喻贡献（包装空间大 / 价目表空间小）。

### 3.5 结构性 vs 气质性风格

| 类型 | 特征 | 例 | 用法 |
|---|---|---|---|
| **结构性** | 有明确版式/网格/字体/色板规则，模型能精准迁移 | Swiss / Bauhaus / Penguin Books / Dieter Rams | 可直接用真名锚定 |
| **气质性** | 靠氛围、镜头、调色，模型只能抓表层 | Wes Anderson / A24 / 电影感 | 必须补结构化描述或 `--ref` |

## 4. 能力边界（以现场实测为准）

| 维度 | 实测口径 | 对 App UI 的含义 |
|---|---|---|
| **中文** | 20+ 字符可准确生成；成语/古诗/对联/印章可做 | 概念图里可放中文示意，但**仍不得当作文案依据** |
| **均匀网格** | 4×4 稳定；5×5 需技巧，末行易压缩 | 批量 icon/角色集 ≤4×4；超过拆批 |
| **画布** | 官方预设 1024²、1024×1536、1536×1024、2560×1440；最大边 <3840、总像素 65 万–830 万、比例 ≤3:1 | App 概念图用 1024×1536 竖版 |
| **quality** | low / medium / high；密集布局、中文、卡牌必须 high | 方向图与正式素材用 high（由上游默认/参数控制） |
| **`--size`** | CPA **可能不遵守**，模型自选画布 | 比例写进 prompt；最终像素用 `--fit` 落地 |
| **透明背景** | 默认不稳；不要假定能出透明底 | 需要透明 → 纯色幕布 + 抠图（§7） |
| **文字下标** | 模型画文字标签做「下标」易乱码 | 用顺序映射/图例，不靠图内小字 |
| **辅助元素** | 一切「辅助装饰」都是污染源 | prompt 明确不要无关元素 |

> 以上是 `gpt-image-2` 的实测口径；默认模型 `gpt-image-2.5` 的差异化能力**尚未逐条重测**，不要把旧数字当 2.5 的结论。**以当次 `--health` 与真实出图结果为准。**

## 5. 单图 / 单素材标准工作流

1. **确认用途与尺寸**：用在哪、什么比例、最终像素、透明/不透明、深色模式是否需要变体。
2. **选模式**：执行 / 混合 / 探索。
3. **写中文 prompt**：三槽位 + 三层架构；方向图另加结构骨架与不可迁移声明。
4. **跑 5 项自检**：不过不生成。
5. **调用**：
   ```bash
   python3 scripts/zcode_image.py --prompt "<prompt>" --out assets/images/xxx.png \
     --size 1024x1536 --fit contain
   ```
   需要参考图时加 `--ref <真实参考图>`，走 `/images/edits`。
6. **验收**：尺寸/比例、中文准确性、关键信息在安全区、设计史细节真实、无伪控件/伪 chrome、与选定方向一致。
7. **登记**：写入 `asset-manifest.json`（来源、模型、prompt、参考、sha256、变体、消费者）。

**失败不要「再试一次」碰运气**：先读错误，按 §9 失败树处理。

## 6. 批量生成（icon 集 / 角色集 / 卡牌集 / 贴图）

### 6.1 画布与网格

- 画布比例要匹配内容：竖版角色用 2:3，方形 icon 用 1:1；不要用 1:1 画布塞 2:3 卡。
- 均匀网格 **≤4×4**；5×5 末行易压缩 18%。
- 各行主体居中、与边框留足间距，避免抠图切到头部/配件。
- prompt 写：`无网格线/无边框/无定位标记`，但保留清晰单元间距。

### 6.2 批量 prompt

- 中文写，压到 90 字内精准命中；长 prompt 会稀释网格硬约束。
- 明确「每个单元格一个独立主体、统一大小、主体居中、纯色背景」。
- 视角/姿态用功能类别词（`2D 横版游戏 sprite`），不要用美学风格词（会被风格惯性覆盖）。

### 6.3 抠图与预览

随仓库提供三个脚本（从 huashu-gpt-image 迁入并自包含）：

```bash
# 网格切分：bbox 按内容定位（推荐）/ density 按密度扫描
python3 scripts/extract_grid.py grid.png --out out/ --mode bbox

# 拼预览图检查质量
python3 scripts/contact_sheet.py --input out/ --out preview.png --grid 4x4

# 单图纯色幕布抠透明（无 API 透明背景时的方案）
python3 scripts/chroma_key.py in.png out.png [tol_low=62] [tol_high=110] [erode=2]
```

**抠图前提**：主体配色里不含幕布色。生成时 prompt 明确「纯平涂 #RRGGBB 背景，无渐变无阴影，主体留边距」。

**已知问题**：网格线残留 → 改 bbox 模式；子图头部缺失 → 改 bbox；颜色被误清 → 锚点检测只在四角局部区域；尺寸参差 → 3 像素膨胀；行高不均 → 降 4×4。

## 7. 图片处理与转换

| 需求 | 做法 |
|---|---|
| 精确尺寸 | `--size` + `--fit cover|contain|stretch`（Pillow 后处理） |
| 裁切焦点 | 记录焦点坐标/比例；不依赖 `cover` 自动居中 |
| 透明 | 纯色幕布 + `chroma_key.py`；或原生 PNG alpha |
| 压缩 | 按平台要求；WebP/PNG；不反复有损重压 |
| 深色模式变体 | 单独生成或程序化调色；登记为同一资产变体 |
| 多倍图 | Android `drawable-*dpi`；iOS `@2x/@3x`；从同一母版导出 |

**本机没有 `sips` / `magick` / `convert`**（以现场为准）；后处理走 Pillow。所有转换记录到 `asset-manifest.json` 的 variants。

## 8. 与 App UI 的一致性

- **同一方向的素材共享视觉语言**：色板、光照、材质、线宽、圆角、纹理。
- **参考一致性**：需要角色/物体一致时，先用一张干净 master，再以 master 作 `--ref` 生成其它姿态。
- **不要用生成图冒充真实产品/品牌资产**：真实 logo、产品图走 `references/brand-asset-protocol.md`。
- **概念图不能直接当正式素材**：只能提取视觉语言；正式素材重新生成或在原型中矢量化。
- **图标优先矢量化**：简单图标用 SVG/VectorDrawable，不生成位图。
- **记录裁切**：CSS `object-fit: cover` 与原生 `CENTER_CROP` 的焦点不同，必须逐端记录。

## 9. 失败模式与 fallback 树

### 9.1 Prompt 层

| 现象 | 原因 | 一线修复 | 仍失败 |
|---|---|---|---|
| 输出「安全好看」无惊喜 | 风格被中和、画面过满 | 切探索模式，让模型先说判断再画 | 加「请贡献品牌名 + slogan + 命名逻辑」invite 模式 |
| 风格 vs 品类自动妥协（Apple 中药变温润） | 模型内置和谐倾向 | 明确写「保留风格精神不动摇」 | 用 `--ref` 提供风格 DNA |
| 模型不会减法、画面过满 | 缺少减法指令 | 「先列 8 个再砍到 4 个」 | prompt 明确「只保留核心元素」 |
| 气质性风格 transfer 不像 | 只有风格名，没有结构 | 补构图/色板/景深/姿势 | 找代表作单图作 `--ref` |
| 出版品牌名被画成 nameplate | 出版物真名触发 nameplate | 删品牌名，用描述词 | 加「严禁外文品牌名水印」 |
| 中文错字/缺字 | quality 不够、prompt 没提 | 升 high + 显式要求每个汉字准确 | 中文文本放最前，双引号包裹 |
| 设计史细节错（年代/口号/合作品牌） | 模型串台 | 自己核实，不直接引用 | 从 prompt 删掉可疑信息 |
| 多端安全区被裁 | 关键信息在外围 | 收到中央安全区，≤3 个核心信息 | 减少信息条数 |

### 9.2 执行层

| 现象 | 处理 |
|---|---|
| `--health` 失败 | 报告接口不可用；不伪造；不自行改 CPA 配置（属高等级动作） |
| 404 `/v1/images/generations` | 只读确认原因并报告；不改配置、不重启核心；不自动换链路 |
| 401/403/429/400 | 按错误原文改 prompt/参数或等额度；**不无条件重试** |
| 超时/5xx | 结果不确定；先确认上游是否受理，避免重复消耗；不自行降级 |
| 模型不支持 | 换 `--model` 为现场支持清单内的型号 |
| 尺寸不对 | `--size` 只是请求；用 `--fit contain/cover` 落地；裁掉 >25% 要告警 |
| 生成成功但文件损坏 | 魔数/完整性校验失败；重出该张，不拼接 |
| 透明底不稳 | 纯色幕布 + `chroma_key.py` |

**原则**：先一线修复（成本低），再换手段；每次 fallback 记录原因；不循环重发。

## 10. 成本与授权

- 在用户已配置并授权的 Provider/模型/账户范围内，正常生图调用属任务成本，**不需逐次请示**。
- **不新增 Provider、不购买服务/额度、不改变付费方案**；超出授权范围先说明再取得授权。
- 一次一张、按实际需要决定数量；不重复生成已有合格素材，不为微小差异反复生图。
- 记录实际调用量/费用（可获得的）；无数据标未知，不估算冒充账单。

## 11. 提示词模板

### 11.1 方向图

```text
App 竖版界面概念图，3 屏并排，比例 2:3。
方向「<名>」：参考 <真实风格/产品/设计师> 的 <可迁移特征>。
结构骨架：<分栏数>；信息层级 <几级>；密度 <疏/中/密>；
首屏视觉锚点 <在哪>；导航 <形态>；核心控件 <位置>。
图内描述性文字用中文；图内文字为示意，不作文案与精确规格依据；
不出现外文 nameplate、水印、签名。
```

### 11.2 插画 / 背景 / 装饰

```text
<真实锚点> 风格的 App <用途> 插画：<主体/场景一句话>。
构图：<主体位置/占比/视线/留白>；色板：<主色 + 辅色 + 底色>；
光照/材质：<具体>；输出 <尺寸/比例>，<透明/不透明>。
不要文字、不要 logo、不要水印、不要无关装饰元素。
```

### 11.3 图标视觉稿

```text
<风格> 的 App 图标概念：<主体隐喻一句话>。
<圆角方形/圆形> 画布，主体居中，<线宽/材质/光照>；
背景 <纯色/微渐变>；无文字、无阴影溢出、无多余装饰。
```

### 11.4 角色/物体一致性

```text
以参考图中的 <角色/物体> 为准，保持 <身份特征/配色/材质/比例> 不变。
新姿态/场景：<描述>。同一光照与视角，<尺寸>，<背景>。
不要改变角色身份特征，不要新增配饰。
```

## 12. 收尾

**Prompt 的上限等于你脑子里的概念库。** 最值得长期投入的不是 prompt 技巧，是研究真实的设计师、品牌、媒介范式——每多认识一个精准的名字，上限就抬高一点。
