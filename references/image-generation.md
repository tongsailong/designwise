# 生图方法论与执行手册 · GPT-image（App UI 版）

> **读这份文档的时机**：要写生图 prompt、要判断模型能不能做、要批量出图/抠图/转换、或出图失败要查原因时。
> **本文吸收自** huashu-gpt-image 的提示词方法论、能力边界、批量与失败处理经验，并**按 App UI 场景重写**；生成入口统一为 DesignWise 的 `scripts/zcode_image.py`，不依赖其他 skill。来源、版权与许可见 `THIRD_PARTY_NOTICES.md`。
> **不重复的规则**：概念方向的流程位置、方向数量、结构骨架与不可迁移声明、差异实测与决策记录，见 `direction-strategy.md` 与 `app-visual-workflow.md` 阶段 1；素材登记与复用见 `image-assets.md`。

## 1. 先判断：这张图该不该生成

| 场景 | 做法 |
|---|---|
| 内容必需的图（人物、地点、实物、产品、场景） | **真实资产优先**；没有才生成，并标注生成来源 |
| 抽象概念 / 情绪 / 叙事背景 / 原创插画 | 生成是最优载体 |
| 数值 / 趋势 / 对比 / 结构 | 用真实数据可视化，不用装饰性 3D 球代替 |
| 材质 / 光泽 / 纹理 / 氛围 | 优先 CSS/SVG/Canvas 程序化，可调、可响应、零版权风险 |
| 图标 / 简单几何 / 控件 | **矢量化或代码实现**，不生成位图 |
| 装饰性配图 | 默认不生成；去掉后信息无损的图就是装饰 |

**真图诚实性测试**：去掉这张图，信息是否有损？有损 → 内容必需；无损 → 装饰，可以不加。

### 1.1 视觉资产计划（先规划，再生成）

生图不是“用户点名才做”的可选项。**阶段 0 结束前先做一张视觉资产计划**，再决定生成哪些。

**七个字段（位置 / 角色 / 内容职责 / 素材来源 / 尺寸与比例 / 主题变体 / 消费者）与模板只在 `references/image-assets.md` §1.5 维护**，本文不复述。

**决策顺序**：内容必需 → 真实资产优先 → 能程序化/矢量化的不生成位图 → 需要原创叙事才生成 → 装饰默认不生成。

**默认主动评估的场景**（产品确有对应内容时才做，不为使用图片而使用图片）：
- 首页/核心页的主题 hero 或场景插画；
- 空态、引导、错误态的说明插画；
- 有真实成长/探索机制时的世界地图、场景、角色、物品；
- 有质感的背景纹理与装饰（低对比、可平铺）；
- 启动页、里程碑、完成态的专属视觉。

**明确不做**：把文字生成进图（重要文字用真实 UI）；用生成图冒充真实产品/品牌/用户照片；同一页面堆多张无语义装饰图；生成图标位图代替矢量。

## 2. Prompt 硬约束（违反任何一条都是 AI slop）

### 2.1 默认中文写，图内描述性文字也默认中文

- 模型中英文理解对等；中文更精炼。
- ❌ 禁止默认英文段落式 prompt；❌ 禁止 `Subject:` / `Style:` / `Constraints:` 伪结构。
- 图内文字：描述性标签/标题/解释用中文；品牌名/产品名原样；技术术语/论文名可英文；数字规格原样。
- **必须显式写「图内描述性文字用中文」**，否则模型会按训练数据偏见跳到全英文。

### 2.2 长度看信息密度，不设硬上限

判断标准：删掉一半字，模型会不会损失信息？会损失就合格；不损失说明堆了无效形容词。

- 简单单图 30 字内理想。
- 构图型（人物位置/占比/手势/遮挡/大字位置）可到 200 字，因为每句都是空间决策。
- 无论多长，形容词堆砌禁止。

### 2.3 用真实参考名替代形容词

| ❌ 形容词 | ✅ 真实锚点 |
|---|---|
| minimalist editorial illustration | Anthropic 风格 / Field Notes 风格 |
| mid-century modern feel | Saul Bass 风格 |
| bold flat shapes | 朱赢椿装帧线条 |
| editorial with film grain | A24 海报质感 |

**1 个真名 > 5 个形容词。** 但出版物品牌名（The Economist / WSJ / NYT Magazine 等）会被画成 nameplate，且自动全英文——要么不用，要么显式加「严禁外文品牌名水印，严禁左上角 nameplate」。

### 2.4 写完必跑 5 项自检

- [ ] 1. 是中文还是英文段落？英文段落默认重写（除非主体是英文品牌名/设计师名，或用户明确要求英文）
- [ ] 2. 长度与场景匹配？简单单图 30 字内；构图型可长，但每句必须是空间关系或具体内容
- [ ] 3. 三槽位（主体/风格/媒介）有几个真名锚点？默认 ≥2；无真名时用「结构化描述 + 风格词」并说明
- [ ] 4. 有伪 section？有必须删
- [ ] 5. 删掉 50% 的字，模型还能理解吗？能就砍

**任何一条不过 → 不交付 prompt → 修复后重跑全部 5 项。**

## 3. 第一性原理

### 3.1 概念压缩比

Prompt 的有效信息 ≠ 字数。决定质量的是**单字承载的设计决策密度**。

> 「Dieter Rams 风格的大疆 Pocket 3 说明书」16 个字 → 完整 A4 说明书含真实参数。

写之前问：主体/风格/媒介三个槽位，能不能各填一个模型熟知的高频名字？能 → 短 prompt；有空槽 → 该槽位用结构化描述补足。

### 3.2 三种工作模式

| 模式 | 你心里有 | Prompt 形态 | 适合 |
|---|---|---|---|
| **执行** | 清晰目标 | 三层全给 | 已定方向、正式素材、品牌物料 |
| **混合** | 有方向不定细节 | 上下文 + 不要什么 | 日常大部分情况 |
| **探索** | 没答案想看惊喜 | 只给上下文 + 防 slop | 找新方向 |

**节奏**：不确定方向时，**先写方向卡再用最小数量验证**（App 概念方向按场景定：新产品概念默认 3 个独立结构假设，已有产品按实质分歧，见 `SKILL.md` 阶段 1），不靠抽卡找方向；方向定后切执行模式深化或补素材。**不要一上来就执行模式**，也不要为「多看看」批量生成无信息增量的图。

### 3.3 三层指令架构

1. **上下文层**：who（观众）/ why（解决什么问题）/ for what（看完做什么）
2. **约束层**：必须 / 禁止 / 冲突时优先级
3. **表面层**：媒介 / 风格 / 参考 / 技术参数

业余 prompt 只写第 3 层；专业 prompt 三层都给。

### 3.4 三维质量模型

```
输出质量 = 载体匹配度 × 精神理解深度 × 创造贡献空间
```

- **载体匹配度**：风格的原生载体与目标载体是否同类（Dieter Rams 是工业产品 → 用在表格不匹配，用在包装完美）。
- **精神理解深度**：模型对该风格是表层标签还是深层精神（Bauhaus 深 / Wes Anderson 浅）。
- **创造贡献空间**：载体允不允许品牌命名/slogan/隐喻贡献（包装空间大 / 价目表空间小）。

### 3.5 结构性 vs 气质性风格

| 类型 | 特征 | 例 | 用法 |
|---|---|---|---|
| **结构性** | 有明确版式/网格/字体/色板规则，模型能精准迁移 | Swiss / Bauhaus / Penguin Books / Dieter Rams | 可直接用真名锚定 |
| **气质性** | 靠氛围、镜头、调色，模型只能抓表层 | Wes Anderson / A24 / 电影感 | 必须补结构化描述或 `--ref` |

### 3.6 艺术方向卡（同一 App 的素材必须共享）

正式素材开始前写一张，写入任务素材目录的 `art-direction.md`，所有生成共用：

```markdown
## 艺术方向
- 气质：<三个能指向产品/用户的词>
- 色板：主色 <hex> / 辅色 <hex> / 底色 <hex> / 暗色策略
- 光照：主光方向 / 软硬 / 色温 / 阴影强度
- 材质：<纸/哑光/玻璃/金属/有机> + 噪点/笔触
- 线条：线宽 / 圆角 / 描边 / 是否描边
- 构图：主体占比 / 留白 / 视角 / 景深
- 人物/物体：比例 / 简化程度 / 身份特征
- 禁止：写实照片感 / 3D 渲染 / 霓虹 / 文字 / 水印 / 无关装饰
```

**一致性规则**：同一角色/物体先出干净 master，再以 master 作 `--ref` 生成其它姿态；同一批素材共用色板、光照、线宽；暗色变体单独生成或按 token 调色，不简单反相。

## 4. 当前模型口径（GPT-Image-2.6）

> 历史 `gpt-image-2` 的实测（中文长度、网格、画布预设等）只作历史参考，**不再作为当前参数依据**；以下以 2.6 的官方参数语义与现场网关探测为准。旧版本参数不要套到 2.6。

### 4.1 GPT-Image-2.6 双模型与参数（官方口径）

2026-11-18 核对 OpenAI Image prompting 文档：

| 参数 | 2.6 取值 | 语义 |
|---|---|---|
| `model` | `gpt-image-2.6-flare` / `gpt-image-2.6-sunburst` | Flare 速度优先；Sunburst 细节、版式与编辑精度优先 |
| `complexity` | `low` / `medium` / `high`（省略时 **high**） | 渲染前的场景规划算力；**不是画质** |
| `quality` | `auto` / `low` / `medium` / `high` / `xhigh` / `max` | 渲染细节、纹理、小字；**不是规划算力** |
| `size` | `auto` / `1024x1024` / `1536x1024` / `1024x1536` / 自定义 | 自定义宽高为 16 的倍数，比例 1:3–3:1 |
| `background` | `auto` / `opaque` / `transparent` | PNG/WebP 透明必须回读 alpha |
| `output_format` | `png` / `jpeg` / `webp`（上游生成也支持 `svg` / `gif`） | 仅 JPEG/WebP 支持 `output_compression`；**本仓库脚本只落 png/jpeg/webp** |
| `markup` | edits 的透明叠加层 | 与 `mask` / `prompt_rewriter` 互斥；**本仓库脚本未暴露这些参数**，需要透明叠加时用 `--ref` + 纯色幕布 + `chroma_key.py` |

**DesignWise 路由**：profile 表（`final` / `premium` / `max` / `explore` / `draft`）**只在 `SKILL.md` §6.1 维护**，本文不复述；两者冲突时以 `SKILL.md` 为准。

**选型原则**：正式视觉资产默认 Sunburst；只有明确的速度/成本优先探索才用 Flare；精品才升 `xhigh`/`max`，不把所有图一律 max。参考图编辑优先 Sunburst，因为跨轮主体一致性是它的强项。

### 4.2 网关现场探测边界（不写死机器结论）

以下不是某台机器的永久快照，而是**每次任务要现场探测**的已知边界；以 `--health`、实际响应和最终文件回读为准：

- **模型可用**：`--health` 检查默认 2.6 模型是否真实可用；缺失即失败关闭，不静默降级。
- **complexity**：请求可能被接受但不回显；不能从响应证明生效。按请求记录，以构图/元素关系验收。
- **quality**：响应字段与请求**不一定一致**（曾见 high 回 medium/low）。响应字段不能当生效质量证据；以实际产物、细节与视觉验收为准，并在 metadata 记录 mismatch。
- **size**：可能只近似遵守。最终像素必须由本地 Pillow `--fit` 保证并回读校验。
- **output_format**：请求 WebP 时网关可能仍返回 PNG；脚本本地转 WebP/JPEG 并记录 `source_format`，最终格式回读校验。
- **background transparent**：可能可用也可能不稳定；脚本回读 alpha，没有 alpha 就失败关闭，不假定透明底成功。
- **安全系统**：含在世艺术家/品牌风格模仿的 prompt 可能被 `moderation_blocked`。改用结构性描述、媒介与色板约束；**不上诉、不绕过、不换账户**。
- **不静默降级**：模型失败、2.6 缺失或参数不被接受时，报告原因与实际模型；不自动切回旧模型或其他 Provider。

## 5. 单图 / 单素材标准工作流

1. **确认用途与尺寸**：用在哪、什么比例、最终像素、透明/不透明、深色模式是否需要变体。
2. **选模式**：执行 / 混合 / 探索。
3. **写中文 prompt**：三槽位 + 三层架构；方向图另加**共用任务块 + 共用原则转译块 + 方向块 + 不可迁移声明**（见 §11.1）。
4. **跑 5 项自检**：不过不生成。
5. **调用**：
   ```bash
   # 正式素材默认：Sunburst / high / high
   python3 scripts/zcode_image.py --prompt "<中文提示词>" --out assets/images/xxx.webp \
     --profile final --size 1024x1536 --fit cover \
     --output-format webp --compression 82 \
     --meta-out assets/images/xxx.meta.json
   ```
   精品把 `--profile final` 换成 `--profile premium`（xhigh）或 `max`；快速探索用
   `--profile explore`（Flare / medium / medium），低成本验证用 `draft`。需要参考图时加
   `--ref <真实参考图>`，走 `/images/edits`。需要精确像素/格式时不要省略 `--size` 与
   `--output-format`，两者都由本地 Pillow 回读校验。
6. **验收**：尺寸/比例、中文准确性、关键信息在安全区、设计史细节真实、无伪控件/伪 chrome、与选定方向一致；同时核对 `--meta-out` 的 model/profile/complexity/quality 与最终文件格式是否一致。**逐项核对 prompt 里的封闭事实清单**：城市/地名、数字、名称、状态、控件、品牌元素都必须在清单内；出现清单外实体（错城市、报纸报头、真实 OS chrome、假按钮）即不通过，重生成或裁掉，不带着编造事实进原型。
7. **登记**：用 `asset_manifest.py register --meta <meta.json>` 写入 `asset-manifest.json`（模型、参数、尺寸、格式、prompt 指纹、参考图、sha256、消费者）。

**失败不要「再试一次」碰运气**：先读错误，按 §9 失败树处理。

## 6. 批量生成（icon 集 / 角色集 / 卡牌集 / 贴图）

### 6.1 画布与网格

- 画布比例要匹配内容：竖版角色用 2:3，方形 icon 用 1:1；不要用 1:1 画布塞 2:3 卡。
- 均匀网格 **≤4×4**；5×5 末行易压缩 18%。
- 各行主体居中、与边框留足间距，避免抠图切到头部/配件。
- prompt 写：`无网格线/无边框/无定位标记`，但保留清晰单元间距。

### 6.2 批量 prompt

- 中文写，压到 90 字内精准命中；长 prompt 会稀释网格硬约束。
- 明确「每个单元格一个独立主体、统一大小、主体居中、纯色背景」。
- 视角/姿态用功能类别词（`2D 横版游戏 sprite`），不要用美学风格词（会被风格惯性覆盖）。

### 6.3 抠图与预览

随仓库提供三个脚本（从 huashu-gpt-image 迁入并自包含）：

```bash
# 网格切分：bbox 按内容定位（推荐）/ density 按密度扫描
python3 scripts/extract_grid.py grid.png --out out/ --mode bbox

# 拼预览图检查质量
python3 scripts/contact_sheet.py --input out/ --out preview.png --grid 4x4

# 单图纯色幕布抠透明（无 API 透明背景时的方案）
python3 scripts/chroma_key.py in.png out.png [tol_low=62] [tol_high=110] [erode=2]
```

**抠图前提**：主体配色里不含幕布色。生成时 prompt 明确「纯平涂 #RRGGBB 背景，无渐变无阴影，主体留边距」。

**已知问题**：网格线残留 → 改 bbox 模式；子图头部缺失 → 改 bbox；颜色被误清 → 锚点检测只在四角局部区域；尺寸参差 → 3 像素膨胀；行高不均 → 降 4×4。

## 7. 图片处理与转换

| 需求 | 做法 |
|---|---|
| 精确尺寸 | `--size` + `--fit cover|contain|stretch`（Pillow 后处理并回读校验；网关只近似遵守） |
| 裁切焦点 | 记录焦点坐标/比例；不依赖 `cover` 自动居中 |
| 透明 | `--background transparent` + 回读 alpha；网关不支持时纯色幕布 + `chroma_key.py` |
| 压缩 | `--output-format webp|jpeg --compression 0-100`；PNG 不支持压缩参数；不反复有损重压 |
| 格式 | 普通素材优先 WebP；透明用 PNG/WebP；照片用 JPEG/WebP；最终格式回读校验 |
| 深色模式变体 | 单独生成或程序化调色；登记为同一资产变体 |
| 多倍图 | Android `drawable-*dpi`；iOS `@2x/@3x`；从同一母版导出 |

**本机没有 `sips` / `magick` / `convert`**（以现场为准）；后处理走 Pillow。所有转换记录到 `asset-manifest.json` 的 variants。

## 8. 与 App UI 的一致性

- **同一方向的素材共享视觉语言**：色板、光照、材质、线宽、圆角、纹理。
- **参考一致性**：需要角色/物体一致时，先用一张干净 master，再以 master 作 `--ref` 生成其它姿态。
- **不要用生成图冒充真实产品/品牌资产**：真实 logo、产品图走 `references/brand-asset-protocol.md`。
- **概念图不能直接当正式素材**：只能提取视觉语言；正式素材重新生成或在原型中矢量化。
- **图标优先矢量化**：简单图标用 SVG/VectorDrawable，不生成位图。
- **记录裁切**：CSS `object-fit: cover` 与原生 `CENTER_CROP` 的焦点不同，必须逐端记录。

### 8.1 生成物必须真正进入设计与交付

生成成功不等于完成。每张正式素材必须走完：

1. **进入原型**：真实文件被原型引用（单文件 HTML 用 base64 内嵌，多文件用相对路径），不得只留下 prompt 或临时图。
2. **进入素材目录**：放在任务 `assets/` 下，按用途/名称可追溯；不留在 `/tmp` 或下载目录。
3. **登记 manifest**：id、路径、sha256、类型、来源、provenance、变体、消费者、许可、状态（`image-assets.md` §5）。
4. **多端导出**：按目标密度/倍率导出变体；记录裁切焦点与暗色变体。
5. **验收**：在真实屏幕比例与裁切下看一遍；确认无拉伸、无错图、低清、焦点偏移；与选定方向的视觉语言一致。
6. **消费者核对**：删除/替换前查 `consumers`，不留悬空引用。

**证据边界**：文件存在与 sha256 只证明“生成了”，不证明“用对了”；集成与视觉正确必须由真实渲染截图证明。

### 8.2 多页/多方向的跨图一致性

同一 App 的多张概念图或素材不是独立作品；逐张好看但拼不成一个 App 就是失败。每批生成后横向核对：

- **同一任务块**：定位、用户、场景、硬约束、封闭事实清单在所有方向间逐字一致；只允许方向块不同。
- **同一视觉语法**：导航形态、app bar 高度关系、主色与语义色、圆角/线宽/材质语言、字号层级比例跨图一致；不因单页 prompt 漂移。
- **同一内容口径**：同一业务数字、状态、名称在不同页面不矛盾；编造的只留在概念图，不进 brief。
- **同一平台事实**：状态栏、手势条、系统控件只画一次且一致，不混 iOS/Android 语法。
- **与原型对齐**：HTML 原型的多屏必须继承同一套 token 与组件形态；概念图之间的差异若只是提示词抖动，不算设计方向。

### 8.3 命名、尺寸与格式

| 项 | 规则 |
|---|---|
| 命名 | `<用途>-<场景>[-<主题/状态>]`，小写 kebab；变体共用同一 id |
| 尺寸 | 按目标屏幕区域与倍率导出；记录最终像素与裁切 |
| 格式 | 透明/图形用 PNG/WebP；照片用 JPEG/WebP；纹理可 WebP；不用 SVG 假装位图插画 |
| 体积 | 单张首屏位图设预算（按项目/设备），超限先压/裁/换格式 |
| 透明 | 默认先出纯色幕布再抠图；不假定模型稳定输出透明底 |

## 9. 失败模式与 fallback 树

### 9.0 先归因，再改（四类）

反复失败时不要把同一句话写得更重。先判断是哪一类，再选对应改法：

| 归因 | 症状 | 改法 | 不要做 |
|---|---|---|---|
| **模型没执行结构指令** | 图很漂亮，但骨架、栏数、信息顺序和你写的不一样 | 把结构写成可数事实（几栏、首屏锚点、信息顺序），减少形容词；必要时给骨架草图或 `--ref` | 反复加"务必""严格" |
| **共用块自相矛盾** | 同一张图里两个要求打架（高密度 + 大留白；极简 + 信息全） | 删到不冲突；某原则不适用于本页就写"本版不适用" | 为了"更高级"继续叠形容词 |
| **要求本身不可视化** | 抽象原则（"有掌控感""有成长感"）落不成画面 | 转译成可见事实（进度可见、下一步明确、状态可回退） | 把原则词再写一遍 |
| **参考不足** | 模型只能编细节 | 提供真实参考图或产品真实截图（`--ref`）；没有就明说"按文字理解" | 让模型猜品牌/产品长什么样 |

**归因顺序**：先看共用块有没有冲突 → 再看结构是否可数 → 再看要求是否可视化 → 最后才怀疑参考与模型能力。

### 9.1 Prompt 层

| 现象 | 原因 | 一线修复 | 仍失败 |
|---|---|---|---|
| 输出「安全好看」无惊喜 | 风格被中和、画面过满 | 切探索模式，让模型先说判断再画 | 加「请贡献品牌名 + slogan + 命名逻辑」invite 模式 |
| 风格 vs 品类自动妥协（Apple 中药变温润） | 模型内置和谐倾向 | 明确写「保留风格精神不动摇」 | 用 `--ref` 提供风格 DNA |
| 模型不会减法、画面过满 | 缺少减法指令 | 「先列 8 个再砍到 4 个」 | prompt 明确「只保留核心元素」 |
| 气质性风格 transfer 不像 | 只有风格名，没有结构 | 补构图/色板/景深/姿势 | 找代表作单图作 `--ref` |
| 出版品牌名被画成 nameplate | 出版物真名触发 nameplate | 删品牌名，用描述词 | 加「严禁外文品牌名水印」 |
| 中文错字/缺字 | quality 不够、prompt 没提 | 升 high + 显式要求每个汉字准确 | 中文文本放最前，双引号包裹 |
| 设计史细节错（年代/口号/合作品牌） | 模型串台 | 自己核实，不直接引用 | 从 prompt 删掉可疑信息 |
| 多端安全区被裁 | 关键信息在外围 | 收到中央安全区，≤3 个核心信息 | 减少信息条数 |

### 9.2 执行层

| 现象 | 处理 |
|---|---|
| `--health` 失败 / 默认 2.6 模型缺失 | 报告接口或模型限制；不伪造、不静默降级旧模型；不自行改 CPA 配置（属高等级动作） |
| 404 `/v1/images/generations` | 只读确认原因并报告；不改配置、不重启核心；不自动换链路 |
| 401/403/429/400 | 按错误原文改 prompt/参数或等额度；**不无条件重试** |
| `moderation_blocked` | 删除在世艺术家/品牌风格模仿等触发词，改结构性描述；不上诉、不绕过、不换账户 |
| 超时/5xx | 结果不确定；先确认上游是否受理，避免重复消耗；不自行降级 |
| 模型不支持 | 不自动换模型；显式选择现场支持清单内的 2.6 型号，并记录原因 |
| 尺寸不对 | `--size` 只是请求；网关可能近似或改写，最终用 `--fit` 与回读校验 |
| 输出格式被归一（如 WebP→PNG） | 本地 Pillow 转换到 `--output-format`，metadata 记录 `source_format` |
| 响应 quality 与请求不一致 | 记录请求与响应；以实际产物和视觉验收为准，不把响应字段当生效证据 |
| 生成成功但文件损坏 | 魔数/完整性校验失败；重出该张，不拼接 |
| 透明底不稳 / 无 alpha | 脚本失败关闭；改用纯色幕布 + `chroma_key.py` |

**原则**：先一线修复（成本低），再换手段；每次 fallback 记录原因；不循环重发。

## 10. 成本与授权

- 在用户已配置并授权的 Provider/模型/账户范围内，正常生图调用属任务成本，**不需逐次请示**。
- **不新增 Provider、不购买服务/额度、不改变付费方案**；超出授权范围先说明再取得授权。
- **选型即成本**：Flare `explore`/`draft` 用于探索和验证；Sunburst `final` 用于正式素材；`premium`/`max` 只给少数核心资产。不要把所有图一律 max，也不要为省时间默认降级正式素材。
- 一次一张、按实际需要决定数量；不重复生成已有合格素材，不为微小差异反复生图。
- 每次记录实际模型、profile、complexity、quality、耗时与可获得的 usage（`--meta-out`）；无数据标未知，不估算冒充账单。

## 11. 提示词模板

### 11.1 方向图

```text
1) 任务块（多方向时逐字共用）：<产品定位>；<目标用户与场景>；本页核心问题：<一句话>；
   用户最重要的信息与操作：<...>；业务规则与平台硬约束：<...>；
   本页禁止：<编造计数/假定状态/伪控件/未授权机制>
   **封闭事实清单**（只允许这些实体出现；清单外一律不画）：
   城市/地名：<...或「无」>；数字与单位：<...或「无」>；名称/品牌：<...或「无」>；
   状态：<...>；控件：<...>。不出现报纸报头/书刊 masthead、真实 OS 状态栏或
   系统设置页、清单外的 logo/水印/伪按钮。
2) 原则转译块（多方向时逐字共用，每条可检查，不写原则名）：
   有用：<第一眼看到什么、主操作是什么>
   好懂：<信息与操作顺序>
   舒服：<密度、留白、可读性、触控>
   有意义：<适用时的一处真实表达；不适用写「本版不适用」>
3) 载体与比例：App 竖版界面概念图，单屏 / 3 屏并排，比例 2:3
4) 方向块：方向「<名>」：参考 <真实风格/产品/设计师> 的 <可迁移特征>；
   结构骨架：<分栏数>；信息层级 <几级>；密度 <疏/中/密>；
   首屏视觉锚点 <在哪>；导航 <形态>；核心控件 <位置>；生成意图：<为什么服务这类用户>
5) 图内描述性文字用中文；图内文字为示意，不作文案与精确规格依据；
   不出现外文 nameplate、水印、签名。
6) 生成后事实核对：逐项对照上面的封闭事实清单，任何清单外城市/数字/名称/
   报头/伪控件出现即判不通过，不进入方向比较。
```

**共用块逐字一致**：1) 与 2) 在多个方向的图里完全相同，只允许 4) 不同；差异只能来自结构，不来自增删业务功能或数据。**只有一个方向时，1) 与 2) 与方向块合并写，但结构与边界仍要写清。** **转译块不要复述「有用/好懂/舒服/有意义」四个词本身**，要写出页面上的具体结果。

### 11.2 插画 / 背景 / 装饰

```text
<真实锚点> 风格的 App <用途> 插画：<主体/场景一句话>。
构图：<主体位置/占比/视线/留白>；色板：<主色 + 辅色 + 底色>；
光照/材质：<具体>；输出 <尺寸/比例>，<透明/不透明>。
不要文字、不要 logo、不要水印、不要无关装饰元素。
```

### 11.3 图标视觉稿

```text
<风格> 的 App 图标概念：<主体隐喻一句话>。
<圆角方形/圆形> 画布，主体居中，<线宽/材质/光照>；
背景 <纯色/微渐变>；无文字、无阴影溢出、无多余装饰。
```

### 11.4 角色/物体一致性

```text
以参考图中的 <角色/物体> 为准，保持 <身份特征/配色/材质/比例> 不变。
新姿态/场景：<描述>。同一光照与视角，<尺寸>，<背景>。
不要改变角色身份特征，不要新增配饰。
```

## 12. 收尾

**Prompt 的上限等于你脑子里的概念库。** 最值得长期投入的不是 prompt 技巧，是研究真实的设计师、品牌、媒介范式——每多认识一个精准的名字，上限就抬高一点。
