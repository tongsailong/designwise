# 工作流 · 从接到任务到真机收口

> **读这份文档的时机**：准备开工、需要问用户问题、需要写假设或组织任务目录时。
> **权威**：阶段、Gate 与红线以 `SKILL.md` 为准；阶段清单与模板见 `app-visual-workflow.md`。本文只补「怎么问、怎么想、怎么组织现场」。

---

## 1. 开工前的思考顺序

1. **这是不是 App UI？** 不是 → 说明不在范围（`routing-table.md`）。
2. **从哪个阶段进？** 看已有产物成熟度，不看任务大小或仪式。
3. **事实先于假设**：具体产品/技术/版本/规格先查权威来源；查不到问用户。
4. **读现场**：项目规则、现有设计系统、代码、素材、截图、日志。
5. **产品三问**：谁在用 / 要完成什么 / 系统替他承担哪部分复杂性。
6. **建页面-状态地图**：整机/多页面全量；单页按风险取深度。每项要能说出状态与出处。
7. **原生可行性**：平台、系统版本、字体缩放上限、系统栏、密度、触控、导航、权限、性能、素材格式。做不到的不要画进方向。
8. **范围冻结**：本次不做什么。

**顺序不能跳**：跳过 6 → 状态在原型阶段才发现；跳过 7 → 方向图里全是做不到的效果。

## 2. 怎么问用户

### 2.1 只问影响决策的缺口

不设问题数量下限；已知信息不重复问。优先一次列出关键问题让用户批量答；宿主限制时只问阻塞项，其余记为 `ASSUMPTION`。

### 2.2 缺口检查清单

| 类别 | 要确认什么 | 没答案时 |
|---|---|---|
| **设计上下文** | 有没有 design system / UI kit / 代码 / Figma / 截图 / 参考站 | 去项目里找；找不到按可探索约束处理 |
| **品牌资产** | logo、产品图、UI 截图、色板、字体、禁区 | 走 `brand-asset-protocol.md` 取官方资产 |
| **目标用户与场景** | 谁、什么场景、什么任务 | 按合理假设并标注 |
| **业务规则** | 必须保留的页面/流程、数据口径、权限、商业化边界 | **必须问或从代码取证**；不能自行发明 |
| **平台** | iOS / Android / 双端、最低版本 | 按项目现状判断；不确定问 |
| **交付形态** | HTML 原型 + 原生实现？只做原型？只做方向？ | 默认到原生实现；用户明确只做原型则到阶段 4 |
| **成功标准** | 怎么算完成 | 与用户确认或按产品三问推导，写进 brief |

### 2.3 不要问的

- 不要问「你想要几个方向」：**数量是设计判断**，按实质分歧定（`direction-strategy.md`）。
- 不要问「要平铺还是可操作」：App 原型默认可交互。
- 不要问「要不要用 GPT 生图」：方向阶段必须真实生图；不可用则报告暂停。
- 不要用问题替代自己该做的调查（代码里能查到的规则不要问用户）。
- 不要问「要不要加这个功能」：业务取舍归用户，但你没被要求的功能不要提案成默认范围。

## 3. 假设与对齐

- 在 `design-brief.md` 写清 `ASSUMPTION`，说明影响范围与验证方式；不要让假设悄悄进入设计或文案。
- **对齐不是停轮仪式**：阶段 0–2 可以连续推进；需要用户拍板的只有业务规则冲突、范围变化、授权边界、关键业务取舍。
- **早期展示**：HTML 原型可以先给结构 + 标签，让用户尽早看到信息架构；但方向阶段必须给真实概念图，不能只给文字。
- **理解错了早改比晚改便宜**：但不要用「等确认」拖住整个流程。

## 4. 任务目录组织

正文相对路径（`prototype/`、`assets/`、`asset-manifest.json`、`handoff/`…）都相对**任务工作根**。
默认 `design-demos/<task>/`；项目已有设计目录时用项目目录，但内部结构不变。

```
design-demos/<task>/
├── design-brief.md                  # 产品理解、P*/S*/X* 地图与出处、目标映射、约束、假设
├── coverage.json                    # 覆盖与验证单一事实源（schema: designwise-coverage/v1）
├── concept-prompts.md               # 方向卡 + 共用块 + 方向块（逐字一致可校验）
├── concept-index.json               # id / 文件 / sha256 / 模型 / 尺寸 / 时间 / 来源
├── concepts/
│   ├── A.png / B.png / C.png        # 按实际方向数
│   ├── merged.png                   # 可选：融合改变结构时的真实整合图
│   └── prompts/A.md B.md C.md
├── direction-divergence.json        # 多方向差异实测
├── direction-approved.md            # ZCode 设计决策记录；决策形成前不得创建
├── prototype/
│   ├── index.html
│   ├── vendor/                      # 可选：本地库副本
│   └── screenshots/                 # r1-*/r2-* 按轮次，命名对齐 P*/S*
├── prototype-notes.md               # 覆盖矩阵、缩放矩阵、概念偏差、评审与打磨记录
├── assets/
│   ├── images/  icons/  prompts/
├── asset-manifest.json
├── generation-log.md                # 真实出图、处理、检查命令与结果
├── handoff/
│   ├── README.md  structure.md  design-tokens.md  states-interactions.md
│   ├── copy-data.md  assets.md  adaptation-a11y.md
│   └── baselines/
├── native/                          # 原生工程，或记录项目内既有工程路径
└── verification-report.md           # 落地映射、三方对照、四态矩阵、双验收
```

**规则**：

- 不把临时验证素材路径写进 `handoff/`；交付引用 `assets/` 下的最终素材。
- 不把 API key、Cookie、内部链接、真实用户隐私写进任何文件。
- 单文件 HTML 的图片 base64 内嵌；多文件才用相对路径 + 启动说明。
- 素材路径必须是**交付时仍可访问的真实路径**，不能是"先放临时目录、交付前删除"。

## 5. 各阶段的心态

| 阶段 | 心态 |
|---|---|
| 0 理解 | 先调查再问；写清出处；别拿截图当理解 |
| 1 方向 | 先写卡再出图；数量按分歧；差异靠实测 |
| 2 原型 | 还原意图，不复制概念图的错误；覆盖矩阵逐项闭合 |
| 3 评审 | 看真实截图，一轮三处；先结构后工艺；致命清零 |
| 4 交接 | 写规格不写截图；等价契约比"像不像"重要 |
| 5 原生 | 落地设计目标，不是换 token；dp/sp 不等于 px；组件不许偷偷降级 |
| 6 验收 | 工程与设计分开判；四态；三方对照；未验证不算通过 |

## 6. 什么时候停

**需要停**（只停受影响动作，其余继续）：

- 业务规则冲突需用户拍板；
- 范围/目标实质变化；
- 需要新授权（生产数据、部署、付费、对外发布）；
- 生图接口不可用且无法在授权内解决；
- 真机/工具链不可用；
- 关键事实查不到且影响方向判断。

**不需要停**：

- 常规设计自由度内的选择（IA、布局、组件形态、素材处理）；
- 方向数量与取舍；
- 是否融合；
- 原型实现细节与打磨轮次。

**不停不等于不报告**：每个 Gate 的证据要在交付说明里能查到；评审与落地对照的缺口要如实写。

## 7. 异常处理

| 异常 | 处理 |
|---|---|
| 用户赶时间 | 可压缩文档长度与打磨轮次，**不压缩真实证据与致命项判断**；交付时说明哪些步骤被压缩 |
| 用户要求跳过方向探索 | 若已有有效方向记录可复用；没有则说明这会让方向变成单一假设，仍要写方向卡与记录 |
| 生图不可用 | 报告并暂停；可交付完整 prompt 让用户外部出图后交回真实文件 |
| 差异实测判换皮 | 换骨架或换来源重出，不用"看起来不同"绕过 |
| 原生只换了皮 | 回阶段 5 按落地映射重构；构建成功、测试通过都不算收口 |
| 组件被降级替换 | 按缺陷修回等价实现；"平台适配"不成立，除非交接已写明且项目接受 |
| 旧版基线缺失 | 复用既有截图/记录；不降级安装、不清数据、不恢复旧包；缺证如实标注 |
| 项目规则冲突 | 暂停受影响动作，说明条款与影响，其余继续 |
| 真机不可用 | 设计交付照常，原生/真机标 `PARTIAL`/`BLOCKED` |
| 事实不确定 | 先查权威来源；查不到问用户 |
