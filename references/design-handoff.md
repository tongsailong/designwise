# App 原生交付契约 · DesignWise → iOS / Android

> **读这份文档的时机**：设计已在 HTML 原型的真实渲染中稳定，准备交给原生实现（自己或别的工程/agent）时。
> **一句话立场**：**交付的是规格，不是截图。** 实现端不该靠「看截图猜数值」还原设计——间距猜错 4dp、色值差一号、状态漏一半，就是返工。
> **与流程的关系**：`app-visual-workflow.md` 阶段 2–3 产出原型、评审与基准图，本文是**阶段 4（原生交接）**的交付包规格；阶段 5 按本包实现，阶段 6 用本包与基准图验收。HTML 是**视觉基准**，不是 App 源码。
> **V3 新增重点**：四类等价契约（组件等价与禁用替代 / 绘制层级与命中 / 滚动与可达 / 业务规则出处）。缺任何一类，实现端就要靠猜。

---

## 0. 什么时候需要交付包

| 场景 | 要不要 |
|---|---|
| 设计要交给原生工程/别的 agent 实现（iOS / Android） | ✅ 必须 |
| 自己在同一项目里继续实现 | ✅ 建议，至少 tokens 与素材清单要落文件 |
| 只做方向探索 / 给用户看方案 | ❌ 不需要 |
| 只做 HTML 原型演示，不进入原生 | ❌ 不需要完整包，但保留原型与说明 |

**原则**：只要有人（包括未来的自己）要照它实现，就给交付包。完整性 = 实现端不需要猜的程度。

## 1. 交付包结构（`handoff/`，七件套）

```
handoff/
├── README.md               # 入口：产物性质、目标平台、清单勾选、红线提示
├── structure.md            # ① 页面结构、导航、信息层级
├── design-tokens.md        # ② 色彩/字体/间距/圆角/阴影/动效
├── states-interactions.md  # ③ 状态矩阵与交互行为
├── copy-data.md            # ④ 真实文案与数据口径
├── assets.md               # ⑤ 素材清单与引用关系
├── adaptation-a11y.md      # ⑥ 适配、字体缩放、对比度、触控、无障碍
└── baselines/              # ⑦ 关键页面/状态基准图（PNG，真实渲染）
```

`README.md` 必须含：产物性质（设计交付包，非产品代码）、目标平台与最低版本、七件套勾选状态、以及「HTML 原型是基准，不是实现代码」的红线提示。

## 2. 七件套逐项规格

### ① `structure.md` — 页面结构与信息层级

- **页面清单**：名称、职责、入口来源、能去哪
- **导航结构**：Tab / 栈 / 抽屉 / 手势；层级深度；返回行为
- **结构树**：每页区块自顶向下顺序，每块一句话职责
- **信息层级**：每页视觉第一主角、次主角、工具性元素
- **不可变边界**：结构上不许动的东西（如「四 Tab 不可增删」「必须保留周报模块」）
- **需求对应**：每个页面/区块指回 `design-brief.md` 的哪条需求，保证需求不丢

### ② `design-tokens.md` — 设计规范（给值，不给观感）

| 类别 | 必须给 |
|---|---|
| 色彩 | token 名 + HEX/ARGB + 职责（主色/强调/文字分级/背景/描边/状态色）+ 深色模式值 |
| 字体 | 字族（中文/数字/西文）+ 字号 + 字重 + 行高 + 字间距，逐层级；Android sp / iOS pt |
| 间距 | 基础栅格（4/8）+ 页面边距/区块间距/组件内距 token |
| 圆角 | 卡片/按钮/输入/标签/弹层的半径值 |
| 阴影/描边 | 具体参数或平台等价效果（elevation / shadow radius/opacity） |
| 动效 | 时长 + 缓动 + 关键转场参数；加载/点击反馈/页面转场 |

**要求**：实现端不看图也能填出 `colors.xml` / `dimens.xml` / Asset Catalog。色值若来自品牌资产，注明来源。

### ③ `states-interactions.md` — 状态与交互

- **状态矩阵**：每页/每组件：默认 / 加载 / 空 / 错误 / 数据不足，各自长什么样
- **交互行为**：点击/滑动/切换后的结果；哪些真实可交互、哪些只是展示
- **状态机**：Tab 切换、弹层开合、多步流程、任务进度
- **边界状态**：数据为 0 / 首次使用 / 无权限 / 断网 / 弱网
- **输入状态**：键盘弹出、焦点、校验错误、提交中、提交失败

### ④ `copy-data.md` — 真实文案与数据口径

- **文案原文**：用户可见的每一句中文，逐字，标注用在哪
- **数据口径**：每个数字/指标的定义与来源
- **数据不足态**：未达条件时显示什么（「数据积累中」「待解锁」）
- 🔴 **红线**：所有数值/文案 = 产品真实口径；**GPT 概念图里的数字一律不得进此表**。

### ⑤ `assets.md` — 素材清单与引用关系

逐张列（与 `asset-manifest.json` 对应）：

| 列 | 内容 |
|---|---|
| id / 文件名 | 稳定 id 与工程路径 |
| 用途 | 哪页/哪组件/哪状态 |
| 尺寸/变体 | 目标像素、密度桶、透明/不透明、深色变体 |
| 来源 | 真实素材（官方/用户）或生成（模型 + prompt 记录 + `--ref`） |
| 裁切 | 焦点/安全区；CSS cover 与原生 CENTER_CROP 的差异 |
| 引用 | Android `drawable-*` / iOS Asset Catalog / 代码位置 |

**简单图标**不塞位图清单：注明「VectorDrawable / SF Symbols / SVG」并给形状规格。

### ⑥ `adaptation-a11y.md` — 适配与无障碍

- **屏幕适配**：目标尺寸/比例范围、横竖屏、安全区（刘海/手势条/圆角）
- **字体缩放**：`1.0 / 1.3 / 1.6 / 2.0` 各档表现（项目有规定按项目，更严取更严）；不截断、不重叠、不遮挡；超出设计档位的替代形态写明
- **高风险结构清单**：多列布局、label+value 同行、固定高度卡片/弹层、长中文文案、图标+文字同行——逐个给出最大档形态（换行/改单列/改可滚动）
- **对比度**：三档逐对实测表（前景/背景/实测比/档位/判定）；正文 ≥4.5:1、重要图标/图形 ≥3:1；档 ①/② 不合格阻断交付
- **点击区**：Android ≥48dp、iOS ≥44pt
- **无障碍**：content description / accessibility label / 语义角色 / 焦点顺序 / 色盲友好 / 动态字体
- **深色模式**：语义色映射；不是简单反相
- **机械校验**：`python3 scripts/check-contrast.py pairs.json`（退出码 1 = 有阻断项）

### ⑦ `baselines/` — 关键页面/状态基准图

- 每页每个关键状态一张 PNG，来自 HTML 原型的真实渲染
- 命名与 `P*`/`S*` 一一对应；`README.md` 给对照表
- 用途：实现端拿真机截图与基准**并排比对**（对意图负责，不对像素负责）

## 2.5 四类等价契约（缺一不得进入实现）

七件套解决"规格在哪"，这四类契约解决"实现端会不会把它做丢"。全部落到具体文件，不写在 README 的散文里。

### ① 组件等价 + 禁用替代

HTML 里凡不是平台标准控件的（自绘、分段、Canvas、自定义测量、组合控件），逐项写清目标平台用什么实现，以及**哪些廉价替代是禁止的**。

```markdown
## 组件等价表

| HTML 组件 | 视觉/行为要点 | 目标平台等价实现 | 禁止的替代 | 理由 |
|---|---|---|---|---|
| 三段 gauge | 三段独立进度、断点对齐、中心读数 | Canvas 三段 drawArc + 文本层 | `CircularProgressIndicator` / 单个 `ProgressBar` | 单值控件表达不了三段状态，替换即丢信息 |
| 城市卡 pager | 相邻卡露出 24dp、一卡一屏吸附 | `RecyclerView` + `PagerSnapHelper` | 普通 `HorizontalScrollView` | 无吸附会破坏"一站一屏"节奏 |
| 步数滚动数字 | 逐位滚动、固定宽字 | 自定义 View + 定宽数字字体 | 普通 `TextView` 动画 | 换字宽会抖动，读数跳位 |
```

**判定**：任何"用系统默认控件替代自绘控件"的实现都要在阶段 5 的替换 diff 里显式确认等价；未确认即为缺陷，不是"平台适配"。

### ② 绘制层级与命中优先级

Canvas / 自绘 / 叠加层必须写清：

```markdown
## 地图层（P8 环球路线）
- z-order（低→高）：底图 → 路线 → 站点标记 → 当前站高亮 → 城市卡浮层 → 顶部返回
- declutter：低缩放只保留当前站与前后各 1 站；点击/悬停优先扩展示意
- hit-test：当前站 > 相邻站 > 路线 > 底图；装饰元素不接收点击
- 半径/尺寸分级：已完成/当前/锁定三档的标记直径与文字尺寸
```

没有这一段，实现端会按"看起来差不多"决定谁在上面，结果是**地图遮挡**、点不到当前站。

### ③ 滚动与可达

每个弹层、长内容、固定高度结构都要声明容器与退路：

| 区域 | 滚动容器 | 关闭/返回路径 | 最大字号风险 | 处理 |
|---|---|---|---|---|
| S9 城市详情 | 内容区独立滚动，头部固定 | 右上关闭 + 系统返回 + 下滑关闭 | 1.6 下正文挤压标题 | 标题限 2 行、正文可滚 |
| S4 目标选择 | 列表滚动，底部按钮固定 | 取消 + 系统返回 | 2.0 下按钮被键盘遮挡 | 键盘弹出时按钮上移，列表可滚 |

**判定**：内容超出但无滚动容器 = 裁切缺陷；关闭按钮不可达 = 致命。**固定高度 + 大字号**是最常见的组合雷区。

### ④ 业务规则出处

| 展示项 | 规则 | 真实出处 | 备注 |
|---|---|---|---|
| 连续天数 | 按目标判定，不是固定 3000 | `StreakCalculator.kt:41` | 文档写 3000，与代码冲突 → 待决 |
| 下一站是否可走 | 由 `JourneyNextStop` 返回锁定状态 | `JourneyViewModel.kt:118` | 不得假设"下一站永远可走" |
| 激励视频额度 | 每次 +1，上限 3/日 | `AdQuota.kt:57` | 广告不可用时需有降级展示 |

**规则**：每个展示值/规则引用真实 UI 代码路径；文档规则与代码冲突时**列为待决**，不由实现端自行选一个；查不到标 `ASSUMPTION` 并写影响。

## 3. 平台映射

### 3.1 Android

| 设计侧 | 映射 |
|---|---|
| 色值 | `res/values/colors.xml`；深色 `values-night/colors.xml`；Compose `Color` |
| 字号 | `sp`；`dimens.xml` 或 Compose `MaterialTheme.typography` |
| 间距/圆角 | `dp`；`dimens.xml` |
| 图标 | VectorDrawable（优先）/ WebP |
| 图片 | `drawable-*dpi` / `mipmap-*`；`CENTER_CROP` / `FIT_CENTER` |
| 触控 | ≥48dp |
| 系统 UI | status/nav bar、WindowInsets、edge-to-edge |
| 字体缩放 | `sp` + 布局自适应；不锁死高度 |
| 导航 | 系统返回、预测性返回、Tab/抽屉按 Material 惯例 |

### 3.2 iOS

| 设计侧 | 映射 |
|---|---|
| 色值 | Asset Catalog（Any/Dark）；SwiftUI `Color` |
| 字号 | `pt`；Dynamic Type text style |
| 间距/圆角 | `pt`；布局常量 |
| 图标 | SF Symbols（优先）/ PDF vector |
| 图片 | Asset Catalog（@1x/@2x/@3x）；`scaleAspectFill` |
| 触控 | ≥44pt |
| 系统 UI | safe area、home indicator、状态栏样式 |
| 字体缩放 | Dynamic Type；大字号下布局重排 |
| 导航 | NavigationStack、TabView、手势返回 |

### 3.3 关键约定

- **保留平台原生实现方式**：交付包给规格与基准，具体技术栈由实现端决定。
- **CSS px ≠ dp/pt**：按目标密度与设计基准换算，在真机核对。
- **HTML 原型 ≠ 原生代码**：不得把原型 HTML 嵌入 App；WebView 只用于明确的产品需求。
- **素材裁切**：CSS `object-fit: cover` 与原生 `CENTER_CROP/scaleAspectFill` 的焦点可能不同，逐端记录。
- **token 必须语义化**：颜色按用途命名（`ui_color_surface` / `color_on_primary` / `color_text_secondary` / `color_danger`），**不得用 `white` / `black` 当语义色**——深色模式下会直接反色成错误结果。字号给 sp/pt 与层级名，间距给 4/8 网格，动效给时长与缓动。
- **旧资源清理**：列出本次被替换的旧资源（旧插画、旧 pager、旧字符串、旧 token），并给"已移除 / 仍被引用"结论，防止旧视觉残留仍在运行。

### 3.4 设计目标 vs 实现自由

- **HTML 与交付包是设计目标，不是配色参考**：核心信息层级、布局关系、视觉语言、交互意图要落地；实现端可为平台适配改控件形态、insets、单位与滚动实现。
- **允许结构重写**：旧实现与新设计冲突时，页面结构、组件层级、信息架构与交互方式都可以改；**最小 diff 不是验收标准**。
- **保留旧结构要有理由**：用户任务、可读性、平台惯例、成熟体验可以构成保留理由；「代码可复用」「测试锁住了」「改动更少」不行。
- **设计一致性 ≠ 像素一致**：对设计意图负责，不对像素负责；但「只换了 token」不能算实现。

### 3.5 允许偏差 vs 缺陷

| 类别 | 例子 | 判定 |
|---|---|---|
| **允许偏差** | 系统栏高度、insets、原生控件形态（开关/日期选择器）、字体渲染差异、平台动效曲线、不同截图压缩 | 记录即可，不算缺陷 |
| **缺陷** | 信息层级错、布局意图丢、关键状态缺失、业务数据错误、组件被降级替换、弹层不可达、最大字号裁切 | 必须修，不得写成"平台适配" |

**判定顺序**：先问"用户可感知的意图有没有变"，再问"是不是平台必然差异"。答不出平台差异的具体理由，就不是允许偏差。

## 5. 红线（违反即返工）

| 红线 | 为什么 |
|---|---|
| 交付包只有截图，没有原理化规格 | 开发只能猜，还原度不可控 |
| 把概念图当基准图交付 | 概念图是探索态，含幻觉文字与不可实现效果 |
| 把原型 HTML 当 App 最终代码 | 原型非产品源码，平台/性能/维护都不成立 |
| 文案/数据表混入 GPT 幻觉值 | 伪造产品数据 |
| 素材清单里的图工程引用不了 | 交付不等于可用 |
| CSS px 直接当 dp/pt | 整体尺寸与触控错误 |
| 缺深色模式/字体缩放/空态规格 | 真机一放就露馅 |
| 自绘控件没有等价实现与禁用替代 | 实现端会用系统默认控件"顺手"替换，丢信息（D2 类） |
| 绘制层级/命中顺序没写 | 遮挡、点不到、装饰吃掉点击（D1 类） |
| 弹层没声明滚动容器与关闭路径 | 大字号下裁切、关不掉（D4 类） |
| 规则只写"按产品逻辑" | 实现端自己发明，或抄文档忽略代码（D8 类） |

## 6. 真实实现反馈闭环

> **边界**：DesignWise 提供设计判断与验收规范，不代替实现端操作开发细节（编译、跑 App、抓日志是实现端的活）。

```
实现端真实运行（真机）
  → ① 获取真实截图（与 baselines 同尺寸或同比例）
  → ② 与基准逐页并排比对（§6.1 六项）
  → ③ 检查真实业务数据（数值 = copy-data 真实值）
  → ④ 检查可读性与无障碍（对比度档 ①/②、触控、字体缩放）
  → ⑤ 发现偏差 → 定向修复（只改被点名项）
  → ⑥ 重新运行验证（复验范围按缺陷影响面）
```

### 6.1 比对六项

| # | 检查项 | 关注 | 判据来源 |
|---|---|---|---|
| 1 | 布局 | 区块位置/比例；首屏核心行为仍在首要位置 | `baselines/` |
| 2 | 色彩 | 主色/底色/气质；是否落在 tokens | `design-tokens.md` |
| 3 | 字体 | 层级是否被压平；字号/行高达标 | `design-tokens.md` |
| 4 | 素材 | 错位/拉伸/用错图/低清；裁切焦点 | `assets.md` + manifest |
| 5 | 关键状态 | 空/加载/错误/数据不足都实现 | `states-interactions.md` |
| 6 | 真实数据 + 可读性 | 数值真实；对比度/触控/字体缩放大达标 | `copy-data.md` + `adaptation-a11y.md` |

**判定原则**：不要求像素级一致；对已落档的设计意图（`direction-approved.md` + `handoff/`）负责。

### 6.2 三方真实对照（旧版 App ↔ HTML 目标原型 ↔ 新版真机 App）

六项比对只说明「像不像基准」；三方对照回答「设计有没有真的落地、有没有退步」。在 `verification-report.md` 里维护一张表，阶段 5 建立、阶段 6 完成：

| 页面/状态或公共结构 | 原有问题或保留依据 | HTML 目标意图 | 原生实现/保留/平台适配 | 旧/HTML/新证据引用 | 结果、偏差与修复 |
|---|---|---|---|---|---|

- **全范围可追溯，视觉对照按风险与代表性组织**：核心任务、结构变化、独有页面/状态、已知问题必须直接对照；重复结构可分组共用证据，但要列明覆盖范围并检查例外。
- **不能只看首页**就推断所有次级页已按新语言实现；次级页缩水是换皮最常见的藏身处。
- 三方证据要能识别版本与场景；截图不能证明交互与业务逻辑时，补真实操作记录。
- 旧版基线缺失先复用已有截图/记录；**不得为补基线擅自降级安装、清数据或恢复旧包**；仍缺证就如实报缺口。
- **保留旧结构是合法结果**，但理由必须对应用户任务、可读性、平台惯例或成熟体验，并写进表里。

### 6.3 修在哪一侧

| 问题 | 在哪修 | 为什么 |
|---|---|---|
| 普通页面问题（这页间距、这个组件状态） | 项目内修 | 页面级问题，不是 skill 的锅 |
| 通用设计规则缺陷（同类问题多项目复现、规则本身错/缺） | 才改 skill 源码基线 | 规则缺陷要回流，否则每个项目重复踩 |

**不要为单个页面的实现问题改 skill。**

### 6.4 复验范围

定向修复 → 按缺陷影响面定复验范围，不重跑整个设计流程。风格/措辞偏好不算实质问题，不改。复验通过 = 该项闭环；仍不合格 = 记录并继续，不无限循环生图/改稿。

## 7. 交付后经验回流

交付完判断：这次发现值不值得影响下一个项目？不值得就写进交付说明；**记录不是义务，回流才有义务**。

| 证据类型 | 长什么样 | 去哪 |
|---|---|---|
| **preference（用户偏好）** | 「这个配色太吵」「按钮再大一点」 | 本机 memory，只对这位用户/项目有效 |
| **observed（单项目观察）** | 只在一个项目看到、未复现 | 留在该项目设计记录 |
| **verified（已复现/已测量）** | ≥2 项目出现，或有脚本/实测证据 | 工程事实 → 知识库候选；可测的 → 改脚本 + 加测试 |
| **superseded（被取代）** | 旧做法被淘汰 | 原记录标注被谁取代，不默默删除 |

**边界**：经验不扩大授权；单个用户口味不进分发层；不带秘密与个人数据。**不为回流新建第三个记录系统。**
