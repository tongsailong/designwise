## 0. 总览与追溯


`design-brief.md` → `coverage.json` → `direction-approved.md` → `prototype-notes.md` → `handoff/` → `verification-report.md`
之间互相引用。**不另建追溯报告，不重新编号。**

| 阶段 | 最小产物 | Gate 一句话 |
|---|---|---|
| 0 | `design-brief.md` + `coverage.json`(初版) | 理解有出处、范围已闭合、目标可判定 |

| 6 | `verification-report.md` + `coverage.json` 终版 | 四态矩阵有本轮证据、双验收分开 |

## 1. 阶段 0 · 产品理解与设计目标（G0）

### 1.1 执行清单

1. **读现场**：项目规则、代码、现有设计系统与 token、真实素材、既有截图/日志。设计从真实上下文长出来，不从风格库长出来。
2. **取证**：每个要展示的数值与规则，找到 `file:line`。只有文档/注释时，同时记录「文档规则」与「UI 实际路径」，冲突列为待决。
3. **建页面-状态地图**（方法见 `state-map.md`）：`P*`/`S*`/`X*` 全量覆盖，逐项 12 字段。
4. **产品三问**：谁在用、此刻要完成什么、系统替他承担了什么复杂性。
5. **原生可行性前置**：平台/最低版本/字体缩放上限/系统栏/键盘/dp-sp/触控/导航惯例/权限/深色/性能与素材格式。**做不到的不要画进方向。**
6. **目标映射**：每个目标回指 `P*`/`S*`/`X*` 里已识别的问题，或有依据的保留项。
7. **范围冻结**：写明本次不做什么，防止后续"顺手加页面"。
8. **初始化 `coverage.json`**（整机/多页面必需，schema 见 `state-map.md` §7）：此时可只有 id 与 `prototype/native` 初值。

### 1.3 G0 通过条件（逐条核对）

- [ ] 范围内每个 `P*`/`S*`/`X*` 都有：用户目标、入口出口、主要功能、关键信息与优先级、状态集合、平台约束、当前问题、保留依据、重构范围。
- [ ] 每个展示值与业务规则的出处可点开核对（`file:line` 或数据源）；无法取得的已标 `ASSUMPTION` 并说明影响。
- [ ] 「文档规则 ≠ UI 路径」的项已列入待决，**没有被静默选掉**。
- [ ] 目标可判定且回指具体页面/状态问题。
- [ ] 平台可行性已检查，没有已被否定的设计进入方向。
- [ ] 范围外已冻结。
- [ ] `coverage.json` 的 id 集合与地图一致。

**不通过的高频原因**：只写页面清单没有状态；规则抄文档；「保留依据」写成「保持原样」；目标写成「提升体验」。

## 2. 阶段 1 · 概念方向（G1）

方法细节在 `direction-strategy.md`。这里只给执行顺序与记录格式。

### 2.1 执行顺序

1. **数方向**：按实质分歧定 1 / 2 / 3（或先候选后融合）。写清依据。
2. **写方向卡**（六栏）。写不出"差异点"或"form 来自产品的哪里"的方向不出图。
3. **写 prompt**：任务块 + 原则转译块逐字相同，方向块不同。带真实产品资料，不只风格词。
4. **真实生成**：`python3 scripts/zcode_image.py --health` → 逐张串行 → 同比例同尺寸同模型。App 默认竖版 `1024x1536`。
5. **逐张自检**：可解码、尺寸正确、结构差异可辨、共用块逐字一致、无编造数据。
6. **差异实测**（多方向）：`scripts/direction_divergence.py --strict`。
7. **设计决策**：采用 / 融合 / 全部拒绝，写入 `direction-approved.md`。
8. **可选独立复核**：高风险或用户要求第二意见时派只读 Reviewer。

### 2.2 `concept-prompts.md` 模板

```markdown
# 概念方向 prompt

## 共用块（逐字相同，校验 sha256：<hash>）
### 任务块
<产品定位 / 用户与场景 / 本页核心问题 / 最重要信息与操作 / 业务规则与数据口径 / 平台硬约束 / 禁止的编造数据与伪控件>

### 原则转译块
<有用→… / 好懂→… / 舒服→… / 有意义→…，转成 4–6 条可检查要求>

## 方向 A · <名称>（来源：A 现有体系 / B 同品类参照 / C 产品结构隐喻）
- 方向卡：逻辑与来源 / 借用的是什么 / 主角信息与素材 / 结构骨架 / 差异点 / form 来自产品的哪里
- 方向块：
<与其它方向的结构差异 + 视觉语言>
- 载体与边界：
<比例尺寸 / 图内文字为示意 / 语言>

## 方向 B · ...
```

### 2.3 `concept-index.json` 模板

```json
{
  "task": "<task>",
  "shared_block_sha256": "<hash>",
  "directions": [
    {"id": "A", "name": "…", "file": "concepts/A.png", "sha256": "…",
     "model": "gpt-image-2.5", "requested_size": "1024x1536", "actual_size": "1024x1536",
     "generated_at": "…", "source": "A|B|C", "structure": "…"}
  ]
}
```

### 2.4 差异实测与判断

```bash
python3 scripts/direction_divergence.py --image concepts/A.png --image concepts/B.png \
  [--image concepts/C.png] --out direction-divergence.json --strict
```

- 判 `same-skeleton` / `reskin` → 换骨架或换来源重出，不是换颜色。
- 判 `distinct` 只是"不像"，**不等于合格**；合格性仍按六条逐项判断。
- 脚本只给事实，决策理由必须由 ZCode 结合方向卡写出。

### 2.5 `direction-approved.md` 模板

```markdown
# 设计方向决策

## 状态
- 状态：实施基线 | 实验推荐
- 任务 / 日期 / 决策人：ZCode 原生 Agent
- 与 P*/S* 的对应：

## 方向数与依据
- 数量：1 / 2 / 3
- 依据（实质分歧是什么 / 为什么不需要更多）：

## 候选
| id | 文件 | sha256 | 模型·尺寸 | 来源 | 结构骨架一句话 |
|---|---|---|---|---|---|

## 差异实测
- 文件：direction-divergence.json
- 关键指标：A-B palette=… skeleton=…；A-C …；B-C …
- 判定：distinct / same-skeleton / reskin

## 逐方向合格性
| id | 核心需求 | 信息与操作清晰 | 严重可用性问题 | 违反产品规则 | 编造数据/诱导 | 原生可实现 |
|---|---|---|---|---|---|---|

## 决策
- 出口：采用 | 融合 | 全部拒绝
- 采用：<方向>；进入原型前必须修正：…
- 融合：保留… / 舍弃… / 统一后的层级与交互：… / 整合图指纹：…
- 全部拒绝：可执行修正项 / 只重出哪些方向 / 用户是否参与

## 机会成本与风险

## 用户意见
- 否决/确认原话（如有）：
- 可选独立复核：reviewer / 范围 / findings / 未采纳意见与反证
```

### 2.6 G1 通过条件

- [ ] 方向数有依据，不是默认三个。
- [ ] 每张图是真实文件（可解码、sha256 记录、尺寸一致）。
- [ ] 共用块逐字一致（有 hash）。
- [ ] 多方向有实测结果，且判定与最终决策不矛盾。
- [ ] 每个方向都写了合格性，不是只夸采用的那个。
- [ ] 三出口之一明确；融合写了统一逻辑；全部拒绝有下一步。
- [ ] `direction-approved.md` 状态字段唯一，不并列两个基线。

## 3. 阶段 2 · HTML 原型与覆盖（G2）

### 3.1 执行清单

1. 只做已选定方向；不做未采用方向的 HTML。
2. 默认单页 inline React；iOS 用 `assets/ios_frame.jsx`，Android 用 `assets/android_frame.jsx`；**不手写设备外框**。
3. 真实交互：tab 切换、按钮/卡片/开关、弹层开合、返回可达、关键流程走通。
4. `P*`/`S*`/`X*` 逐项有去向：`rendered` / `deferred-native`(+理由+`native_verify`) / `not-applicable`(+理由)。
5. 缩放矩阵：`1.0/1.3/1.6/2.0`；多列、label+value 同行、固定高度结构**必须在最大档渲染**。
6. 真实素材或阶段 3 生成，不用灰块/色块/手画 SVG 顶替。
7. 概念图的伪控件、编造数据、不可实现效果按真实产品修正，并记录修正点。
8. 机械验证：`check-ui.mjs`、`check-contrast.py`、Playwright 点击且 `pageerror=0`。
9. 按目标视口截图作基准图，命名与 `P*`/`S*` 对齐。

### 3.2 覆盖矩阵模板（写入 `prototype-notes.md`）

| id | 类型 | 标题 | 去向 | 屏名/路由 | 已渲染档位 | 缺口与下一步 |
|---|---|---|---|---|---|---|
| P1 | page | 今日 | rendered | `?screen=today` | 1.0 / 1.6 | — |
| S4 | overlay | 目标选择 | rendered | `?screen=today&overlay=goal` | 1.0 / 1.6 / 2.0 | — |
| X6 | state | 激励视频不可用 | deferred-native | — | — | HTML 无法模拟广告回调；原生用假配额驱动，`native_verify: true` |
| X9 | state | 儿童模式 | not-applicable | — | — | 产品无此能力 |

同步到 `coverage.json`，两者 id 集合必须一致。

### 3.4 G2 通过条件

- [ ] `file://` 可直接打开；控制台 0 error；Playwright 三项点击测试通过。
- [ ] 覆盖矩阵每项有去向，**没有静默缺失**；`deferred-native` 理由成立。
- [ ] 每类页面有 1.0 与至少一个风险档；多列/同行/固定高度结构有最大档渲染。
- [ ] 弹层能开能关，关闭路径在最大档可达。
- [ ] 对比度、触控、字号达标（阈值见 `content-guidelines.md` / `check-ui.mjs`）。
- [ ] 无假控件、无编造数据、无灰块顶替真实素材。
- [ ] `coverage.json` 与原型实际渲染一致。

**不通过的高频原因**：只渲染正常态；只在 1.0 看；弹层只截弹出瞬间；覆盖矩阵写在笔记里但 coverage.json 没更新。

## 4. 阶段 3 · 设计评审与完善（G3）

### 4.1 执行清单

1. 用**当前版本真实截图**（含弹层、空/错/大字体）评审，逐屏打开原图。
2. 按 `critique-guide.md` 六维 + App 三项附加检查逐条给结论。
3. 每条缺陷：位置（`P*`/`S*` + 屏名 + 元素）、现象、判据、严重度、改法。
4. 严重度：致命 / 重要 / 打磨。**致命清零**才可交接。
5. 打磨环：一轮三处，结构先于工艺，改后重出受影响屏截图（见 `polish-loop.md`）。
6. 素材按需：复用优先 → 需要才生成 → 登记 `asset-manifest.json`。
7. 可选独立复核：只读 Reviewer 查截图与记录，findings 写入笔记。

### 4.2 评审记录模板

```markdown
## 设计评审 · 第 N 轮（日期）
- 评审范围：P1 P3 P6 S4 @1.0/1.6/2.0（截图 rN-*）
- 结论概览：致命 x / 重要 y / 打磨 z

| # | 位置 | 现象 | 判据 | 严重度 | 改法 | 状态 |
|---|---|---|---|---|---|---|
| 1 | P6 @1.6 | 三列摘要第三列换行后被裁 | 状态完整/大字体 | 致命 | 改 2 列 + 关键值单行 | 已修（r2 图） |
| 2 | S4 @2.0 | 确认按钮被键盘遮挡 | 交互真实性 | 致命 | 按钮固定 + 列表独立滚动 | 已修 |
| 3 | P3 | 主数字与按钮同色重 | 视觉层级 | 重要 | 数字升字重 / 按钮降饱和 | 已修 |
| 4 | P8 | 缩略图 1.0 偏小 | 细节执行 | 打磨 | 原生用真实地图 | 排期 |

## 复验
- 受影响项：1、2、3；复验截图：r2-p6-16.png / r2-s4-20.png / r2-p3.png
- 未复验项与原因：
```

### 4.3 G3 通过条件

- [ ] 评审基于当前版本真实截图，截图路径可核对。
- [ ] 六维 + 三项附加检查都覆盖，没有只写总评。
- [ ] 致命项为 0；重要项已修或写明不修依据。
- [ ] 每项修复有前后证据；改善不靠分数趋势。
- [ ] 素材有来源/指纹/消费者；`temp` 未进交付。
- [ ] 打磨轮次有记录；≥5 轮仍在改结构的情况已按回退处理。

## 5. 阶段 4 · 原生交接（G4）

### 5.1 七件套 + baselines

```
handoff/
├── README.md               # 产物性质、技术栈、清单勾选、使用顺序
├── structure.md            # 页面/导航/状态入口/信息层级（按 P*/S*）
├── design-tokens.md        # 语义色/字号 sp/间距/圆角/阴影/动效
├── states-interactions.md  # 状态矩阵与交互行为（按 S*/X*）
├── copy-data.md            # 真实文案与数据口径（附出处）
├── assets.md               # 素材清单与引用关系
├── adaptation-a11y.md      # 字体缩放/深色/系统栏/触控/对比度
└── baselines/              # 关键页面与状态真实渲染 PNG，命名对齐 P*/S*
```

完整逐项规格见 `design-handoff.md`。

### 5.2 四类等价契约（本阶段的核心，缺一不得进入实现）

**① 组件等价 + 禁用替代**

| HTML 组件 | 视觉/行为要点 | 目标平台等价实现 | 禁止的廉价替代 | 理由 |
|---|---|---|---|---|
| 分段 gauge（三段环路） | 三段独立进度、断点对齐 | Canvas `drawArc` ×3 + 文本层 | `CircularProgressIndicator` | 单值控件无法表达三段状态，用它会丢失信息 |
| 城市卡横向 pager | 相邻卡露出 24dp、吸附 | `RecyclerView` + `PagerSnapHelper` | 普通 `HorizontalScrollView` | 无吸附会破坏"一站一屏"节奏 |

**② 绘制层级与命中优先级**

```markdown
### 地图层（P8）
- z-order：底图 → 路线 → 站点标记 → 当前站高亮 → 城市卡浮层 → 顶部返回
- declutter：低 zoom 只保留当前站与前后各 1 站；悬停/点击优先扩展示意
- hit-test：当前站标记 > 相邻站标记 > 路线 > 底图；装饰元素不接收点击
```

**③ 滚动与可达**

| 区域 | 容器 | 最大字号风险 | 关闭/返回路径 |
|---|---|---|---|
