# 素材先行 · 选对主角素材，再谈生成还是取图

> **读这份文档的时机**：判断「这个设计该用什么承载视觉」、决定某张图是取真图 / 生成 / 程序化画、
> 或想知道本机有哪些素材能力可用时。
>
> **一句话立场**：**先决定主角素材是什么，再决定怎么把它做出来。**
> 反过来的顺序（先看手上有什么工具，再让设计迁就工具）是素材型设计最常见的失败起点。
>
> **不重复的规则**：「图片是否内容必需」的强制判断在 `SKILL.md` Phase 3.5（CHECKPOINT）与
> `references/gpt-visual-workflow.md` §3.6.3 / §3.6.4；本文只补**选择**与**能力分档**两件事。

---

## §1 先选主角素材（hero material）

一个设计通常只能有一个视觉主角。先定它是哪一类：

| 内容特征 | 主角素材 | 该用 | 反例（常见走偏） |
|---|---|---|---|
| 真实物体 / 人物 / 地点 / 动植物 / 产品 | **真实摄影**（公共领域或免版权） | 主体清晰、可裁切、许可可查；一张对的照片胜过十张氛围图 | 用 stock「微笑握手」图凑数；用 AI 生成的假产品图冒充真机 |
| 抽象概念 / 情绪 / 叙事开场 | **原创插画 / 场景图 / 氛围图** | GPT 生成即最优载体（这类没有「真图」可言） | 硬找一张「大概相关」的 stock 图来替代 |
| 数值 / 趋势 / 对比 / 结构 | **数据可视化** | 图表本身就是主角，用真实数据与明确刻度 | 用装饰性 3D 球体代替数据；坐标轴省略却声称是图表 |
| 材质感 / 光泽 / 纹理 / 氛围 | **程序化材质**（CSS/SVG/Canvas 渐变、噪点、模糊、光效） | 可调、可响应式、零版权风险 | 用一张大位图铺满当背景，导致体积暴涨且不可调 |
| 一句话 / 名字 / 数字要成为画面 | **字即图**（排版本身当主视觉） | 字号跨度、字重对比、留白都服务于那一句 | 给大字配一堆无关装饰图标，把主次拉平 |
| 实体包装 / 印刷品 / 卡片 | **实物仿制**（CSS 3D、纸感、阴影） | 尺寸与材质线索真实（纸边、压痕、厚度） | 拿一张「mockup 模板」截图当成品 |
| 使用情境本身（谁在用、怎么用） | **场景 / 人物** | 真实场景或明确标注为演示的合成场景 | 用明显摆拍的商务图讲一个工程师深夜调试的故事 |

**判断顺序**：内容 → 主角素材 → 载体（真图 / 生成 / 程序化）→ 具体实现。
主角素材定不下来，通常说明**产品要传达什么还没想清**，这时应该回到
`references/product-value.md` 的四层判断，而不是先去找图。

## §2 内容必需 vs 装饰（判定只有一条，别自创）

沿用 `SKILL.md` Phase 3.5 的**真图诚实性测试**：

> **「去掉这张图，信息是否有损？」** 有损 → 内容必需，必须取真图；无损 → 装饰，可以不配、也可以程序化画。

- 内容必需的图**绝不**用 CSS 色块 / SVG 几何 / stock 氛围图糊弄（鹦鹉网站没有鹦鹉图 = 失败）。
- 装饰图**默认不调生图模型**——「default 无生图」只约束装饰，不等于内容图也不许有图。
- 拿不准时**按内容必需处理**。

> 取图的可执行落点：Phase 3.5 的来源表 + `scripts/fetch_images.py`（公共领域/免版权检索）
> + `references/brand-asset-protocol.md`（品牌与产品官方资产）；生图用 `scripts/zcode_image.py`
> （`--ref` 走参考图编辑）。**交付为单文件 HTML 时图片必须 base64 内嵌**，否则挪目录即裂图。

## §3 能力分档与探测（按需查，不预检查没在用的工具）

| 档 | 能力 | 探测命令（零成本，只读） | 不可用时怎么办 |
|---|---|---|---|
| **T0** | 纯 CSS / SVG / Canvas 程序化材质与插图 | 无需探测（浏览器原生） | —— |
| **T1** | 本地图片处理与尺寸/裁切 | `python3 -c "import PIL, sys; print(PIL.__version__)"` | 跳过本地裁切适配，直接用原始尺寸并说明 |
| **T1** | 页面渲染截图 / UI 机械采集 | `node --version`（需 ≥22）+ `command -v google-chrome chromium` | 无法截图 → 用浏览器手动截图后 `ref_board.py --image` 或人工看 |
| **T1** | 视频编码（动效交付） | `ffmpeg -version \| head -1` | 只交 HTML 动效，说明未出视频 |
| **T2** | GPT 生图 / 图生图 / 视觉评审 | `python3 scripts/zcode_image.py --health`（只探测接口，不出图、不花额度） | 明确报告限制；可给完整英文 prompt 让用户在 ChatGPT 出图后交回（见 `gpt-visual-workflow.md` §2.2.1） |
| **T2** | 外部视觉评审 | `python3 scripts/zcode_vision.py --health` + 用户在**本轮授权** `--confirm-gpt-review` | 默认走原生自检即可，不影响交付 |

**规则**：

1. **按当前任务真正要用到的能力探测一次**，不要把上表全跑一遍当仪式；
2. **探测不到不阻断**——降级并说明，只有「内容必需的素材且没有替代通路」才需要向用户报告限制；
3. 探测结果**不缓存为永久结论**：换机器、换轮次、模型清单变化都要重新看（`zcode_image.py --health` 的可用型号以当次返回为准）；
4. **不得声称调用了不存在的通路**（无通路却说「已生成」是明确反模式），也不得用占位图冒充已还原视觉。

## §4 素材三态：参考 / 概念 / 正式

三态的定义与职责**只有一处权威**：`references/gpt-visual-workflow.md` §3.6.4。此处仅提醒：

- **参考图**是判断输入（可作 `--ref`），不是产出；
- **概念图**只用于比较与定方向，不能当 UI 或正式素材交付；
- **正式素材**才进产品，且真图/授权素材优先，生成物需标注。

## §5 失败模式速查

| 症状 | 根因 | 修正 |
|---|---|---|
| 页面「图很多」，但说不出主角是什么 | 没做 §1 选择 | 先定主角素材，删掉其余装饰图 |
| 内容必需的图用色块顶着 | 把「default 无生图」误解成「不许有图」 | 回到 §2 诚实性测试，取真图 |
| 用 AI 图冒充真实产品/品牌资产 | 跳过 `brand-asset-protocol.md` | 取官方图；实在取不到才用生成物并标注 |
| 大图铺满导致单文件巨大 | 用位图做本可以做材质的部分 | 换成 CSS/SVG 渐变、噪点、光效 |
| 图片挪目录就裂 | 相对路径引图 | 单文件交付改为 base64 内嵌（`check-ui.mjs` 的 `images.anyRelativeRef` 会黄灯提示） |
| 为了用上某个工具而改设计 | 顺序反了 | 先定主角素材与目标，再挑工具 |
