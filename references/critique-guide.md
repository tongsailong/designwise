# 设计评审深度指南

> Phase 7 的详细参考。提供评分标准、场景侧重点、常见问题清单，以及三项**附加检查**（用户价值与易用性 / Spec 一致性核验 / 视觉还原检查）与一项**生图前的检查**（Prompt 级创意评审）。

---

## 评分标准详解

### 0. 概念/立意（Concept）· 权重最高

先问「这个设计有没有一个idea」，再看做得好不好。为什么放第0位：执行是放大器，放大一个空洞的概念只会更空洞。

| 分数 | 标准 |
|------|------|
| 9-10 | 有一个从用户内容里长出来的独有idea，视觉母题不可替换 |
| 7-8 | 有明确立意，母题与内容相关但换个近似主题也勉强能用 |
| 5-6 | 只有风格没有概念：好看，但没说任何东西 |
| 3-4 | 通用模板套皮，概念层为零 |
| 1-2 | 连风格都没选对，纯装饰堆砌 |

**核心问题清单**：
- 这个设计说了什么？能用一句话讲出它的idea吗？讲不出来就没有
- 盖住所有文字和logo，还认得出主题吗？认不出说明视觉没承担表达（文字即母题的排版设计除外，改问：这套文字处理换个主题还成立吗）
- 换个客户名/产品名还成立吗？**成立=模板，本维度直接≤5分**
- form有没有来自内容的独有视觉母题？（呼应SKILL.md的form推导：形式该从内容推出来，不是从风格库里抽）

**一票否决规则**：概念≤5分时，总评封顶6.0（良好档下限）。后面5个维度全是execution，execution再精致也拉不回一个没有idea的设计——那只是把模板打磨得更亮。

### 1. 哲学一致性（Philosophy Alignment）

| 分数 | 标准 |
|------|------|
| 9-10 | 设计完美体现了选定哲学的核心精神，每个细节都有哲学依据 |
| 7-8 | 整体方向正确，核心特征到位，个别细节偏离 |
| 5-6 | 能看出意图，但执行时混入了其他风格元素，不够纯粹 |
| 3-4 | 仅在表面模仿，未理解哲学内核 |
| 1-2 | 与选定哲学基本无关 |

**评审要点**：
- 是否使用了该设计师/机构的标志性手法？
- 色彩、字体、布局是否符合该哲学体系？
- 有没有「自相矛盾」的元素？（如选了Kenya Hara却塞满内容）

### 2. 视觉层级（Visual Hierarchy）

| 分数 | 标准 |
|------|------|
| 9-10 | 用户视线自然沿设计者意图流动，信息获取零摩擦 |
| 7-8 | 主次关系清晰，偶有1-2处层级模糊 |
| 5-6 | 能分出标题和正文，但中间层级混乱 |
| 3-4 | 信息平铺，没有明确的视觉入口 |
| 1-2 | 混乱，用户不知道先看哪里 |

**评审要点**：
- 标题与正文的字号对比是否足够？（至少2.5倍）
- 颜色/粗细/大小是否建立了3-4个清晰层级？
- 留白是否在引导视线？
- 「眯眼测试」：眯起眼看，层级是否仍然清晰？

### 3. 细节执行（Craft Quality）

| 分数 | 标准 |
|------|------|
| 9-10 | 像素级精确，对齐、间距、颜色无任何瑕疵 |
| 7-8 | 整体精致，有1-2处微小对齐/间距问题 |
| 5-6 | 基本对齐，但间距不统一，颜色使用不够系统 |
| 3-4 | 明显的对齐错误、间距混乱、颜色过多 |
| 1-2 | 粗糙，看起来像草稿 |

**评审要点**：
- 是否使用了统一的间距系统（如8pt网格）？
- 同类元素的间距是否一致？
- 颜色数量是否受控？（通常不超过3-4种）
- 字体家族是否统一？（通常不超过2种）
- 边缘对齐是否精确？

### 4. 功能性（Functionality）

| 分数 | 标准 |
|------|------|
| 9-10 | 每个设计元素都服务于目标，零冗余 |
| 7-8 | 功能导向明确，有少量可删减的装饰 |
| 5-6 | 基本可用，但有明显的装饰性元素分散注意力 |
| 3-4 | 形式大于功能，用户需要努力寻找信息 |
| 1-2 | 完全被装饰淹没，失去了传达信息的能力 |

**评审要点**：
- 删掉任何一个元素，设计会变差吗？（如果不会，就应该删）
- CTA/关键信息是否在最显眼的位置？
- 是否有「因为好看所以加上去」的元素？
- 信息密度与载体是否匹配？（PPT不宜太密，PDF可以更密）

### 5. 创新性（Originality）

| 分数 | 标准 |
|------|------|
| 9-10 | 令人耳目一新，在该哲学框架内找到了独特表达 |
| 7-8 | 有自己的想法，不是简单的模板套用 |
| 5-6 | 中规中矩，看起来像模板 |
| 3-4 | 大量使用了cliché（如渐变圆球代表AI） |
| 1-2 | 完全是模板或素材拼凑 |

**评审要点**：
- 是否避免了常见cliché？（见下方「常见问题清单」）
- 在遵循设计哲学的同时是否有个人表达？
- 是否有「意想不到但很合理」的设计决策？

## 场景评审侧重

不同输出类型的评审重点不同（概念维不在表内：它对所有场景都是第一道关，不参与侧重取舍）：

| 场景 | 最重要维度 | 次重要 | 可放宽 |
|------|-----------|--------|--------|
| 公众号封面/配图 | 创新性、视觉层级 | 哲学一致性 | 功能性（单图不涉及交互） |
| 信息图 | 功能性、视觉层级 | 细节执行 | 创新性（准确优先） |
| PPT/Keynote | 视觉层级、功能性 | 细节执行 | 创新性（清晰优先） |
| PDF/白皮书 | 细节执行、功能性 | 视觉层级 | 创新性（专业优先） |
| 落地页/官网 | 功能性、视觉层级 | 创新性 | —（全面要求） |
| App UI | 功能性、细节执行 | 视觉层级 | 哲学一致性（可用性优先） |
| 小红书配图 | 创新性、视觉层级 | 哲学一致性 | 细节执行（氛围优先） |

> **产品界面 / 交互原型类评审**（App UI、落地页、Dashboard、后台工具、多步流程）：除上表侧重外，
> 「功能性」维度里**加查一层用户价值与易用性**（下一节）。纯视觉产出（封面 / 信息图 / 演示 / 海报）**不加这一层**——
> 它们没有「用户要完成的行为」，硬套只会产出空泛评价。判断依据见 `references/product-value.md` §1。

## 用户价值与易用性（产品界面类评审追加）

**只对产品界面/交互原型启用。** 不改 5 维度评分体系，作为「功能性」维度的细化检查——因为「有用好懂」本身就是功能性的内核（见 `references/product-value.md` 判断顺序：有用 → 好懂 → 舒服 → 有意义）。

**三条可检验的追问**（可判定、不含糊）：

| 追问 | 不合格的信号 | 该写进 Fix 的内容 |
|------|-------------|------------------|
| **理解成本**：一个没用过它的人，几秒内能否说出「这页是干嘛的」？ | 首屏要读完三行解释才知道在讲什么；主视觉抢了核心信息 | 具体到「把 X 提到首屏第一眼 / 删掉挡住 Y 的 Z」 |
| **操作成本**：完成核心行为要几步？其中几步是系统本可以替用户做的？ | 让用户自己算 / 自己记 / 自己填本来就有的信息；高频入口藏在二级页 | 「把高频入口提到首屏 / 把差额直接算好呈现，不让用户心算」 |
| **容错**：点错 / 填错会怎样？有无解释与回退？ | 无反馈、不可撤销、错误提示只说「操作失败」 | 「错误提示说明具体原因 + 给出可回退动作」 |

**还要查一条结构性判断**：

- **核心用户行为是否被首屏服务？** 首屏先服务「完整导航 / 所有功能露个脸」而不是核心行为 = 结构问题，属 ⚡重要 及以上。
- **骨架测试**：把颜色/阴影/图片都拿掉，只留灰块和文字，核心行为是否仍清楚？不清楚 = 结构在靠装饰撑。

**第四层：情感价值机会（机会判断，不是评分项）**

前三层过了之后，**看一眼**有没有值得投入的情绪价值机会（五个方向见 `references/product-value.md` §0.5）——注意这不是第六个维度、不进总分：

- **只问一句**：这版的「情感价值点」，能说清是**谁、在哪个时刻、因为什么**真的会这样感受吗？
  - 答不出 → 那是设计者想象出来的装饰，**建议去掉**（写进 Fix：「去掉 X，它不服务于任何真实感受」）。
  - 答得出 → 只需确认它**没有挤压**核心行为与理解成本，然后放行。
- **没有情感价值点的版本不算缺陷**，不要为它写 Fix。工具类界面克制本身就是对的做法。
- ⚠️ 反模式：把「加点动效 / 加句有温度的文案 / 加个成就徽章」当**默认改进建议**——那是反 AI slop 的另一面（`references/product-value.md` §0.5 四条边界）。

**输出纪律（避免空泛概念化评价）**：

- ❌ 反例：「交互可以更顺畅些」「整体体验还有提升空间」「信息架构可以更清晰」——用户无法据此行动。
- ✅ 正例（落到 Fix 的三段式：现状 / 为什么是问题 / 改成什么含数值）：
  > **首页信息层级被装饰抢走** — ⚡重要
  > 当前：首屏正中是一个 240px 的环形进度装饰，目标数字被挤到右下角 14px。
  > 问题：核心行为是「扫一眼看还差多少」，但用户第一眼看到的是装饰不是数字，违背理解成本。
  > 修复：把「还差 2,300 步」提到首屏 48px 主位，环形图降为背景层或删掉。
- **每条问题必须指向一个具体界面位置 + 一个具体改法**；指不出具体位置的「问题」，不是问题，是印象——不要写进报告。

## Spec 一致性与范围核验（附加检查 · 无 spec 时 N/A）

**这是一层附加核验，不是第六个评分维度**——不改上方 5 维度评分与总评口径，只在报告里多跑一遍「做的是不是要的东西」的回勾。目的是减少 **AI 自行扩大范围、遗漏需求**。

**核验基线**：设计 spec（Phase 3 的 ≥500 字 spec）／用户明确需求／`direction-approved.md` 记录。三者都没有时，本层记 **N/A** 并写明「未做规格核验」，**不臆造基线**。

**逐条回勾**（把规格条目**抄成检查表**，不靠印象）：

| 核验项 | 要问的 | 不合格信号 |
|--------|--------|-----------|
| **Scope 越界** | 规格没要求、却被做出来的页面 / 功能 / 状态？ | 「演示完整性 / 点击测试 / 看起来更完整」被当成补充的理由（见 `references/product-value.md` 的 Scope 冻结） |
| **Non-goals 突破** | 规格明确说「不做 X」，产物里却有 X？ | 自行把被排除的范围「顺便做上」 |
| **Acceptance Criteria 遗漏** | 每条验收标准都能在设计里找到对应证据？ | 有 AC 找不到对应物，或只落地了一半 |
| **功能要求（FR）未满足** | 明确的 FR 是否真的落地？ | 关键 FR 缺失，或只有占位式敷衍 |

**阻断级判定：`BLOCKING_SPEC_DEVIATION`**

命中下列任一，**在报告顶部**标 `BLOCKING_SPEC_DEVIATION`，并**不得**把该版本作为「已完成」交付：

- 超出 Scope（含「规格只要求入口，却补出了 destination」这类）
- 违反 Non-goals
- 明确的 FR 未满足
- 明确的 AC 未满足
- 与已冻结的约束（`direction-approved.md` / 品牌规范）直接冲突

**处理路径**（按「修复是否需要新的产品决策」分流，**不新增审批环节**）：

1. **不需要新产品决策**（机械可修：删掉越界内容、改回规格要求的文案 / 状态）→ 直接修复 → 重跑相关验证 → 重新核验；通过后正常交付。
2. **需要改动需求 / FR / AC / 范围** → **停止**，把问题连同证据交回用户决定；评审**不自行补规格、不自行改 AC**。

**不阻断交付的**（照旧只报告，别把评审变成无限优化循环）：一般视觉优化、间距、卡片冗余、创新性不足、非 AC 级别的细节问题。

**评审仍然只报告、不改文件**——修复是产出的动作，评审只负责判定与留痕。

## 视觉还原检查（附加检查 · 走 GPT 概念生图通路时）

**仅在存在「已确认的 GPT 概念效果图」时执行**（`references/gpt-visual-workflow.md`）；无效果图时记 **N/A**。这是与上一节并列的**附加核验**——不改 5 维度评分口径、不新增评分维度、不新增审批环节。

> 🔴 **与本文件外的 Gate 2 的分工**：本节检查**由 DesignWise 自己做**（执行方视角的证据核对）；**需要独立第二视角、或要判「是否可进入下一阶段 / 收口」这类阶段门槛时，走 **Gate 2**——默认由**原生自检**读真实渲染截图 + 已确认概念图 + 客观测量并给判断；**用户授权 GPT 评审通道后**才交给 `scripts/zcode_vision.py --confirm-gpt-review`；**仅用户明确点名 Copilot 时**才走 copilot 正式 REVIEW（`references/gpt-visual-workflow.md` §3.7.6）。两者**并行、互不替代**；客观测量能解决的微调不重新送审。

**做法**：把**已确认的效果图**与 **DesignWise 真实渲染截图**并排比对，找**明显**偏差——只抓影响设计意图的那几类，不逐像素抠。

> 🔴 **先答一句**：**HTML 是否真实还原了概念图的视觉，而不是仅还原了结构？** 若概念图里由图片承载的部分（插画 / 人物 / 主视觉 / 背景 / 装饰 / 产品展示图）在实现里是**占位图 / 灰块 / 色块**，或复核者说不清「这是设计如此还是图还没做」——**评审结论不可判定为「视觉通过」**，先按 `gpt-visual-workflow.md` §3.7.1 命中情况 A 补齐验证素材再评。（边界：视觉价值不依赖图片的页面标记 N/A，见该文 §3.6.3）

| 检查项 | 关注什么 | 不合格信号 |
|--------|---------|-----------|
| **布局偏差** | 主要区块的位置 / 比例关系 | 首屏核心行为被挤出视觉首要位置；区块顺序或主次走样 |
| **字体层级差异** | 标题 / 正文 / 标签的大小对比 | 层级被压平，读不出主次 |
| **图片素材错误 / 缺失** | 素材是否错位 / 拉伸 / 用错图；**该有图的位置是否真的有图** | 正式素材与概念图对不上；误用探索态的图；**占位图 / 灰块 / 色块顶替了该有的视觉素材** |
| **配色与视觉气质** | 主色 / 底色 / 情绪基调 | 整体气质跑偏（如概念图的克制被做成高饱和） |
| 🔎 **一眼识别用途**（图标 / 标志类） | 在真实使用尺寸下能否一眼看出是干什么的 | 需要解码才能理解；小尺寸退化成无意义色块 |
| 🔎 **硬约束 / 满底核对** | 要求不透明满底的图是否真满底（**先按目标底色合成再看**，别只看像素值）；色值是否落 token；有无未经要求的光晕/渐变/阴影 | 概念图实为透明底却当满底通过；把透明背景误读成"暗角/光晕" |

> ⚠️ **判据优先级**：**用户能否识别与理解为先，像素占比 / 连通块 / 腐蚀存活率等技术指标只作辅助证据**——指标好看不等于设计好，指标难看也未必该推翻概念成立的方向（见 `references/gpt-visual-workflow.md` §2.4 缺陷分级）。

**判定原则**：**不要求机械像素级一致**——以**用户确认的设计意图**和**真实产品可用性**为准。效果图是意图，实现对意图负责，不对像素负责。

**与功能验证并行**：视觉还原检查**替代不了**功能与交互验证（点击测试、`pageerror` 为 0、内容可动态更新，见 `references/verification.md`）——两者都要做。

**输出**：偏差清单（现状 / 是否影响设计意图 / 改什么）。**只修实质偏差**——不为「更像效果图」牺牲可用性、可访问性或真实交互；评审仍只报告、不改文件。

## Prompt 级创意评审（生图前 · 附加检查 · 无候选 Prompt 时 N/A）

**这是一层附加检查，不是第六个评分维度**——不改上方 5 维度评分与总评口径，只规定「**手上还没有图、只有初始视觉提示词与候选方向方案卡时**，这套评审标准里哪些能用、哪些不能用」。适用时机：走 GPT 视觉概念通路、提示词已生成但**尚未生图**时（流程见 `references/gpt-visual-workflow.md` §2.6）——**它是生图前的门，用通过的提示词去生成真实候选图**。

> 🔴 **与 Gate 1 的边界**：本节是**文字级**评审——标为不可判的项目**一律不出结论**，**也不决定视觉方向**。方向判断走 **Gate 1**：**真实候选图**（每方向 1 张，§2.2）默认由**原生自检**基于真实像素比较并给推荐；**用户授权 GPT 评审通道后**才交给 `scripts/zcode_vision.py --confirm-gpt-review`（**仅用户明确点名 Copilot 时**才走 copilot 正式 REVIEW），见 `references/gpt-visual-workflow.md` §2.6.1。🔴 **Gate 1 的执行时机是「真实候选图生成之后」**——**在真实图产生之前不做 Gate 1**，那时没有像素可比较。**文字级评审不能代替 Gate 1，Gate 1 也不能代替本节的文字可判项。**

> **为什么需要这一层**：`gpt-visual-workflow.md` 的时序是「提示词先评审 → 再生成多方向真实候选图 → Gate 1 → 用户选定方向」（§2.2~§2.8）。评审对象从「画面」变成「提示词 + 方案卡」，**评分标准里有一部分就不再有判据**——不写清边界，就会出现「凭 prompt 判定 48px 清晰度通过」这类把推测当结论的错误。

**🔴 第一原则：文字推测 ≠ 真实视觉测试结果。** 评审对象是 prompt 与方案卡，不是渲染出来的画面。把「按这条 prompt 应该会……」（预期）写成「已经……」（实测），就是越界。

**六个维度在 Prompt 阶段的可判性**：

| 维度 | Prompt 阶段 | 说明 |
|---|---|---|
| **0. 概念 / 立意** | ✅ **可判（且仍是最重要的一关）** | 概念是否从真实产品需求长出来、能否一句话讲清、换个产品名是否还成立——文字层就能判；概念不立，一样按「概念≤5 则总评封顶」的原则**退回重写** |
| **1. 哲学一致性** | ✅ 可判 | 方向之间的气质是否自洽；prompt 里有没有自相矛盾的要求（如「不出现足迹」与「以足迹为主体」并存） |
| **2. 视觉层级** | ⚠️ **只能判意图，不能判效果** | 可判「prompt 是否写明了主次与层级」；**不可判**「实际视觉层级是否成立」——后者要等图 |
| **3. 细节执行** | ⚠️ **只能判要求是否写明** | 可判「色值 / 间距 / 数量 / 安全区是否写进了 prompt 正文」；像素级对齐、抗锯齿、边缘质量**必须等真实图** |
| **4. 功能性** | ✅ 可判（判意图） | 核心行为是否被主体服务、元素是否冗余——在方案层面可判 |
| **5. 创新性** | ⚠️ 部分可判 | 可判「是否明显撞 cliché（如渐变圆球代表 AI）」「两个候选是否同质」；「是否耳目一新」要看到图才算 |

**🛑 不可判清单（在 Prompt 阶段写下这些结论即为越界）**：

- ❌「48px / 目标尺寸下清晰可辨」→ ✅ 只能写「prompt 已要求 `legible at 48×48`——待出图后按 `gpt-visual-workflow.md` §2.4 核对」
- ❌「满底合规 / 透明底问题已解决」→ ✅ 只能写「prompt 已写明不透明满底要求」
- ❌「品牌色准确」→ ✅ 只能写「色值已按 `brand-spec.md` 的 token 写进 prompt」
- ❌ 任何形如「XX 已达标 / 已通过」的量化结论（未见图，无从判起）

**评审追问六条**（完整表格见 `references/gpt-visual-workflow.md` §2.6）：① 是否真正服务需求；② 是否能够产生有区分度的视觉方向；③ 是否存在互相冲突的要求；④ 是否存在会导致视觉歧义的描述；⑤ 哪些要求应留到后续产品化 / 矢量精修；⑥ 提示词自身是否可执行、可实现。

**输出**：沿用下方「评审输出模板」的 **Keep / Fix / Quick Wins** 三段，但有两个差别——

1. **不打 0-10 总分与分项分**：分数是给已成型的视觉作品的；对没有图的 prompt 打分属推测。**判断以证据说明优劣**（证据 = 方案卡字段或 prompt 原文）。
2. **判断必须能指回证据**：指不回具体方案字段 / prompt 原句的判断，是印象不是问题，不写进报告（同下方「输出纪律」）。

**与前后环节的衔接**：

- 本节结论的用途是**决定「这份提示词能不能拿去生图」**（不合格 → 先改提示词，§2.6）——它**不产出方向决策**；真实候选图生成后由 Gate 1 做方向比较与推荐（§2.6.1），再由用户选定方向（§2.7），选定后才写收敛型最终提示词（§2.8）。
- **真实图生成后**再按本节上方的「视觉还原检查」与完整 5 维度评审**复评**——此时上面标 ⚠️/❌ 的项目才有判据（判据优先级仍是「用户能否识别与理解」为先，见 `references/gpt-visual-workflow.md` §2.4）。

## 常见设计问题 Top 10

### 1. AI科技cliché
**问题**：渐变圆球、数字雨、蓝色电路板、机器人脸
**为什么是问题**：用户已经对这些视觉疲劳，无法区分你和其他人
**修复**：用抽象隐喻替代直白符号（如用「对话」的隐喻而非聊天气泡图标）

### 2. 字号层级不足
**问题**：标题和正文差距太小（<2.5倍）
**为什么是问题**：用户无法快速定位关键信息
**修复**：标题至少为正文的3倍（如正文16px → 标题48-64px）

### 3. 颜色过多
**问题**：使用5种以上颜色，没有主次
**为什么是问题**：视觉混乱，品牌感弱
**修复**：限制为1个主色+1个辅色+1个强调色+灰阶

### 4. 间距不统一
**问题**：元素间距随意，没有系统
**为什么是问题**：看起来不专业，视觉节奏混乱
**修复**：建立8pt网格系统（间距只用8/16/24/32/48/64px）

### 5. 留白不足
**问题**：所有空间都被内容填满
**为什么是问题**：信息拥挤导致阅读疲劳，反而降低信息传达效率
**修复**：留白至少占总面积40%（极简风格60%+）

### 6. 字体过多
**问题**：使用3种以上字体
**为什么是问题**：视觉噪音，削弱统一感
**修复**：最多2种字体（1种标题+1种正文），用字重和大小创造变化

### 7. 对齐不一致
**问题**：有的左对齐，有的居中，有的右对齐
**为什么是问题**：破坏视觉秩序感
**修复**：选定一种对齐方式（推荐左对齐），全局统一

### 8. 装饰大于内容
**问题**：背景图案/渐变/阴影抢了主要内容的风头
**为什么是问题**：本末倒置，用户来看信息不是看装饰
**修复**：「如果删掉这个装饰，设计会变差吗？」如果不会，就删

### 9. 赛博霓虹滥用
**问题**：深蓝底(#0D1117) + 霓虹色发光效果
**为什么是问题**：默认审美禁区（本 skill 的品位基线），且已成为最大 cliché 之一——用户可按自己品牌 override
**修复**：选择更有辨识度的配色方案（参考20种风格的色彩系统）

### 10. 信息密度与载体不匹配
**问题**：PPT里放了一整页文字 / 封面图里塞了10个元素
**为什么是问题**：不同载体的最佳信息密度不同
**修复**：
- PPT：每页1个核心观点
- 封面图：1个视觉焦点
- 信息图：分层展示
- PDF：可以更密，但需要清晰的导航
