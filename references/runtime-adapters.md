# 运行时能力适配 · 能力契约与载体映射

> **读这份文档的时机**：不确定当前环境有没有某个能力，或某一步失败、要判断是「没这个能力」还是「用错了方式」时。
> **一句话立场**：**文档规定需要什么能力，用什么工具调由执行方按当前环境映射。** 工具名可以换，能力不能降级。

---

## 1. 能力契约

| 能力 | 用在哪 | ZCode 默认载体 | 缺失时 |
|---|---|---|---|
| **文件读写** | brief、方向记录、原型、交付包、清单 | Read / Write / Edit / Bash | 无文件系统的环境把内容贴进回复并说明保存路径 |
| **本地命令执行** | `scripts/*.py`、构建、渲染、清单校验 | Bash | 不能跑就交付源文件 + 命令说明，**不声称已执行** |
| **真实生图** | 阶段 2 三方向、阶段 5 正式素材 | `python3 scripts/zcode_image.py` | 其他 runtime 用自身图像生成；都没有 → **报告并暂停生图环节**（可交付完整 prompt 让用户外部出图后交回真实文件），**不得用 SVG/色块/程序绘图冒充概念图** |
| **图片处理** | 尺寸/裁切/格式/抠图/预览 | Pillow（`zcode_image.py` 内建 `--fit`；`extract_grid.py` / `contact_sheet.py` / `chroma_key.py`） | 缺 Pillow → 报告；不用「大概能跑」的替代冒充已处理 |
| **素材清单校验** | 阶段 5 起、交付前 | `python3 scripts/asset_manifest.py register\|verify\|list` | 无法运行 → 手工核对 id/文件/sha256/消费者并在交付说明标注「未跑清单校验」 |
| **浏览器渲染与截图** | 阶段 4 原型验证、基准图 | Playwright（`scripts/verify.py`）或本机 headless Chromium | 无浏览器 → 交付 HTML 并说明「未经自动验证」；**不得把未渲染说成已验证** |
| **Copilot CONSULT** | 阶段 2 提示词预审、阶段 3 方向决策、阶段 4 原型设计评审 | `~/.zcode/skills/copilot/scripts/bridge_evidence.py` + `call_gpt.py --mode CONSULT` | 不可用 → 受影响动作 **BLOCKED**（预审不可用则暂停生成；评审不可用则不声称 G4 通过）；不自行替代判断、不用文字描述冒充图像或截图送审 |
| **真机运行与截图** | 阶段 6/7 安装、启动、验收 | 宿主 `app-testing` 授权入口（`~/.zcode/skills/app-testing/runtime/mi6-verify/adb-auto-install.sh`） | 无真机 → 原生与验收标 `PARTIAL`/`BLOCKED`，设计交付照常 |
| **公开信息检索** | 阶段 0 事实验证、品牌资产来源 | 宿主搜索/抓取工具 | 无法核实 → 明确告诉用户「这条事实无法联网核实」，**不凭记忆断言** |
| **视觉自检** | 原型/截图/素材的像素判断 | 主模型直接读真实图片并标注「自检」 | 无视觉输入 → 报告缺证；**不得用文字描述冒充视觉结论** |

**能力列是契约，载体列是当前环境的实例。** 换宿主时只需重填载体；阶段、Gate 与证据要求不变。

---

## 2. 怎么判断「我有没有这个能力」

**试一次，别读文档猜。**

1. 到需要该能力的步骤，按上表载体试一次（如 `zcode_image.py --health`，零成本）；
2. 工具不存在或报错 → 用该行「缺失时」的替代；
3. 替代也没有 → 如实报告这一步未自动化，**不静默假装完成**。

**特例**：阶段 0 的事实验证没有「跳过」选项——不能核实就说明不能核实，不编事实。

## 3. 不能降级的能力

以下能力任何 runtime 都必须达成，只是手段不同：

| 硬约束 | 为什么不能降级 |
|---|---|
| **阶段 2 三张真实概念图** | 没有真实像素就没有可比的方向；文字/文件名/示意图都不算 |
| **阶段 2 生图前提示词预审** | 先出图再补审会把介入点退回事后；预审不可用就暂停生成，不把未预审写成已预审 |
| **阶段 3 Copilot 基于真实图像裁决** | 送选材料必须是图片本身；裁决不可由执行方代做或编造 |
| **阶段 3 三出口与融合逻辑** | 采用 / 融合 / 全部拒绝都是有效结果；不得强迫三选一，也不得把拼图当融合 |
| **阶段 4 真实截图设计评审** | 机械校验只证明没坏；未评审不得声称 G4 通过 |
| **阶段 6/7 三方真实对照** | 旧版、HTML、新版三组真实证据缺一不可；构建/安装/token 替换不能替代落地证明 |
| **品牌/真实资产协议** | 生成图不得冒充真实产品、品牌或官方素材 |
| **真机证据** | 未在真机验证不得写成通过；缺证据就标未验证 |

> 降级可以牺牲**并行度与文档长度**，绝不牺牲真实证据与反 slop 底线。
