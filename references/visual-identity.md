# 产品视觉身份 · 让每个产品有自己的一套语言

> **读这份文档的时机**：阶段 0 写视觉定位；一个产品第一次做对外素材；同一开发者有第二个产品；
> 评审报告「看着像另一个产品」；接手一个已有品牌但说不清它凭什么长这样。
> **一句话立场**：DesignWise 统一**设计质量**，不统一**设计风格**。风格属于产品，不属于工具。
> 本文只展开 `SKILL.md` §0（相邻载体）、§3.1（统一质量不统一风格）、§6.5（跨产品差异化）；
> 论证链方法见 `art-direction.md`，跨产品检查见 `cross-product-differentiation.md`。

---

## 1. 三层职责，各管一段

| 层 | 管什么 | 住所 | 谁改 |
|---|---|---|---|
| **通用设计质量** | 理解、层级、可读性、对比度、原创性、可验证性、可落地性 | 本 skill（`SKILL.md` §3–§5、`references/`） | 维护者 |
| **产品视觉身份** | 这个产品**凭什么**长这样：母题、不变量、反模式 | **使用方产品项目内**（一份 Markdown） | 该产品的设计负责人 |
| **Campaign 视觉方向** | 这一次传播讲什么、怎么变 | 该产品的设计目录，按批次 | 该次任务 |

**职责不混的三条推论**：

1. 通用层不能下发调色板、字体、材质、插画风格、构图或卡片体系——那是产品层的事。
2. 身份层不能被别的产品继承，也不能被本 skill 当成默认值分发给下一个项目。
3. Campaign 层可以大胆变化，但必须能指回身份层的不变量；变不回去就是另一个品牌。

**为什么需要中间这层**：只有通用层和 Campaign 层时，每一个 Campaign 都从零推导艺术指导，
而推导者（人或 agent）带着自己的会话级默认审美——同一个默认值被用在四个产品上，就得到
四套「看起来是同一家公司」的素材。实测案例见 `cross-product-differentiation.md` §7。

## 2. 身份档案：分析维度，不是问卷

下面 14 项是**分析维度**。产品不同，要回答的深度不同；**不要求每个产品填满、也不要求答案
同构**。留空比编一个通用答案好——留空是诚实的「这一维暂不成立」。

| 维度 | 要回答什么 | 不合格答案 |
|---|---|---|
| Product Essence | 用户雇它来完成什么任务 | 「一款优秀的工具」 |
| Brand Personality | 它在什么情绪下被需要：被信任 / 被催促 / 被陪伴 / 被认真对待 | 「年轻、活力、温暖」 |
| **Core Motif** | 反复出现的**结构**或比例决定，来自产品的哪个真实对象/行为/数据形态 | 「用圆环代表进度」 |
| Visual Metaphor | 把产品翻译成什么已有事物（册页 / 野外图版 / 仪表盘 / 路书） | 「科技感」 |
| Composition Grammar | 这一产品的构图语法：重心在哪、留白承担什么、主角占比区间 | 「居中、卡片式」 |
| Color Logic | 每个颜色的**角色**与**面积比**，不只是色值 | 「主色蓝 + 辅色橙」 |
| Typography | 字面密度、字阶比、数字处理、语气是工具还是读物 | 「用 Inter」 |
| Material Language | 表面隐喻来自哪个真实材质场景，光源方向 | 「玻璃拟态显高级」 |
| Image Strategy | 摄影/插画/图形/真机截图各承担什么，比例如何 | 「配一些插画增加温度」 |
| Graphic Language | 图标、符号、装饰的统一规则（线宽、圆角、网格、标记法） | 「线性图标」 |
| Layout Principles | 版式与信息层级的固定关系（标题区占比、边距制度） | 「简洁大气」 |
| **Visual Invariants** | 换一批素材也必须保留的 3–6 项 | 列了 12 项（等于没有不变量） |
| Flexible Elements | 可以逐批次变化的表达 | 「都可以变」 |
| Anti-patterns | 本产品**不应**出现的同质化或误读表达 | 「不要太丑」 |

**最小档（三栏）**：时间或信息不足时，只写 `Core Motif`、`Visual Invariants`、`Anti-patterns`。
这三栏就能挡住「换成任何产品都成立」的默认审美；其余维度随素材批次补。

## 3. 怎么推导：顺序不可颠倒

```
产品事实（谁、什么场景、完成什么、系统替它承担什么）
  → 这个产品**不能**和邻居共享的是什么（差异来源）
  → 母题（从内容结构里抽出的形状/节奏/比例）
  → 不变量（3–6 项，换素材也要保留）
  → 可变项与反模式
```

四条硬规则：

1. **证据来自真实产品**：代码、资源、真机截图、真实用户场景、已有品牌资产。**不得**用行业
   刻板印象代替证据（「运动类就该蓝+橙+速度线」「传统文化就该米黄+宋体+印章」）。
   每个结论后面写出它来自哪个文件、哪个界面、哪个行为。
2. **独立推导，不得先定共同风格再切分**。给多个产品做身份时，**一个产品一份，各自从自己的
   证据出发**；不允许先设计一个「家族风格」再给每个产品换主色——那正是同质化的生产线。
3. **必须做差异确认**：身份定稿前，与该开发者或同品类**已交付**的产品做一次
   `cross-product-differentiation.md` 的六项检查。**相似落在结构层就改结构**，不靠换色通过。
4. **身份是从产品长出来的，不是从风格库挑的**：`design-styles.md` 只能在母题确定之后作为
   实现参考，不能作为母题来源。

**「自有语言已重叠」的补充约束**（本案的教训）：当两个产品本身就有同一材质家族（例如都用
暖纸底、暖红强调），「沿用应用内视觉语言」这条正确规则执行两次必然产出同款素材。此时差异
**必须落在结构**——第一视觉对象、构图比例、图像策略、图形语言、字阶节奏，任选两到三项做实质
不同；**不得只靠色相区分**（暖纸配赤陶 vs 暖纸配朱红，在缩略图上不可分）。

## 4. 住所、来源与优先级

- **住所**：使用方产品项目内，建议 `docs/design/visual-identity.md` 或项目已有的设计目录
  （先查项目规则与既有目录习惯，不要另建平行体系）。**一份产品一份**，不集中到本 skill，
  不建中央产品数据库或全局风格注册表。
- **不覆盖权威品牌资料**：项目已有 brand book / design-system 时，身份档案**引用**它们，
  不复制、不改写；冲突时保留原件，在身份档案里写「差异与待决」，不静默择一。
- **优先级**（高 → 低）：
  1. 当前项目的视觉身份与项目规则；
  2. 当前项目已有品牌资产与设计系统；
  3. 当前项目的历史设计与已交付素材；
  4. 跨项目参考（仅用户明确要求或有明确专业价值时，且必须写明借用了哪个维度）。
- **失效与复审**：以下任一发生时身份档案需要复审——产品定位改变、主流程重构、品牌资产更换、
  与另一产品出现混淆、**连续两个 Campaign 都只能靠同一套构图成立**（说明 Campaign 已变成模板）。
  档案里写 `derived_at`、`evidence` 与 `revisit_when`。

## 5. Campaign 层：允许变化，禁止固化

同一产品可以有多个传播主题（功能介绍、节日活动、版本更新、社交传播）。规则四条：

1. **可追溯到不变量**：每个 Campaign 方向必须能指认它保留了哪几条 `Visual Invariants`。
   指不出来 = 这个 Campaign 属于另一个品牌。
2. **可以变的是表达，不是识别**：构图、镜头、色彩面积、节奏可以逐批不同；母题、图形语言、
   字阶关系属于不变量。
3. **成功不等于模板**：某次素材效果好，**不得**直接变成该产品后续所有素材的固定版式。
   下一次仍从身份 + 本次传播目标重新推导。**判断信号**：如果新批次只有文案和截图换了、
   版式完全照搬上一批，这不是「系列一致」，是「停止设计」。
4. **记录最小集**：每个 Campaign 记 `identity_version`、用了哪几条不变量、变了哪些维度、
   以及「为什么这次这样变」。这四行足以让下一个人判断这是延续还是漂移。

**系列一致 ≠ 每一张同构**。产品内一致性靠不变量与视觉语汇，不靠把同一套版式复制五遍。
五张同构的素材在商店货架上确实「整齐」，但它们只讲了一件事。

## 6. 常见失败

| 失败 | 症状 | 修正 |
|---|---|---|
| 身份 = 一份 token 表 | 只有色值和字号，没有母题与不变量 | 回到 §3 重推母题；token 是实现不是身份 |
| 身份 = 形容词清单 | 「温暖、克制、有质感」 | 改成可检查的关系（面积比、字阶比、线宽、光源方向） |
| 先定家族风格再切分 | 多产品像同一家公司的不同产品线 | 各自独立推导；共同点只能事后统计，不能事前规定 |
| 用色相区分代替结构区分 | 只换主色，版式骨架完全一致 | 改第一视觉对象、构图比例或图像策略中的至少两项 |
| 不变量列太多 | 8 项以上，实际每项都做不到 | 压到 3–6 项，其余降为可变项 |
| Campaign 固化 | 新批次只换文案和截图 | 重新推导构图；把上一批降级为「已用过的一种」 |
| 身份档案放在 skill 里 | 别的项目开始继承它的审美 | 搬回产品项目；本 skill 只留格式与方法 |

## 7. 验收（做没做对）

1. 每个结论都能指到真实证据（文件、界面、行为），没有一条来自行业印象；
2. `Visual Invariants` 是 3–6 项，且换一批素材时**真的**能用来判断取舍；
3. 多个产品时，各自独立推导，且做过一次六项检查、相似项落在结构层已被改掉；
4. 身份档案住在产品项目内，没有被本 skill 当作默认审美分发；
5. 最近一次 Campaign 能指认它保留了哪几条不变量，并且**不是**上一批版式的照搬。
