# 产品价值判断 · 先做对的事，再做好看的事

> **读这份文档的时机**：任务属于**产品界面 / 交互原型 / 与产品决策相关的设计**时。
> 纯视觉创作、动画、幻灯片、信息图、封面等**不强制**套用本文件（判断方法见 §1）。
>
> **一句话立场**：这份文档不改任何流程，只加一层判断——在原有的方向门（数量口径见 `SKILL.md` 阶段 1：**方向数按实质分歧决定，1–3 个，不固定三方向**）、资产协议、评审机制里，
> 多带一句「这对用户是不是真的有用」。**产品价值判断是帮原有设计流程做出更好的选择，不是替代原有设计能力。**

> **效力顺序**：**全局安全与授权硬约束**（上级 `AGENTS.md`）不被本文件或项目规则放宽；项目规则文件（如项目 `AGENTS.md`）定义了产品设计原则时，以项目为**唯一权威**；本文件的四维度与三问在项目未定义时作为**默认方法**；执行口径（含方案数量、设计自由度、**设计方向与交付物数量的区别**）与**完整 5 层效力关系**统一见 `SKILL.md`「项目规则优先」，本文可就近复述但不得给出不同数值。本文件自身**不定义**任何项目的产品原则，也不把自身偏好强加给项目。

## 0. 判断顺序：有用 → 好懂 → 舒服 → 有意义

四个维度是**设计判断原则**，按顺序成立——前一层没成立，后一层补不上：

| 维度 | 一句话要问的 | 判错了会怎样 |
|------|-------------|-------------|
| **有用** | 它解决的是真实用户问题吗？还是我们自己觉得该有？ | 好看但没人需要 = 精致的 slop |
| **好懂** | 用户理解它要花多少力气？复杂性由谁承担？ | 功能在，但用户找不到/看不懂 = 等于没有 |
| **舒服** | 有没有无意义的操作、违背既有习惯的交互？ | 每次都要多一步、多想一下 = 长期摩擦 |
| **有意义** | 功能成立后，值得为它加一点审美 / 情绪 / 身份表达吗？ | 过早加 = 装饰压过功能；永远不加 = 工具感 |

**三条边界（避免把原则变成教条）**：

1. **不要求每次都出四份报告**——四个维度是同时在你脑子里过一遍的判断，不是四个交付物。
2. **不要求所有设计都加情绪价值**——「有意义」是**功能成立之后**的可选项。工具类界面克制本身就是对的做法。
3. **后一层不能补前一层**——不有用但好看是 slop；不好懂但舒服是装饰。判断顺序就是优先级顺序。

> 「有意义」这一层的分寸，和 `SKILL.md` §4 的反 AI slop 红线是同一条线：情绪价值要**从内容/品牌长出来**，
> 不是叠滤镜。品牌本身走安静克制，那克制就是它的「有意义」。

### 0.5 第四层「有意义」：前三层保证它值得用，第四层让它有机会被真正喜欢

**核心命题：意义不是产品单方面赋予的，是用户在真实体验里感受、发现和创造的。**
产品能做的是**创造条件**，不是**指派意义**——加一个奖章不等于让人有成就感，写一句文案不等于让人被理解。
所以第四层的动作分两类：**自主、掌控、成长**是基础体验判断（用户是否真的理解目标、掌握过程、看到进步）；**情绪与审美**才是可选的「找机会」——判定标准是「用户会不会真的这样感受」，而不是「我们有没有做这件事」。

**「有意义」的完整含义不止情绪与审美。** 它首先要求实际价值被用户真正获得，其次是在适用场景下让用户获得**自主感、掌控感、成长感**：

| 体验 | 要问的 | 实质性不合格信号（不是「少了个控件」） |
|---|---|---|
| **自主感** | 用户能否理解自己的目标，并自主选择或调整重要目标、行动方式与节奏？ | 重要目标被系统强加；用户没有选择或退出的余地；把大量配置丢回用户，用「选项多」冒充自主 |
| **掌控感** | 用户能否理解规则、掌握进度、了解结果，并据此调整行动？ | 规则、进度或结果不可理解；用户不知道系统做了什么、结果从哪里来；必须自己管理本该系统承担的复杂流程 |
| **成长感** | 用户能否通过真实成果和清晰、及时的反馈看到自己的进步？ | 进步靠等级、积分、勋章或动画虚构；反馈与真实成果无关；把持续使用当成成长 |

三者是**判断体验是否服务用户的视角**，不是功能清单、配置清单或逐项达标要求；**不要求每个产品、每个页面、每个版本同时提供三者**。自主感不等于选项越多；掌控感不等于让用户自己管理复杂流程；成长感不等于等级、积分、勋章或持续使用。合理默认、清楚的规则、必要的调整与退出能力，以及真实、及时的成果反馈，常常比新增功能更合适。**不要把「没有目标选择器 / 没有进度条 / 没有成长页」当成缺陷**——要看重要目标是否被强加、规则与结果是否难以理解、进步是否被虚构。

**情绪与审美是第四层的一种可选表达，不是它的全部。** 下面五个方向只用于探索「是否值得在某一处增加情绪价值」；它们不构成对「有意义」的完整判定，也不要求每个任务都回答。**情绪专属的真假检验与投入标准只约束这类可选情绪设计，不外推到整个第四层。**

**前三层是基础竞争力，第四层在基础成立之后决定产品能否被真正喜欢、被长期信任。** 它**不是第四道门**，也不是实施排期——必要的知情、控制与退出能力不能被解释为「前三层做完才考虑」；三层没过时，情绪装饰仍然是装饰。

**五个探索方向**（这是探索的罗盘，**不是功能清单**——不必逐项实现，多数任务一个都不做才是对的）：

| 方向 | 要问的 | 常见误区（做了反而扣分） |
|------|--------|------------------------|
| **快乐与惊喜** | 有没有一处**自然、真实**的积极情绪触点？（一次准确到位的反馈、一个意料之外但合理的细节） | 用动效和彩带制造热闹 |
| **情感共鸣** | 用户会感到「被理解」「从这里看到自己」吗？（内容、语气、默认值站在他那一边） | 写煽情文案 |
| **自我表达** | 用户能借它表达自己的审美、个性、价值观吗？（可定制、可留痕、可署名） | 塞一堆无意义的主题皮肤 |
| **成就与纪念** | 努力、成长、经历是否被**值得珍惜地**记录下来？（真实数据的沉淀与回看） | 给每个人发同样的徽章；用等级 / 积分代替真实进步 |
| **陪伴与归属** | 长期使用中，产品是否稳定地「在场」？（连续性、记得他的历史、归属感） | 假装有人格、编造虚假陪伴 |

> 「成就与纪念」只是成长感的**一种可选表达**；成长感首先看真实成果与及时反馈，不靠徽章、等级或连续打卡制造。

**五条边界**（越界就是从「有意义」滑向「情绪操纵 / 功能清单」）：

1. **不机械理解**：奖章、动画、仪式感、分享功能、情感文案，以及游戏化里的积分、等级、排行榜，都是**手段**，不是「有意义」本身。手段没有真实需求支撑就是装饰。
2. **不要求每个页面、每个功能都提供情绪价值**：工具类界面**克制本身就是对的做法**；第四层允许「这一版一个都不加」。
3. **不强行煽情、不制造虚假陪伴、不操纵用户情绪**：情感不能靠文案伪造，不用损失厌恶 / 焦虑 / 愧疚去驱动行为；不用强制任务、虚假稀缺、惩罚性连续机制或过度竞争制造使用压力，不以短期活跃或使用时长牺牲用户的长期价值。
4. **不从设计者视角想象**（见下方真假检验）。
5. **机制服务用户自己的目标**，而不是让用户被系统设定的规则绑架。基于真实约束的必要步骤或真实期限不因此被一概禁止；判断重点是是否必要、透明，以及有没有利用误导或不成比例的压力驱动行为。

**游戏化：可选手段，不是产品目标**

游戏化是用**目标选择、任务挑战、阶段进度、成长反馈、成就**等机制，把抽象目标转化为可理解、可参与、可感知的体验。

- 只在**确实有助于真实用户目标、且收益与成本合理**时采用；可以只取其中一两种，不必整套引入。
- **不采用游戏化可以是更好的设计**：不把积分、勋章、排行榜、签到或任务体系当默认配置，不为游戏化而游戏化。
- 先问两句：**不加这套机制，用户是否仍能完成核心行为？加了以后，用户是否更理解目标、更有掌控、看到真实进步？** 第一问答「能」且第二问答不出时，机制不是必需，删掉。
- 机制服务用户自己的目标；不用强制任务、损失焦虑、虚假稀缺、惩罚性连续机制或过度竞争制造压力，不以短期活跃 / 使用时长换长期价值。

**真假检验（只用于可选情绪设计，一句话过门）**：

> **这份情感价值，是用户在他的真实场景里可能真的感受到的，还是我们（设计者）自行想象、自己感动的？**

说不清「**谁、在哪个时刻、因为什么**而真的这样感受」→ 属想象，**不做**。

**情绪设计值不值得做，看四项**：**用户价值 / 实现成本 / 维护负担 / 商业潜力**。
只在「情感连接的潜力明显」且「成本与维护负担扛得住」时才投入；拿不准就先不做——**装饰性的情绪功能比没有更糟**（拉高维护面，还稀释了真正的差异化）。**这条投入判断只约束情绪表达，不用于否定自主感、掌控感、成长感这类基础体验。**

**证据口径（判断产品是否真的有意义，不只看设计稿）**：

已有真实使用、反馈、留存、推荐或付费证据时优先采用；**没有时明确当前判断仍属假设**，不以视觉观感、点击率或短期转化代替。点击率、短期转化和视觉效果只是**局部指标**，还需考虑长期价值、信任、收益与副作用。不同产品采用与其目标相适应的证据，**不要求每项齐备**，也不要求为设计任务新增埋点、研究报告或上线验证流程。

## 0.6 四层在各环节的落点（只标位置，细则不在这里复制）

四层不是只在开工前问一遍的口号，它要在四个位置各留一个**能被检查**的痕迹。哪一环没痕迹，
就说明当轮的四层判断没有真正生效：

| 环节 | 四层的形态 | 权威位置（细则只在那里） |
|---|---|---|
| **信息架构推导（生图前）** | 一行**信息优先级**（第一眼看什么 / 什么在下一层 / 什么不进首屏）+ 一句「系统替用户承担了什么」 | `references/app-visual-workflow.md` 阶段 0 |
| **`design-brief.md` 的目标与约束** | 每层一条**可检验约束**（不适用就写「本版不适用」）+ 上面那一行信息优先级 | `references/app-visual-workflow.md` 阶段 0 `design-brief.md` 模板 |
| **生图 prompt 正文** | 多方向时逐字共用的**任务块**（用户/核心行为/本页问题/硬约束/禁止项）+ **原则转译块**（每层 1–2 条本页可检查要求）；方向块只写结构差异。只有一个方向时两块与方向块合并 | `references/image-generation.md` §11.1 与 `references/direction-strategy.md` §4 |
| **方向决策（阶段 1，ZCode）** | 逐方向判合格性：核心需求、信息与操作清晰度、严重可用性、是否违反产品规则、是否编造数据、原生可实现；加**复杂度转嫁四问**（信息优先级 / 理解成本 / 系统责任 / 信息完整性与控制权）；再给采用 / 融合 / 全部拒绝三出口 | `references/direction-strategy.md` §6–7 |
| **HTML 原型设计评审（阶段 3，ZCode 自评 + 可选只读复核）** | 四层是否在真实截图里成立：核心信息是否第一落点、装饰是否抢焦、关键信息是否被折叠、空/错态是否还能理解 | `references/critique-guide.md`「原型设计评审」 |
| **真实体验验收** | 概念图好看 ≠ 产品体验成立：录一次真实操作，看用户在哪一步停顿、哪一步放错（§0.5 的真假检验同样适用于验收）；旧版 / HTML / 新版三方对照判断是否真有改善 | `references/app-visual-workflow.md` 阶段 5–6 与 `references/verification.md` |
| **设计评审**（`critique-guide.md`） | 用户价值与易用性三项 + 视觉噪音与干扰一项 | `references/critique-guide.md`「用户价值与易用性」 |

**边界**：这张表不加流程阶段、不加审批门、不新增文档；它只保证四层不只活在本文里。

## 0.7 系统承担复杂度（Complexity Translation）

**一句话**：让系统承担它承担得起的复杂度——计算、整理、分析、判断、换算、找重点——
让用户更容易理解信息、完成任务，同时**保留用户真正需要的信息与控制权**。

它是「有用 → 好懂 → 舒服 → 有意义」的**实现方法**，**不是第五层**，也不是新维度、新评分或新门。

**四层各自要求什么**：

| 层 | 复杂度转译在这里意味着什么 | 判错的信号 |
|---|---|---|
| **有用** | 区分**核心信息 / 辅助信息 / 专业信息**；系统能做的计算、整理、分析不无必要地转给用户 | 为展示功能或"专业感"堆信息；本该算好的差额、该默认的选项、该排好的顺序丢回用户 |
| **好懂** | 把专业指标转成**自然语言结论与解释**；结论直接说出来，不让用户推导 | 只给数字（`14.5 km/h`、`坡度 1.1%`、`62 m 爬升`）却不说「快不快 / 累不累 / 算不算多」 |
| **舒服** | 控制信息密度与视觉干扰；不让多个指标、图表、入口**同时争夺注意力** | 首屏三四块指标与曲线并列；为"丰富"加没有决策价值的数据模块 |
| **有意义** | 视觉表达服务内容理解与产品辨识度；在适用场景下让用户理解目标、掌握过程、看到真实进步；情感与审美放在前三层成立之后 | 先做氛围图再把内容塞进去；用视觉丰富度代替信息组织；用等级 / 徽章 / 动画制造进步假象 |

**四层信息呈现参考模型（参考，不是页面模板）**：

1. **结果层**——用户最需要知道什么？
2. **行动层**——接下来可以做什么？
3. **解释层**——为什么是这个结果？
4. **专业层**——还有哪些详细数据、指标与专业信息值得看？

**顺序与呈现方式由用户任务、产品类型、使用场景与用户专业程度决定**：普通工具优先结果与行动；数据分析工具可以直接呈现专业指标；专业用户需要完整数据时不得为简化而隐藏；复杂功能可以渐进式呈现，但不得让用户为找信息多付成本。**不是每页都要四层俱全，也不是固定排列。**

**五条边界（防止把"减负"做成"减信息"）**：

1. **信息优先级由用户任务与产品价值决定**，不由数据复杂程度、也不由设计者偏好决定。
2. **先定内容与信息层级，再定视觉布局**；版式偏好不得反过来改写信息优先级。
3. 转化出的**结论 / 解释 / 行动建议不得虚构**；依据不足就只给数据，并说明缺什么。
4. **不为简化而隐藏用户必须知道的重要信息**，也不收回用户需要的专业能力与控制入口（原始数据、导出、专业模式、取消与回退）。
5. **专业用户、专业工具、数据分析场景允许合理提高信息密度**。「信息少」不等于「设计好」，「信息多」也不等于「够专业」。

**与 §2 三问的关系**：三问第三问「设计的哪一处替他承担了复杂性」是**入口**；本节给的是**判断维度**（上面五条）与**呈现模型**（四层参考），**不新增第三份清单、不新增检查点**。

**落点**：生图前在 `design-brief.md` 里推导信息架构；prompt 里写清分层；方向选择请求里按复杂度转嫁四问说明；设计评审按 `references/critique-guide.md`「复杂度转嫁（信息架构）」查。**不要求为每个任务产出独立的信息架构文档**——写进 `design-brief.md` 与 prompt 即可，不因此多出生图或审批环节。

## 1. 适用边界：App UI 一律套用，按交互深度决定展开多少

**本 skill 只做 App UI，因此产品价值判断默认适用。** 差别只在展开多少：

| 任务 | 怎么处理 |
|------|---------|
| 有核心行为与流程的 App 界面（首页、列表、详情、表单、多步流程、设置） | 完整走 §2 三问 → §3 核心行为 → §4 价值检验 |
| 以展示为主的 App 页面（关于页、开屏、纯浏览内容页） | 仍写清「谁、看什么、系统替他省了什么」，但可不展开价值检验 |
| 纯视觉物料（海报、封面、信息图） | **不在本 skill 范围**，说明边界并转交相应工具 |

⚠️ **边界模糊时**取轻量做法：在 `design-brief.md` 写一句「这版为用户解决什么」，不展开三问。
**宁少不多**——多出来的分析没有人读，只会拖慢交付。

## 2. 最小三问（产品界面 / 交互任务开工前）

**接在原有 form 推导五问之后，不替代它。** 五问管「这一页怎么长」，三问管「这一页为谁解决什么」。
两者一起，才是完整的开工前思考。

1. **谁在用，在什么场景？** —— 一个**具体人物 + 一个具体时刻**，不是人口统计群体。
   - ✅「早上出门前、站在玄关、手机揣在兜里、一只手拎着包的上班族」
   - ❌「25-40 岁都市白领」（这种描述做不出判断）
2. **他此刻要完成什么？** —— 一个**动词短语级别的核心行为**，不是一串功能。
   - ✅「确认今天有没有走到目标步数，没到就看还差多少」
   - ❌「查看数据 / 管理健康 / 使用各种功能」
3. **设计的哪一处替他承担了复杂性？** —— 系统接住了什么，而不是把决策丢回给用户。
   - ✅「不用他心算——进度直接用『还差 2,300 步』表述，并把差额换算成『再走 25 分钟』」
   - ❌「提供了步数、目标、百分比三个数值，让用户自己比」（把计算丢回用户）

**怎么产出（轻，不新增检查点）**：

- 三行，写进 HTML 头部的 assumptions comments（原有的对齐 pass 就写在那里）——`references/workflow.md` 的 Pass 1 位置。
- **不单独等用户点头**，不新增检查点。阶段 0–2 可连续推进，本三问只是把内容写进 `design-brief.md` 与方向 prompt。
- **用户已经提供了这些信息 → 直接用，不重问**。只有**关键不确定性会实质影响方案**时才问（见 §7）。
- 信息缺失且非关键 → **用明确假设**（写进 assumptions），不阻塞。

## 2.5 范围冻结（不做用户没要求的东西）

**设计任务不得为了「展示完整性 / 点击演示 / 看起来更完整」，自行增加用户未要求的页面、功能或规格。** 这类补充看似「锦上添花」，实际是**范围漂移**：多做的东西没人验收、可能违背真实需求，还挤占了本该投入核心部分的精力。

| 常见漂移 | 为什么是问题 | 克制做法 |
|---------|-------------|---------|
| 规格只要求一个**入口**，却顺手把 **destination 页面**也做出来 | 用户没要那页，做了就是替用户做了未授权的产品决策 | 入口可点 + 用明确 placeholder /「此页不在本次范围」承接；需要就说清楚 |
| 「真实产品通常会有这个」→ 自行补出设置页 / 空状态 / 错误页 | 用「通常」代替了「被要求」 | 只做需求覆盖的状态；不确定就问，或标注为假设 |
| 为了「演示更完整」多铺几屏 / 加几个功能 | 屏幕数量与功能数不是质量指标 | 按核心行为交必要的最小集；多出来的先问 |

**三条边界（不阻止合理补充）**：

1. **有明确需求或已确认假设 → 正常做**，这不是漂移。范围冻结只拦「用户没要求、也没确认」的自行扩张。
2. **不确定是否在范围内 → 问**（把「要不要顺手做」和澄清问题合并成一批），或标成显式假设交付；**不默认做上**。
3. **发现需求本身该扩 → 交回用户决定**，不自行把「不做 X」改成「做了 X」。

> 与工作流的关系：这一步不改流程。项目有 spec 时，它就是 spec 里的 Scope / Non-goals 的落地口径；评审阶段由 `references/critique-guide.md` 的「Spec 一致性与范围核验」回头检查是否越界。

## 3. 核心用户行为优先：把设计从「页面」抬到「行为」

**核心行为** = 用户在应用里**最高频 / 最高价值**的那一件事。界面为它服务，不是为「把功能都摆出来」服务。

四条可操作的做法：

1. **首屏先服务核心行为**，不是先服务「完整导航」或「所有功能露个脸」。
   - 计步器：核心行为是「看一眼今天走到哪了」→ 首屏第一眼就是进度，不是「欢迎 + 五个 tab 入口 + 今日运势」。
2. **高频操作 ≤ 一步，低频操作可以藏**。把所有功能平铺给用户 = 把「找」的成本转嫁给用户。
   - 录音 / 记账这类「随时要用」的入口，应该一步可达；「导出 CSV」这类一年一次的，放进设置。
3. **每个界面能指认它在服务哪个行为**。指认不出 = 可能是装饰页或功能堆砌页。
4. **一句话价值说明**：交付时在 summary 里说清「这个界面替用户省了什么 / 解决了什么」——
   说不出来，说明还是按「页面该有什么」在做，而不是按「用户要做的事」在做。

## 4. 三条可检验的价值判断（把「有用好懂」变成能判定的问题）

评审和自检都用这三条，因为它可判定、不含糊：

| 检验 | 怎么问 | 不合格的信号 |
|------|--------|-------------|
| **理解成本** | 一个没用过它的人，能否在几秒内说出「这页是干嘛的」？ | 首屏需要读完三行解释才知道在讲什么 |
| **操作成本** | 完成核心行为要几步？里面有几步是**系统本来可以替用户做**的？ | 让用户自己算、自己记、自己填本来就有的信息 |
| **容错** | 用户点错了 / 填错了会怎样？有没有解释和回退？ | 无反馈、不能撤销、错误提示只说「操作失败」 |

**用法**：这三条不是打分表，是**找改进点的手电筒**。任一条亮红灯 → 就是本设计该修的地方。

## 5. 关键选择与取舍：设计要能说明「为什么不是另一种做法」

**关键决策 = 选择 + 被放弃的替代 + 理由。** 理由要落在用户 / 场景 / 约束上，不落在「好看」上。

- ✅「目标步数用**大字号单一数字**而不是环形进度图——因为这个场景是『站着扫一眼』，
  环形图好看但需要先读懂刻度，违背 §4 的理解成本。」
- ❌「用了漂亮的渐变进度环，视觉更精致。」（这是描述，不是取舍）

**怎么记录（不新增文档、不写 PRD）**：

- 写进 **HTML 头部的 reasoning comments**（原有做法，`references/design-context.md` 已有此约定）；
- 或交付 summary 里一句话带过。
- **不新增 `design-rationale.md` 之类的文件，不成体系、不写长篇。** 取舍是给判断找依据，不是交付物。

**取舍要说的是「为谁牺牲了什么」**，不是罗列优点。说不清放弃了什么，通常等于没做取舍。

## 6. 融入方向探索

方向数量**按实质分歧决定**（1 / 2 / 3 或先候选后融合，见 `direction-strategy.md` §1）。本文件**不改变流程，只给方向差异补一类产品价值维度**：

- **多方向的 prompt 共用「任务块 + 原则转译块」**：用户 + 核心行为（来自 §2 三问）写进任务块，四层原则转成当前页面的可检查要求写进转译块；两块在各方向**逐字共用**，差异只在方向块，保证每一版都是为同一件事服务，而不是各服务一个臆想需求，也不会为了「看起来不同」删改业务功能。只有一个方向时，两块与方向块合并，但仍要写清结构与边界。
- **方向的差异化维度，可以包含「产品价值」维度**，不只是视觉：
  - 例：做计步器首页，若确实存在三种用户假设，可以是 **A 极简数字型**（最小理解成本）/ **B 仪表盘型**（信息密度高，服务「认真健身」的重度用户）/ **C 激励叙事型**（情绪价值，服务「需要被推着走」的用户）。**没有这种分歧时就给 1 个最优方向，不硬凑。**
  - 这些方向的差异**本身就是产品价值判断的分支**——不同的用户、不同的核心行为侧重。
- **方向选定后**，把该方向对应的「关键取舍」（§5）写成一句 rationale，进 `direction-approved.md` 与 HTML 头部。
- ⚠️ **不因「已经想清楚用户是谁」就省掉真实视觉证据**。想清楚用户 ≠ 已经有资格省掉视觉判断；但也不因"流程要求"制造伪方向。

## 7. 什么时候才问用户（把追问的阈值写死）

原有原则「用户已提供的信息直接使用，不反复追问」在本文件里继续成立，并给出阈值：

| 情形 | 动作 |
|------|------|
| 用户已说明目标用户 / 使用场景 / 要解决什么 | **直接用**，不重问，最多在 assumptions 里复述一遍以求确认 |
| 关键不确定性**会实质影响方案**（例：同一个界面面向「独立开发者」还是「企业采购」，取舍完全相反） | **问**，一次问清，和其他澄清问题合并成一批 |
| 非关键信息缺失（例：具体步数目标默认值、品牌色调微差） | **用明确假设**，写进 assumptions，继续做，不阻塞 |

**判据一句话**：问，是因为**不问就会做错方向**；不是因为「流程上该问」。不满足这个条件就别问。

## 8. 在设计评审里怎么查（接 `references/critique-guide.md`）

原有评审是 5 维度（概念 / 哲学一致性 / 视觉层级 / 细节执行 / 功能性 / 创新性）。
产品界面类评审时，**在「功能性」维度里加一层用户价值检查**，不新开一套评分体系：

- 核心用户行为是否被首屏服务？
- §4 三条检验（理解成本 / 操作成本 / 容错）哪一条亮灯？
- **复杂度转嫁四问（§0.7 的实现检查）**：信息优先级是否被专业数据抢占？用户是否需要自己从数字里读出结论？本该系统做的计算、整理、判断有没有被丢回用户？降复杂度时有没有收走必要信息与控制入口？（细则见 `references/critique-guide.md`「复杂度转嫁（信息架构）」）
- **三体验（§0.5）**：任务涉及目标选择、进度/成果反馈、激励或游戏化时——机制是否服务用户自己的目标？用户能否理解规则、掌握进度、看到真实进步？有没有用强制任务 / 损失焦虑 / 虚假稀缺 / 惩罚性连续 / 过度竞争制造压力？（不相关则不展开；三者不是功能清单）
- **第四层情绪机会（可选，§0.5）**：这版有没有用户真会感受到的情感价值点？有的话是五个方向里的哪一个，还是我们自行想象的装饰？（**不必每版都有**——答不出「谁在哪个时刻因什么而感受」就不是机会，别硬凑）
- 指出的问题是否**具体、可操作**（说得出改哪一处、改成什么），而不是空泛概念（见 §9 反模式）。

完整检查清单与话术见 `references/critique-guide.md` 的「用户价值与易用性」一节。

## 9. 反模式（做了就和「有用好懂」背道而驰）

| 反模式 | 为什么错 | 正确做法 |
|--------|---------|---------|
| **为体现方法论而产出分析** | 产品分析写了半页，界面没变好 = 流程自嗨 | 判断只服务于产出，写完的取舍要能指向具体设计决策 |
| **每屏堆「完整的」信息**（怕漏） | 理解成本直线上升，用户找不到重点 | 按核心行为做减法（`references/content-guidelines.md`「Don't add filler content」） |
| **把系统能做的丢回给用户** | 让用户自己算 / 自己记 / 自己填已知信息 | 系统承担复杂性（§2 第三问） |
| **把专业指标 / 趋势图当首屏主视觉**（信息密度高的参考板容易诱发） | 数据齐全但重点不明：结论层没先给，判断被转嫁给用户（§0.7 好懂 / 舒服） | 结论先给；专业层下沉到详情 / 展开 / 专业模式；指标本身是核心任务时才占第一眼 |
| **把「简化」做成删信息** | 为干净砍掉必要数据、专业入口或控制权——负担没被承担，只是被换成了门槛 | 减掉的是转嫁的负担，不是用户需要的信息与能力（§0.7 边界 4、5） |
| **只给数据不给一句人话** | `62 m 爬升`、`14.5 km/h` 对新手不构成结论 | 数字配一句结论或解释；依据不足就说明缺什么，不编 |
| **空泛概念化评价** | 「交互可以更顺」「体验有待提升」——用户无法据此行动 | 每条问题说清：现状 / 为什么是问题 / 改成什么（含具体数值） |
| **无意义的强制确认 / 拦截** | 多一步就多一次摩擦，还美其名曰「严谨」 | 只在不可逆 / 高风险动作上加确认 |
| **对纯浏览页强套完整分析** | 没有核心行为的页面套三问只会拖慢 | 按 §1 判定；用轻量做法（一句价值说明） |
| **为「完整」自行扩大范围** | 多做用户没要求的页面 / 功能 / 状态 = 范围漂移，做了也没人验收 | 只做需求覆盖的最小集（§2.5 范围冻结）；要扩先问 |
| **把「有意义」当功能清单** | 逐项堆奖章 / 动画 / 仪式感 / 分享 / 情感文案 = 机械理解第四层，装饰压过功能 | 先满足前三层，再按 §0.5 找**用户真实感受得到**的机会；多数任务一个都不做也对 |
| **用损失厌恶 / 焦虑 / 愧疚驱动行为** | 短期数据可能好看，但操纵用户情绪是透支信任，与「情感共鸣」背道而驰 | 情绪只能正向建立；不做「再不学就落后」式催促 |
| **把三体验当功能清单** | 每个产品都硬配目标选择器 / 进度条 / 成长页 / 等级体系 = 机械理解，制造无价值功能 | 按真实用户目标选；没有必要时不做；合理默认、清晰规则与真实反馈常比新增功能更合适 |
| **用游戏化指标代替真实价值** | 积分 / 勋章 / 连续签到 / 排行榜好看，但用户没有真实进步，甚至被系统规则绑架 | 先验证机制服务真实目标；反馈必须对应真实成果；不采用游戏化也可以是更好的设计 |
| **以短期活跃 / 使用时长换长期价值** | 强制任务、损失焦虑、虚假稀缺、惩罚性连续、过度竞争能拉短期数据，却透支信任 | 机制可退出、可调整节奏；看长期价值、信任与副作用，不把局部指标当成功 |

## 10. 收尾自检（融进阶段 6 真机验收）

产品界面交付前，心里过这三条（不用写报告）：

1. **骨架测试**：把视觉样式（颜色、阴影、圆角、图片）拿掉，只留灰块和文字——核心行为是否仍然清楚？
   不清楚 → 结构在靠装饰撑，回去改结构。
2. **一次完成测试**：一个真实用户能否**不借助外部解释**，一次性完成核心行为？中途卡在哪，就是该修的点。
3. **取舍可述测试**：能否一句话说出「为谁、牺牲了什么、为什么值」？说不出 → 说明关键决策是顺手做的，不是判断做的。

**落地自检（原生阶段，与上三条并列）**：

4. **换皮测试**：把新版的颜色/圆角/字体换回旧版——用户还能看出这是重设计吗？看不出 → 结构没落地。
5. **全局测试**：只遮住首页，看次级页与弹层是否还用旧版语言？是 → 落地只做了一半。

## 与原有机制的关系（一句话总述）

本文件**不新增检查点、不新增 Gate 文件、不要求额外的用户确认阶段**。
它只让三个原有位置多带一层「对用户是否有用」的判断：

1. **开工前**：写进 `design-brief.md` 的「产品与用户」三行（用户 / 核心行为 / 系统承担什么）；
2. **方向探索**：多方向时各方向 prompt 共用任务块与原则转译块（逐字相同），差异化只落在方向块、也可以落在产品价值维度上；只有一个方向时也要写清结构与边界；
3. **方向决策**：ZCode 判合格性时一并看「是否服务真实用户任务」，并写进 `direction-approved.md`；
4. **收尾验收**：`references/critique-guide.md` 的功能性维度里多查一层用户价值。
5. **（可选）第四层情绪机会**：前三层成立后，是否值得在**某一处**创造用户真能感受到的情感价值（§0.5）——**可选项，无强制、无评分、无审批**。

**产品的视觉能力（风格库、方向探索、资产协议、反 slop 底线）一条都没有减少——本文件只在它们之上加判断，不在它们之外加流程。**

## 附录：产品价值判断（速查版）

> 2026-10-27 从 SKILL.md 移入，内容逐字保留；入口见 SKILL.md 对应小节。

做**产品界面 / 交互原型**时看这一节（完整方法 → `references/product-value.md`）。判断顺序：**有用 → 好懂 → 舒服 → 有意义**——前一层不成立，后一层补不上。

**先定展开多少**：App 界面一律适用——有核心行为与流程的走三问与价值检验，纯浏览页写一句价值说明即可；海报/封面/信息图不在本 skill 范围。

**开工前三问**（各一行写进 `design-brief.md`；**不新增检查点、不单独等用户点头**）：

1. **谁在用、什么场景**——一个具体人物 + 一个具体时刻（不是人口统计群体）
2. **他此刻要完成什么**——一个动词短语级别的**核心行为**（不是一串功能）
3. **设计哪一处替他承担了复杂性**——系统接住了什么，而不是把决策丢回用户

**三条可检验的价值判断**（自检与评审共用，可判定、不含糊）：**理解成本**（几秒内能否说出这页干嘛）/ **操作成本**（完成核心行为几步、有几步本该系统做）/ **容错**（点错填错会怎样、能否回退）。任一条亮灯 = 该修的点。

**融入方向探索**（数量按实质分歧）：多方向时各方向 prompt **逐字共用任务块**（用户 + 核心行为 + 本页问题 + 硬约束与禁止项）与**原则转译块**（四层各落成 1–2 条本页可检查要求）；差异只在方向块，也可以落在产品价值上（如 极简数字型 / 高密度仪表盘型 / 激励叙事型）。没有真实分歧时给 1 个最优方向，不硬凑三个。方向决策后把关键取舍写成一句 rationale 进 `direction-approved.md` 与 HTML 头部。

**「有意义」的完整含义**：实际价值 + 在适用场景下的**自主感 / 掌控感 / 成长感**（理解目标、掌握过程与规则、通过真实反馈看到进步）。三者是**判断视角，不是功能清单**，不要求每个产品 / 页面 / 版本同时具备；自主感 ≠ 选项多，掌控感 ≠ 用户自己管复杂流程，成长感 ≠ 等级 / 积分 / 勋章。**游戏化是可选手段，不是产品目标**：只在确实有助于真实用户目标且收益成本合理时采用，不强制积分 / 勋章 / 排行榜 / 签到 / 任务体系，不采用也可以是更好的设计；机制服务用户自己的目标，不用强制任务、损失焦虑、虚假稀缺、惩罚性连续或过度竞争制造压力，不以短期活跃 / 使用时长牺牲长期价值。**证据口径**：优先真实使用 / 反馈 / 留存 / 推荐 / 付费；点击率 / 短期转化 / 视觉只是局部指标；没有真实数据时标明是假设。

**第四层情绪机会（可选，不是功能清单）**：前三层成立后，看一眼有没有**用户真会感受到**的情感价值——五个方向（快乐与惊喜 / 情感共鸣 / 自我表达 / 成就与纪念 / 陪伴与归属）是**罗盘不是清单**。**意义由用户在真实体验中感受、发现、创造，产品只创造条件、不指派意义**。只过一句话门：说得出「**谁、在哪个时刻、因为什么**」才做；说不出 = 装饰，去掉。**多数任务一个都不做也是对的**；禁止把奖章 / 动画 / 仪式感 / 情感文案当默认改进（那是反 slop 的另一面），禁止用焦虑、愧疚驱动行为。详见 `references/product-value.md` §0.5。

**四条底线**：① 用户已给的信息直接用，非关键缺失用明确假设；② 只有关键不确定性会实质影响方案才问；③ 不把设计变成写 PRD，不新增 rationale 文件；④ 不为体现方法论而牺牲效率、审美与视觉质量——**产品价值判断是帮原有流程做更好的选择，不是替代原有设计能力**。

**范围冻结**：**不为「展示完整性 / 点击演示 / 看起来更完整」自行增加用户未要求的页面、功能或规格**——规格只要求入口就不补 destination；「真实产品通常会有」不是理由。有需求或已确认假设的正常做，不确定就问或标成假设，**不默认做上**。详见 `references/product-value.md` §2.5。
