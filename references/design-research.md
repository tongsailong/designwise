# 设计参考板与外观账本 · 从真实像素里拆规则，不重复自己

> **读这份文档的时机**：要做「像真实优秀产品」的 L2 视觉探索、手上只有一段文字需求、
> 用户丢来参考链接/截图，或者要判断「这次是不是又做成了和上次一样的壳」。
>
> **一句话立场**：参考板是**输入**，不是交付物；外观账本是**提示**，不是评分。
> 两者都不新增流程阶段、不新增审批门、不新建记忆系统——它们只让 Brief、prompt、
> Gate 1 里本来就有的判断**有真实像素可依**。

---

## §0 什么时候用（不强制，按需）

| 情况 | 用不用 | 说明 |
|---|---|---|
| L2 引入新视觉语言、要做「这个行业里好产品长什么样」 | **用** | 一块板比十句形容词准 |
| 用户给了参考链接 / 竞品截图 / 「照着这个感觉」 | **用** | 先把参考变成规则，再谈方向 |
| 用户明确说「不用参考，就要你自己的方案」 | **不用** | 尊重用户决定 |
| 新的视觉体系定稿前，想知道有没有和本项目历史撞车 | **账本查一次** | 黄灯提示，不阻断 |
| L1 局部改动（改一个按钮、补一屏） | **不用** | 直接改，别加流程 |
| 纯文本 / 数据整理 / 已有明确设计语言只需沿用 | **不用** | 参考板不承担「没思路」的功能，那是风格库的活 |

**一块板可以复用到同项目的多个屏**：板是项目级资产，不必每屏重采。反过来，
**参考板不是「每单必做」的仪式**——没做就直说没做，不要用文字描述假装看过真实像素。

## §1 采集真实参考（脚本通路）

```bash
# 网址 + 本地图混采，输出 board.html / board.jpg / board.json / shots/
python3 scripts/ref_board.py --out ./ref-board \
  --url https://example.com/product --label "标杆产品页" \
  --image ./refs/competitor-login.png

# 只看首屏通常够；要看整页结构加 --full
python3 scripts/ref_board.py --out ./ref-board --url https://example.com --full

# 只用已有截图（没有 Chrome 时的手动通路）
python3 scripts/ref_board.py --out ./ref-board --image ./a.png --image ./b.png
```

- 截图走 `scripts/check-ui.mjs` 的 Chrome/CDP 通路（与 UI 验收同一条链路，**不引入 Playwright 依赖**）。
- **缺 Chrome 或 node 时脚本直接报错退出**，不会出半块板。此时用浏览器手动截图，再用 `--image` 加入。
- `board.json` 里每条来源都记了标题、来源与「采集提示」（参考站点常有触控/对比度不达标项——
  那是对**参考站**的记录，不是要你去修它）。
- **疑似空白会单独告警**：整张图近乎单一颜色多半是 WebGL / 懒加载 / 登录墙没渲染出来。
  这时要换页面或换手动截图，**不能把空白图当「极简风格」的参考**。

**采集边界**：只截公开可访问的页面与用户提供的图；登录态页面走用户已登录的浏览器会话，
但这不构成任何账号操作授权（不改设置、不发消息、不下单）。截图里出现他人隐私信息要裁掉再用。

## §2 从像素里拆规则（这是整件事的重点）

看板本身不产生价值，**拆出来的规则才产生价值**。每张参考图至少回答下表的 3 行：

| 维度 | 在像素里量什么 | 写成什么（能进 Brief / 能检查） |
|---|---|---|
| 网格与间距 | 内容区栏数、外边距、区块间距的重复值 | 「12 栏 / 24px 基础刻度 / 区块间距 96px」 |
| 字号层级 | 标题与正文的实际 px、层级数量、行高 | 「4 级 type scale：48/28/17/15，正文 1.7」 |
| 主色与占比 | 主色/强调色/中性色的面积比与角色 | 「中性 92% + 主色 6% + 强调 2%，强调只出现在主行动」 |
| 图文关系 | 图占屏比例、图与文字的对齐、裁切方式 | 「首屏图占 55%，图左文右，图统一 3:2 横向裁切」 |
| 母题与材质 | 重复出现的形状、描边、纹理、圆角、阴影 | 「2px 描边 + 无阴影 + 8px 圆角作为母题」 |
| 信息密度 | 首屏可见的信息块数量 | 「首屏 1 个主张 + 1 个证据 + 1 个行动」 |

**借方法，不抄标识**：

- ✅ 借：版式节奏、层级策略、留白比例、交互暗示、配色角色分配、母题的构成方式。
- ❌ 不借：品牌标识与商标、独有插画、有版权的字体文件、别人的文案与数据、可识别的角色形象。
- ❌ 不把「更像它」当目标。要问的是**它为什么好读**，再把那个机制用在自己的内容上。

**规则的落点只有两个**（不新增第七个文档）：

1. 写进 `design-state.md` / Visual Brief 的「视觉母题」「参考资产」「可探索边界」
   （见 `references/gpt-visual-workflow.md` §2.0）；
2. 写进 prompt 正文里可执行的一句（例如「12 栏、左边距 64px、强调色仅用于主按钮」）。

拆出来的规则如果**无法被检查、也无法写进 prompt**，那它还是形容词，不算拆完了。

## §3 参考图能做什么、不能做什么

| 资产状态 | 用途 | 边界 |
|---|---|---|
| **参考图**（reference） | 判断输入；可作为 `scripts/zcode_image.py --ref` 的图生图输入 | 只提供结构与气质，其中的数字/文案不得当事实写进 prompt |
| **概念图**（concept） | 候选方向、Gate 1 的比较依据 | 不能当成品 UI，也不能当正式素材交付 |
| **正式素材**（production） | 真实图片、授权素材、程序化生成 | 见 `references/gpt-visual-workflow.md` §3.6.4 与 `references/brand-asset-protocol.md` |

参考截图**永远不是**本项目的产出。把竞品截图放进交付包、或用参考图冒充自己的设计，
是明确的反模式（同 §6）。

**实测边界（2026-10-31 验收）**：`--ref` 确实会被模型读取并改变输出，但**不保证**继承参考的视觉系统。
同一内容型 prompt 下：不带参考出的是模型默认（高饱和绿、填充卡片）；带「首屏大面积空白」的参考截图几乎无迁移；
换成**信息密集区裁切**的参考后，强调色与细线/弱化副行等装置开始迁移。**把 §2 拆出的规则写进 prompt 正文，装置才稳定出现**
（细线分隔、大写宽字距小标签、同字号不同明度、单一小面积强调色）。结论：`--ref` 是增强输入，
**规则进 prompt 是主通路**；采参考时优先截**信息密集区**，别截大片空白的首屏。

## §4 常见失败模式

| 失败 | 症状 | 修正 |
|---|---|---|
| 板很漂亮，规则 0 条 | 汇报里全是「干净、克制、高级」 | 回到 §2 的表，逐行量出数字 |
| 抄了标识 | 参考图里的 logo/插画出现在方案里 | 换成自己的母题，重出概念图 |
| 参考与产品不同类 | 拿 C 端 landing 参考 B 端后台 | 换同类参考，或明确只借排版不借信息密度 |
| 只截首屏看不出结构 | 拆不出区块与层级 | 加 `--full`，或补一张整页截图 |
| 空白当极简 | 看板里有一块纯色 | 看 `board.json` 的空白告警，换页面/换手动截图 |
| 把参考站的问题学过来 | 参考页本身对比度不足、触控过小 | 「采集提示」里列出的事实，不要继承 |

## §5 外观账本（Appearance Ledger）

### 它是什么

本机私有的一份**设计产物指纹记录**，每条包含：时间、项目名、底色、主色板 top5、
display/body 字体、骨架（纵屏段数 × 网格列数 × 卡片数 × 首屏文本节点数）。

默认写 `~/.designwise/ledger.jsonl`（`DESIGNWISE_HOME` 可改目录）。性质与
`personal-asset-index.json` 相同：**本机工具产物，不是知识，不随分发**。

### 怎么用

```bash
# 一个方向定稿后记一笔（同一项目多屏可以都记）
node scripts/check-ui.mjs --url file:///path/home.html --ledger-add 项目名

# 新方向开工前查一次：与最近 10 个交付有没有撞外观家族
node scripts/check-ui.mjs --url file:///path/new.html --ledger-check 10

# 只看账本里记了什么
node scripts/check-ui.mjs --ledger 20
```

判定规则：**底色相同 / 主色板重合 ≥2 色 / 骨架同为 N 段 × M 列**——命中 ≥2 项算同族，
输出黄灯提示。**它只提示，从不改退出码，也不构成「必须改」的指令。**

### 撞族之后怎么办

| 情况 | 做法 |
|---|---|
| 同一产品的多个屏 | **本来就应该同族**，这是优点，不是问题 |
| 有意延续同一视觉语言（跨屏/跨期） | 保留，在交付说明里写清「有意延续」 |
| 跨项目无意识重复（又是一个白底卡片流） | 改骨架（列数/节奏）或改色板角色，再重出概念图 |
| 只是巧合（同底色但版式完全不同） | 不用管——判据要 ≥2 项，单一信号不算 |

**不为差异化而差异化**：仅仅为了让账本变绿而换色、加装饰、改栏数，是拿审美指标替代产品判断。
账本的作用是让你**看见**重复，不是强迫你**表演**不同。

### 它不是记忆系统

账本只存**像素指纹**，不存用户偏好、业务规则、历史决策、失败原因。
- 用户口味与执行偏好 → memory；
- 工程事实、坑与验证结论 → 知识库候选（见 `references/design-handoff.md` §9「交付后经验回流」）；
- 能被脚本测出来的问题 → 改脚本 + 加测试，而不是记在账本里。

### 隐私边界

- **只有显式 `--ledger-add` 才写**：`--ledger-check` / `--ledger` 只读不写。
- 每条只有 5 个字段：时间、项目名（≤80 字符）、页面地址（**去掉查询串、锚点与 `user:pass@` 凭据**，防 token/签名/密码落盘）、页面标题（≤80 字符）、指纹；**不存截图、不存正文**（截图只在显式 `--shot` 时写到你指定的路径）。地址的**路径部分保留**——账本靠它认出是哪次交付；不要把凭据放在路径里（如 `/reset/<token>`）。
- 目录 `0700`、文件 `0600`，写入时也会收紧已有权限位。

## §6 验收（做没做对，看这几条）

1. 板里每张图都是**真实截到/用户提供的像素**，`board.json` 有来源与标题（空白图已被标注）；
2. 至少拆出 **3 条能落到 Brief 或 prompt 的具体规则**（数字、比例、层级，不是形容词）；
3. 方案里**没有**参考对象的标识、独有插画、受版权字体或原文文案；
4. 参考图/概念图/正式素材**三态没有混用**（交付包里没有「参考截图充当成品」）；
5. 用了账本的项目：阅读过黄灯，并对「延续」还是「改」给出了一句理由。
